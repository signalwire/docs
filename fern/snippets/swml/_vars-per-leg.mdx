<Note title="Variables belong to one leg">
SWML variables live on the leg that set them, for as long as that leg lasts. A `confirm` script runs on the leg `connect` dialed, and its two forms see different values. A `confirm` given as a URL is fetched and run there with an empty `vars` and the dialed leg's own `call` object. An inline `confirm` has its variable expressions filled in first, on the leg that issued `connect`. In it, `%{vars.x}` reads that leg's variables and `%{call.from}` is that leg's caller, and a variable that leg hasn't set becomes an empty string. On the leg that issued `connect`, every variable survives, and `connect_result` is set when the document resumes. For how legs relate, see [Call legs](/docs/platform/voice/call-legs).
</Note>
