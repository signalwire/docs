Programmatically define a SWAIG function (tool) that the AI can invoke during a
conversation. This is the imperative alternative to the
[`@tool` decorator](/docs/server-sdks/reference/python/agents/{{base}}#tool).

This method is available on [`SWMLService`](/docs/server-sdks/reference/python/agents/swml-service) and inherited by
[`AgentBase`](/docs/server-sdks/reference/python/agents/agent-base).

<Info>
Tool definitions map to SWML [SWAIG function](/docs/swml/reference/calling/ai/swaig/functions)
entries. See the [SWML SWAIG functions reference](/docs/swml/reference/calling/ai/swaig/functions)
for the full specification.
</Info>

<Tip>
For most cases, the [`@tool` decorator](/docs/server-sdks/reference/python/agents/{{base}}#tool)
is simpler and supports automatic parameter inference from type hints. Use
`define_tool()` when you need dynamic tool registration or when the tool definition
comes from external configuration.
</Tip>

## Parameters

<ParamField path="name" type="str" required={true} toc={true}>
  Function name. Must be unique within the {{noun}}; a duplicate name raises
  `ValueError`. The AI uses this name to invoke the function.
</ParamField>

<ParamField path="description" type="str" required={true} toc={true}>
  Human-readable description of what the function does. The AI reads this to decide
  when to call the function.
</ParamField>

<ParamField path="parameters" type="dict[str, Any]" required={true} toc={true}>
  JSON Schema describing the function's parameters. The AI generates arguments
  conforming to this schema.
</ParamField>

<ParamField path="handler" type="Callable" required={true} toc={true}>
  Python function to call when the AI invokes this tool. Receives `(args: dict, raw_data: dict)`
  and should return a [`FunctionResult`](/docs/server-sdks/reference/python/agents/function-result).
</ParamField>

<ParamField path="secure" type="bool" default="True" toc={true}>
  Whether to require token validation on tool calls. Recommended for production.
  Only `AgentBase` issues and checks tool tokens; a standalone `SWMLService`
  doesn't validate them.
</ParamField>

<ParamField path="fillers" type="dict[str, list[str]] | None" default="None" toc={true}>
  Language-specific filler phrases spoken while the function executes.
  Format: `{"en-US": ["Looking that up...", "One moment..."]}`.
</ParamField>

<ParamField path="webhook_url" type="str | None" default="None" toc={true}>
  External URL to forward the tool call to instead of executing locally.
</ParamField>

<ParamField path="required" type="list[str] | None" default="None" toc={true}>
  List of required parameter names from the JSON Schema.
</ParamField>

<ParamField path="is_typed_handler" type="bool" default="False" toc={true}>
  Set to `True` if the handler uses type-hinted parameters instead of the standard
  `(args, raw_data)` signature.
</ParamField>

<ParamField path="gates" type="Sequence[SemanticGate | dict[str, Any]] | None" default="None" toc={true}>
  1 to 8 [semantic gates](/docs/server-sdks/reference/python/agents/semantic-gate): yes/no questions a decision model must
  pass before the function runs. When one fails, the function doesn't run and the
  AI gets that gate's `on_fail` output. Raises `ValueError` for gates the platform
  would refuse.
</ParamField>

<ParamField path="gate_fillers" type="dict[str, list[str | list[str]]] | None" default="None" toc={true}>
  What the AI says while the gates are checked, shaped like `fillers`. Raises
  `ValueError` without `gates`.
</ParamField>

<ParamField path="**swaig_fields" type="Any" toc={true}>
  Additional SWAIG fields to include in the function definition
  (e.g., `wait_file`, `meta_data`). Function properties without a dedicated
  parameter go here too, such as `fillers_at_gates=False` on a gated function.
</ParamField>
