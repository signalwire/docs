[ref-capabilities]: /docs/server-sdks/reference/typescript/core/capabilities

Return the user variables from a SWML request body. They are nested two levels down, at
`vars.userVariables`, which is easy to get wrong silently: a missing level yields an empty object and
every downstream check quietly reports "not declared".

```typescript {1}
userVariables(bodyParams: unknown): Record<string, unknown>
```

## Parameters

<ParamField path="bodyParams" type="unknown" required={true} toc={true}>
  The SWML request body, as passed to a dynamic-config callback or SWAIG handler.
</ParamField>

## Returns

`Record<string, unknown>` -- The user variables, or `{}` when absent or malformed. Never throws.

## Examples

```typescript {7}
import { userVariables } from '@signalwire/sdk';

const body = {
  vars: { userVariables: { handoff_nonce: 'n-4821', capabilities: { transcript: true } } },
};

const variables = userVariables(body);
console.log(variables['handoff_nonce']);
// n-4821
console.log(userVariables({ vars: {} }));
// {}
console.log(userVariables('not an object'));
// {}
```

Part of the [client capabilities][ref-capabilities] helpers.
