A semantic gate is a yes/no question about the call that must pass before a SWAIG
function runs. Attach gates with `gates=` on [`define_tool()`][define-tool] or the
[`@tool` decorator][tool-decorator], or with [`DataMap.gate()`][datamap-gate]. A
function takes 1 to 8 gates. A decision model checks all of them together right
before the function would run. If any gate fails, the function doesn't run, and the
AI gets the `on_fail` output of the first failing gate in list order.

The decision model reads `conversation` (the recent dialogue), `semantic_state`
(the call's `global_data.semantic_state`, or `{}`), and `proposed_function` (the
function's name, description, and the arguments the AI is calling it with), plus
`visual_input` (the caller's newest video frames) when a gate sets `visual_input`.
Name what each question is about with those names in backticks. They label what the
decision model reads; nothing is substituted. The decision model reads literally
and doesn't do arithmetic or compare dates, so put a computed result in the state
with [`set_semantic_state()`][set-semantic-state] instead of asking for it.

<Info>
Gates map to the SWML [gate object][swml-gates]. For how to write questions and
pick thresholds, see the [semantic gates guide][semantic-gates-guide]. Call-wide
settings are on [`set_semantic_gates()`][set-semantic-gates]. For a ready-made confirm
step, see [`Proposal`][patterns-proposal].
</Info>

<Note>
The SDK checks gates when the tool is defined and raises `ValueError` for anything
the platform would refuse. That includes gates on these function names:
`startup_hook`, `hangup_hook`, `check_for_input`, `end_call`, `hangup`,
`check_time`, `wait_for_user`, `wait_seconds`, `adjust_response_latency`,
`next_step`, `change_context`, `gather_submit`, `get_visual_input`,
`get_ideal_strategy`, `pause_conversation`.
</Note>

## Parameters

<ParamField path="question" type="str" required={true} toc={true}>
  The yes/no question, at most 8 KB (UTF-8). `${...}` variables from the call's
  global data are expanded when the gate is checked; `@{...}` functions are not.
</ParamField>

<ParamField path="threshold" type="float" required={true} toc={true}>
  Above 0 and at most 1. The gate passes when the decision model's probability of
  "yes" is at or above this value.
</ParamField>

<ParamField path="on_fail" type="str | FunctionResult | dict[str, Any]" required={true} toc={true}>
  What the AI gets when this is the first gate that fails, at most 8 KB. A string
  is the response text. A [`FunctionResult`][functionresult] contributes its
  response, actions, and `post_process`. A dict is used as written, in the
  `data_map` output shape (`response`, optional `action`). Say that the function
  didn't run: `ValueError` is raised when there's no response. The platform
  expands the output's `${...}` variables once, from the call's data, as it does
  for a DataMap output, so `${global_data.semantic_state.proposal}` quotes the
  current proposal. Realtime (speech-to-speech) agents don't use `tool_prompt`,
  so put everything in `tool_result` for them.
</ParamField>

<ParamField path="id" type="str | None" default="None" toc={true}>
  Keyword-only. 1 to 64 letters, digits, or underscores, unique within the
  function. Defaults to `gate_1`, `gate_2`, and so on, by position.
</ParamField>

<ParamField path="true_means" type="str | None" default="None" toc={true}>
  Keyword-only. What "yes" means, at most 2 KB. Sent as `criteria.true`.
</ParamField>

<ParamField path="false_means" type="str | None" default="None" toc={true}>
  Keyword-only. What "no" means, at most 2 KB. Sent as `criteria.false`.
</ParamField>

<ParamField path="visual_input" type="bool | int | None" default="None" toc={true}>
  Keyword-only. How many of the caller's newest video frames the decision model
  sees with this gate, as `visual_input`: `True` is 1, `False` or `0` is none, or a
  whole number up to 5. Every gate on a function sees as many frames as the gate
  that asks for the most. The gate's provider must accept images; one that
  doesn't makes the check a configuration error, which blocks the function. If the
  call has no video frame to show, the gate fails without being asked. Omitted by
  default.
</ParamField>

<ParamField path="on_unclear" type="str | FunctionResult | dict[str, Any] | None" default="None" toc={true}>
  Keyword-only. What the AI gets when this is the first gate answered unclear and
  none failed, in the same forms as `on_fail`, and expanded the same way. It should
  ask the caller again. `ValueError` is raised when there's no response. Without it,
  the platform uses its own text, which asks again.
</ParamField>

<ParamField path="unclear" type="bool | None" default="None" toc={true}>
  Keyword-only. `True` lets the decision model answer yes, no, or unclear, where its
  provider supports it; a yes below `threshold` also counts as unclear. An unclear
  answer doesn't run the function: the AI gets `on_unclear`. Two unclear answers in
  a row for the same function and `semantic_state` ask again, and the third counts
  as a fail. A gate with `unclear` wants a lower threshold than a yes/no gate.
  Omitted by default, which asks for yes or no.
</ParamField>

<ParamField path="dialogue" type="str | None" default="None" toc={true}>
  Keyword-only. The dialogue this gate judges, in place of the agent-wide setting
  from [`set_semantic_gates()`][set-semantic-gates]:

  - `"window"` -- the newest entries.
  - `"proposal"` -- the entries since `global_data.semantic_state` last changed.

  A gate about what the caller asked before a proposal started wants `"window"` on an
  agent that judges confirmations by the proposal.
</ParamField>

<ParamField path="history" type="int | None" default="None" toc={true}>
  Keyword-only. How many of the newest dialogue entries this gate judges, a whole
  number from 1 to 100, in place of the agent-wide setting.
</ParamField>

<ParamField path="since" type="str | None" default="None" toc={true}>
  Keyword-only. The name of a mark, 1 to 64 letters, digits, or underscores, that
  your code sets with [`set_semantic_gate_mark()`][set-semantic-gate-mark]. The gate
  judges the dialogue from the agent's first turn at or after the mark, up to
  `history` entries. Until the mark is set, the gate judges its `dialogue` as usual.
</ParamField>

Every gate on one function must set the same `dialogue`, `history`, and `since`, or
leave them all unset, because the gates are asked together about one dialogue.
Otherwise `ValueError` is raised when the tool is defined.

<Note>
`on_unclear`, `unclear`, `dialogue`, `history`, and `since` need a platform release
that supports them. A release that supports gates but not one of these keys refuses
the function.
</Note>

## Examples

### Gate a cancellation on an explicit request

```python {6-16,20-21}
from signalwire import AgentBase, FunctionResult, SemanticGate

agent = AgentBase(name="account-agent", route="/account")
agent.set_prompt_text("You help callers manage their account.")

explicit_request = SemanticGate(
    "Has the caller explicitly asked to cancel their account in `conversation`?",
    threshold=0.95,
    on_fail=FunctionResult(
        tool_result="cancel_account was not run.",
        tool_prompt="Ask the caller to confirm that they want to cancel.",
    ),
    id="explicit_request",
    true_means="The caller says they want to cancel.",
    false_means="The caller asked about cancelling, or said something else.",
)

@agent.tool(
    description="Cancel the caller's account",
    gates=[explicit_request],
    gate_fillers={"en-US": ["One moment."]},
)
def cancel_account(args, raw_data):
    return FunctionResult("The account is cancelled. Tell the caller.")

agent.serve()
```

### Judge only the dialogue since a mark

A gate with `since` judges the dialogue from the point where a tool set the mark. Here
`give_quote` sets the mark, and the gate on `cancel_account` judges at most the 10
entries that follow it.

```python {7,14-16}
from signalwire import AgentBase, FunctionResult, SemanticGate

agent = AgentBase(name="accounts", route="/accounts")
agent.prompt_add_section("Role", "You manage accounts.")

def give_quote(args, raw_data):
    return FunctionResult("Quoted the cancellation fee.").set_semantic_gate_mark("cancel_offer")

def cancel(args, raw_data):
    return FunctionResult("The account is cancelled.")

agent.define_tool("give_quote", "Quote the cancellation fee", {"type": "object", "properties": {}}, give_quote)
agent.define_tool(
    "cancel_account", "Cancel the caller's account", {"type": "object", "properties": {}}, cancel,
    gates=[SemanticGate("Has the caller asked to cancel in `conversation`?", 0.9,
                        "cancel_account was not run.", id="asked",
                        dialogue="window", history=10, since="cancel_offer")],
)
agent.serve()
```

### Let the decision model answer unclear

```python {4-5}
from signalwire import SemanticGate

gate = SemanticGate("Did the caller say yes to the quote in `conversation`?", 0.6,
                    "book_job was not run.", unclear=True,
                    on_unclear="Ask the caller for a plain yes or no.")
print(gate.to_dict())
# {'question': 'Did the caller say yes to the quote in `conversation`?', 'threshold': 0.6,
#  'on_fail': {'response': 'book_job was not run.'},
#  'on_unclear': {'response': 'Ask the caller for a plain yes or no.'}, 'unclear': True}
```
