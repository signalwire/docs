`AIChatClient` sends messages to an AI agent and returns its replies. It is async-first: a `chat()`
call waits on a full model round trip, measured in seconds, and the typical consumers run on an
asyncio event loop where a blocking HTTP call would stall every other conversation.

Use it as an async context manager, or call `close()` yourself.

<Warning>
  This class holds your API token, so it belongs on a server you control. To reach an agent from a
  browser, use [`ChatGateway`][chatgateway] instead.
</Warning>

## **Parameters**

<ParamField path="project" type="str | None" toc={true}>
  Your project ID. Falls back to `SIGNALWIRE_PROJECT_ID`. Raises `ValueError` when neither is set.
</ParamField>

<ParamField path="token" type="str | None" toc={true}>
  An API token with the `chat` scope. Falls back to `SIGNALWIRE_API_TOKEN`.
</ParamField>

<ParamField path="space" type="str | None" toc={true}>
  Your Space name, used to build the service URL. Falls back to `SIGNALWIRE_SPACE`.
</ParamField>

<ParamField path="url" type="str | None" toc={true}>
  The service URL, used verbatim. Overrides `space`. Raises `ValueError` when neither is available.
</ParamField>

<ParamField path="session" type="aiohttp.ClientSession | None" toc={true}>
  An existing session to send requests on. When omitted, the client creates and owns one, and
  `close()` closes it. Pass your own to control connection pooling or timeouts.
</ParamField>

Identity travels in HTTP Basic auth, never in the request body.

## **Methods**

### create_conversation

Creates a conversation, or resets an existing one when `reinit` is set.

<ParamField path="conversation_id" type="str" required={true} toc={true}>
  The conversation id. You choose it, and it is scoped to your project.
</ParamField>

<ParamField path="config_url" type="str" required={true} toc={true}>
  The URL serving your agent's SWML. SignalWire fetches it server-to-server, so it must be reachable
  from the public internet.
</ParamField>

<ParamField path="user_message" type="str | None" toc={true}>
  An opening message from the user, sent as part of creating the conversation.
</ParamField>

<ParamField path="timeout" type="int | None" toc={true}>
  Idle seconds before the conversation ends. Sent as `conversation_timeout`; the service default is
  3600.
</ParamField>

<ParamField path="user_metadata" type="dict[str, Any] | None" toc={true}>
  Arbitrary data about the user, echoed back on this conversation's webhooks. Sent as
  `user_meta_data`.
</ParamField>

<ParamField path="reinit" type="bool" default="False" toc={true}>
  Reset an existing conversation instead of returning it as-is.
</ParamField>

Returns `ConversationInfo` with `id`, `status`, and `initial_message` — the agent's greeting, when
the agent speaks first. Generating that greeting is a turn, and a turn bills.

### chat

Sends a message and returns the agent's reply. One call is one full turn, including any tool calls
the agent makes, so expect seconds rather than milliseconds.

<ParamField path="conversation_id" type="str" required={true} toc={true}>
  The conversation to send on.
</ParamField>

<ParamField path="message" type="str" required={true} toc={true}>
  The message to send.
</ParamField>

<ParamField path="role" type="str" default="user" toc={true}>
  `user` or `system`. A `system` message steers the agent without appearing as something the user
  said.
</ParamField>

<ParamField path="config_url" type="str | None" toc={true}>
  Creates the conversation if it does not exist yet. Saves a call, at the cost of never receiving
  `initial_message`.
</ParamField>

<ParamField path="user_metadata" type="dict[str, Any] | None" toc={true}>
  Applies when this call creates the conversation.
</ParamField>

<ParamField path="timeout" type="int | None" toc={true}>
  Applies when this call creates the conversation.
</ParamField>

<ParamField path="reinit" type="bool" default="False" toc={true}>
  Applies when this call creates the conversation.
</ParamField>

Returns `ChatResponse` with `text`, `conversation_id`, and `user_event` — an event one of your tools
raised for your application to act on, present only when the turn produced one. Its contents are
whatever your tool passed to [`swml_user_event()`][swml-user-event].

### end

Ends the conversation and starts post-processing: the summary, and a request to your
`post_prompt_url` when your SWML sets one.

<ParamField path="conversation_id" type="str" required={true} toc={true}>
  The conversation to end.
</ParamField>

Returns `bool` — `True` when the service reported the conversation ended.

### delete

Removes the conversation and its data. Nothing is post-processed and no webhook fires.

<ParamField path="conversation_id" type="str" required={true} toc={true}>
  The conversation to delete.
</ParamField>

Returns `bool` — `True` when the service reported the conversation deleted.

### log

Reads the conversation back.

<ParamField path="conversation_id" type="str" required={true} toc={true}>
  The conversation to read.
</ParamField>

Returns `ChatLog` with `messages` and `call_timeline`.

<Warning>
  `messages` is the conversation as the service holds it, including `system` and `system-log` entries
  — your own prompt and internal markers. Filter to `user` and `assistant` before displaying it, or
  you publish your prompt to your users. Message timestamps are epoch **microseconds**.
</Warning>

### summarize

Generates a summary of the conversation. Rate limited server-side to one call per minute per
conversation.

<ParamField path="conversation_id" type="str" required={true} toc={true}>
  The conversation to summarize.
</ParamField>

<ParamField path="summary_prompt" type="str | None" toc={true}>
  How to summarize. Overrides the `post_prompt` text in your SWML for this call only.
</ParamField>

<ParamField path="**sampling" type="Any" toc={true}>
  Sampling controls passed through to the service: `temperature` (0.3), `top_p` (0.3),
  `frequency_penalty` (1.0), `presence_penalty` (1.0), and `max_tokens` (512). The list is closed —
  any other key is rejected.
</ParamField>

Returns `str`. Raises `SummaryError` when the service reports that generation failed, so a failed
summary can never reach you as an empty string.

### raw_post

An async context manager yielding the response for one JSON-RPC call with its body unread, for
proxies that must stream the body through rather than buffer it.

<ParamField path="method" type="str" required={true} toc={true}>
  The JSON-RPC method name.
</ParamField>

<ParamField path="params" type="dict[str, Any]" required={true} toc={true}>
  The method's parameters.
</ParamField>

<Warning>
  The caller owns interpreting the result, including that a JSON-RPC error arrives under HTTP 200.
  A relay that awaits the whole body absorbs the service's keepalive padding and recreates the very
  timeout that padding exists to prevent — iterate `resp.content` and forward chunks as they arrive.
  Prefer the typed methods unless you are genuinely relaying bytes.
</Warning>

### close

Closes the session, when the client created it. A client constructed with `session=` leaves that
session alone.

## **Exceptions**

All inherit from `AIChatError`, which carries `code` and `message`.

<ParamField path="AuthenticationError" type="AIChatError" toc={true}>
  Missing or rejected credentials.
</ParamField>

<ParamField path="ConversationNotFoundError" type="AIChatError" toc={true}>
  No conversation with that id exists in your project.
</ParamField>

<ParamField path="RateLimitError" type="AIChatError" toc={true}>
  A project or conversation rate limit was hit.
</ParamField>

<ParamField path="ChatInProgressError" type="AIChatError" toc={true}>
  A turn is already running on this conversation. Wait for it to return — retrying immediately fails
  again.
</ParamField>

<ParamField path="SummaryError" type="AIChatError" toc={true}>
  Summary generation failed. `code` is `None`, because this failure rides the success envelope rather
  than arriving as a JSON-RPC error.
</ParamField>

Error codes without a specific class raise `AIChatError` itself. The client decides success from the
response body rather than the HTTP status, so the HTTP-200-carries-errors behavior of the endpoint is
handled for you.

## **Timeouts**

The default session has no total cap, a 10-second connect timeout, and a 60-second `sock_read`
timeout. A turn's length is the server's business, so liveness is byte-driven rather than
wall-clock: the service pads a slow turn with keepalive whitespace, and 60 seconds of true byte
silence means the request is dead.

## **Example**

```python {10,19,28}
import asyncio

from signalwire.ai_chat import AIChatClient, ChatInProgressError

CONFIG_URL = "https://your-agent.example.com/swml"


async def main():
    async with AIChatClient(space="your-space") as client:
        info = await client.create_conversation(
            "conv-123",
            config_url=CONFIG_URL,
            timeout=1800,
            user_metadata={"customer_tier": "premium"},
        )
        print("agent:", info.initial_message)

        try:
            reply = await client.chat("conv-123", "Where is order A-771?")
        except ChatInProgressError:
            # A turn is already running on this conversation. Wait, don't retry.
            return

        print("agent:", reply.text)
        if reply.user_event:
            handle(reply.user_event)

        summary = await client.summarize("conv-123")
        print("summary:", summary)

        await client.end("conv-123")


asyncio.run(main())
```
