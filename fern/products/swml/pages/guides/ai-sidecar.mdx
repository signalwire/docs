An AI sidecar listens to a live call between a customer and your agent, and after each customer turn
it sends your server one short tip for the agent. It never speaks on the call, so the customer hears
only your agent. Start by coaching a call between two phones you own with [SWML][swml-intro], then
attach and stop a sidecar on a call that's already in progress with the
[REST Calling API][call-commands].

## Pick the right product for AI sidecar

You can run a sidecar with SWML or the REST Calling API, but not every function is available on
each.

| Function | SWML | REST |
|---|---|---|
| Attach a sidecar as your SWML handles a call | <Icon icon="regular circle-check" color="var(--status-success)" /> | <Icon icon="regular circle-xmark" color="var(--status-error)" /> |
| Attach a sidecar to a call that's already in progress | <Icon icon="regular circle-xmark" color="var(--status-error)" /> | <Icon icon="regular circle-check" color="var(--status-success)" /> |
| Give the sidecar tools that run on your server | <Icon icon="regular circle-check" color="var(--status-success)" /> | <Icon icon="regular circle-check" color="var(--status-success)" /> |
| Receive the sidecar's tips at a webhook | <Icon icon="regular circle-check" color="var(--status-success)" /> | <Icon icon="regular circle-check" color="var(--status-success)" /> |
| Stop the sidecar while the call continues | <Icon icon="regular circle-xmark" color="var(--status-error)" /> | <Icon icon="regular circle-check" color="var(--status-success)" /> |

- [SWML](#coach-a-call-via-swml): the call's document attaches the sidecar with
  [`ai_sidecar`][ai-sidecar], then bridges the customer to your agent. Use it when every call to a
  number should be coached from the start.
- [REST](#coach-a-call-in-progress-via-rest): the [REST Calling API][call-commands] attaches a
  sidecar to a live call by its ID, from any process, and stops it while the call carries on. Use it
  to coach a call that's already connected, such as one your agent picked up from a queue.

Both send their tips to the same [server](#run-the-sidecar-server).

## Prepare for AI sidecar

Start with working call setup from [Make and receive calls][make-and-receive-calls]. To test a
sidecar you need two phones: one to call in as the customer, and one to answer as the agent. You also
need a machine that can run a small server, and a tunnel such as [ngrok](https://ngrok.com/) that
gives it a public HTTPS URL.

<Warning title="Trial projects only call and receive calls from verified numbers">
A [trial project][trial-mode] only places calls to and receives calls from numbers you've
purchased or verified. [Prepare for your first call][prepare-calls] shows how to verify the
phones you'll test with.
</Warning>

Replace these values in the samples you run:

| Value | Replace with |
|---|---|
| `<YOUR_SPACE>` | Your Space's subdomain in `<YOUR_SPACE>.signalwire.com` |
| `<YOUR_PROJECT_ID>` | Your Project ID |
| `<YOUR_API_TOKEN>` | Your API token with the **Voice** permission, used only in server code |
| `<YOUR_PUBLIC_HOST>` | The public hostname of your server's tunnel, such as `abc123.ngrok.app` |
| `<YOUR_BASIC_AUTH_PASSWORD>` | A password you choose for your server, letters and digits only, because it appears inside a URL |
| `<YOUR_CALLER_ID>` | Your SignalWire phone number, or a [verified caller ID][caller-id], in E.164 format |
| `<YOUR_AGENT_NUMBER>` | The phone the agent answers, in E.164 format |
| `<YOUR_CALL_ID>` | The ID of a live call, which your server prints when a sidecar starts |

## How the AI sidecar works

A sidecar runs alongside the call without taking part in it:

1. **The sidecar attaches to the call.** It hears both sides, and the call carries on as normal.
   A call runs one sidecar at a time.
2. **The customer finishes a turn.** The sidecar sends the conversation so far to an AI model,
   together with your prompt. The model writes one tip for the agent, or calls the built-in
   `sidecar_skip` tool to stay quiet when no tip is needed.
3. **SignalWire posts each step to your server.** Tips, skips, and the sidecar's other steps each
   arrive as a callback at the URL you set.
4. **The sidecar stops.** It stops when the call ends or when you stop it, and sends a last callback
   with a record of the session.

## Run the sidecar server

Both approaches use one server. It prints the sidecar's callbacks as they arrive at `/events`, and,
for the SWML approach, serves the call's SWML document at its root URL. Both routes require the
username `signalwire` and your password, and the document passes the same credentials in the URL it
gives the sidecar.

The [Server SDKs][server-sdks] build the document with the SWML builder and serve it through
`SWMLService`:

<CodeBlocks>
<CodeBlock title="Python — SWML builder">
```python
# Install: python -m pip install signalwire-sdk==3.4.1
# Save as sidecar.py and run: python sidecar.py
from signalwire import SWMLBuilder, SWMLService

PASSWORD = "<YOUR_BASIC_AUTH_PASSWORD>"

service = SWMLService(name="sidecar", basic_auth=("signalwire", PASSWORD))
swml = SWMLBuilder(service)
swml.ai_sidecar(
    prompt="You coach a support agent. After each customer turn, give the agent "
    "one short tip, or call sidecar_skip if no tip is needed.",
    lang="en-US",
    url=f"https://signalwire:{PASSWORD}@<YOUR_PUBLIC_HOST>/events",
)
# "from" is a Python keyword, so it's passed in a dictionary.
swml.connect(to="<YOUR_AGENT_NUMBER>", **{"from": "<YOUR_CALLER_ID>"})


# The sidecar posts its callbacks to /events.
def on_event(body, headers):
    event = body.get("sidecar_event", {})  # transcription events have none
    if event.get("type") == "start":
        print(f"Sidecar started on call {event['channel_data']['call_id']}")
    elif event.get("type") == "insight":
        print(f"Tip: {event['raw']}")
    elif event.get("type") == "final":
        print(f"Sidecar finished: {event['stop_reason']}")


service.register_routing_callback(on_event, path="/events")
service.serve(host="0.0.0.0", port=8080)
```
</CodeBlock>
<CodeBlock title="TypeScript — SWML builder">
```typescript
// Install: npm install @signalwire/sdk@2.0.5
// Save as sidecar.mts and run: npx tsx sidecar.mts
import { SWMLService } from "@signalwire/sdk";

const PASSWORD = "<YOUR_BASIC_AUTH_PASSWORD>";

interface SidecarEvent {
  type: string;
  channel_data: { call_id: string };
  raw?: string;
  stop_reason?: string;
}

const service = new SWMLService({ name: "sidecar", basicAuth: ["signalwire", PASSWORD] });
const swml = service.getBuilder();
// This SDK version's builder has no ai_sidecar method, so the verb is added by name.
swml.addVerb("ai_sidecar", {
  prompt:
    "You coach a support agent. After each customer turn, give the agent " +
    "one short tip, or call sidecar_skip if no tip is needed.",
  lang: "en-US",
  url: `https://signalwire:${PASSWORD}@<YOUR_PUBLIC_HOST>/events`,
});
swml.connect({ to: "<YOUR_AGENT_NUMBER>", from: "<YOUR_CALLER_ID>" });

// The sidecar posts its callbacks to /events. Return null to acknowledge each
// one: any other value tells the SDK to redirect the request.
service.registerRoutingCallback((body) => {
  const event = body.sidecar_event as SidecarEvent | undefined; // transcription events have none
  if (event?.type === "start") {
    console.log(`Sidecar started on call ${event.channel_data.call_id}`);
  } else if (event?.type === "insight") {
    console.log(`Tip: ${event.raw}`);
  } else if (event?.type === "final") {
    console.log(`Sidecar finished: ${event.stop_reason}`);
  }
  return null;
}, "/events");

await service.run({ port: 8080 });
```
</CodeBlock>
</CodeBlocks>

Start a tunnel to port `8080`, such as `ngrok http 8080`, and check that the server is reachable
through it:

```bash
curl -u "signalwire:<YOUR_BASIC_AUTH_PASSWORD>" "https://<YOUR_PUBLIC_HOST>/"
```

The response is the SWML document. A `401` means the password doesn't match the one in your server.

Each callback carries its event under a `sidecar_event` key, with a `type` that says what happened.
The same URL also receives transcription events that have no `sidecar_event` key, so the server
skips those. The server prints these types:

| `type` | Sent when | Field the server prints |
|---|---|---|
| `start` | The sidecar attaches to the call | `channel_data.call_id`, the call's ID |
| `insight` | The sidecar has a tip for the agent | `raw`, the tip |
| `final` | The sidecar stops | `stop_reason`, why it stopped |

The [callback catalog][callback-types] lists every type, including `skip`, which arrives with the
model's `reason` each time it stays quiet.

## Coach a call via SWML

[`ai_sidecar`][ai-sidecar] attaches the sidecar and the document moves straight on, here to a
[`connect`][swml-connect] that bridges the customer to the agent.

### Attach a sidecar via SWML

The server serves this document. Customers who call your number are coached from the moment the call
is answered:

<CodeBlocks>
<CodeBlock title="YAML">
```yaml
version: 1.0.0
sections:
  main:
    - ai_sidecar:
        prompt: >-
          You coach a support agent. After each customer turn, give the agent
          one short tip, or call sidecar_skip if no tip is needed.
        lang: en-US
        url: 'https://signalwire:<YOUR_BASIC_AUTH_PASSWORD>@<YOUR_PUBLIC_HOST>/events'
    - connect:
        to: '<YOUR_AGENT_NUMBER>'
        from: '<YOUR_CALLER_ID>'
```
</CodeBlock>
<CodeBlock title="JSON">
```json
{
  "version": "1.0.0",
  "sections": {
    "main": [
      {
        "ai_sidecar": {
          "prompt": "You coach a support agent. After each customer turn, give the agent one short tip, or call sidecar_skip if no tip is needed.",
          "lang": "en-US",
          "url": "https://signalwire:<YOUR_BASIC_AUTH_PASSWORD>@<YOUR_PUBLIC_HOST>/events"
        }
      },
      { "connect": { "to": "<YOUR_AGENT_NUMBER>", "from": "<YOUR_CALLER_ID>" } }
    ]
  }
}
```
</CodeBlock>
</CodeBlocks>

`ai_sidecar` answers the call if nothing has answered it yet, and `lang` is its only required
setting. Place it before `connect` so the sidecar hears the whole conversation. The prompt describes
the coaching; tell the model to call `sidecar_skip` when no tip is needed, or it tends to offer one
on every turn. To let the sidecar look things up on your server before it gives a tip, add tools
with the method's `SWAIG` setting, as the [AI sidecar SWAIG reference][ai-sidecar-swaig] shows.

To have SignalWire fetch the document, create a SWML Script with **Handle Calls Using** set to
**External URL** and `https://signalwire:<YOUR_BASIC_AUTH_PASSWORD>@<YOUR_PUBLIC_HOST>/` as its
**Primary Script URL**, then assign it to your phone number, as
[Answer a call via SWML][answer-swml] shows.

Call your number from the customer phone, and answer on the agent phone. As the customer, say "Hi,
I was charged twice for my last order" and pause. The server prints the call's ID and the sidecar's
tip, in wording that changes from call to call:

```text
Sidecar started on call 3a1f6b2e-8c4d-4e7a-9b1f-5d2c7e8a9f10
Tip: Apologize for the double charge and ask for the order number to look it up.
```

Stay on the call for the next section, or hang up and the server prints
`Sidecar finished: transcribe_close`.

If the call connects but the server prints nothing, the sidecar couldn't start or couldn't reach
your `/events` URL. A sidecar that fails to start doesn't stop the document, so the call still
connects. Check that the document sets `lang`, that the tunnel points at port `8080`, and that the
password in the URL matches your server's.

## Coach a call in progress via REST

The [REST Calling API][call-commands] controls a sidecar by the call's ID. The Server SDKs' REST
client doesn't include the sidecar commands in this version, so send them to Call commands directly.

### Stop a sidecar via REST

With the call from [Attach a sidecar via SWML](#attach-a-sidecar-via-swml) still connected, send
`calling.ai_sidecar.stop` with the ID the server printed:

<EndpointRequestSnippet endpoint="POST /api/calling/calls" example="calling.ai_sidecar.stop" />

The server prints `Sidecar finished: api_stop`, and the two phones stay connected. If the request
returns an error, check that the call is still live and that the ID matches the one the server
printed.

### Attach a sidecar via REST

Send `calling.ai_sidecar` to attach a sidecar to a call that's already connected. `params` takes the
same settings as the SWML method: copy `prompt`, `lang`, and `url` from the document in
[Attach a sidecar via SWML](#attach-a-sidecar-via-swml), so the new sidecar reports to your server.

<EndpointRequestSnippet endpoint="POST /api/calling/calls" example="calling.ai_sidecar" />

To try it, send the command for the call you stopped the sidecar on. The server prints
`Sidecar started` again, and tips resume after the customer's next turn. A call runs one sidecar at
a time, so the request fails while another sidecar is still attached.
