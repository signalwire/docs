An AI sidecar listens to a live call between a customer and your agent, and after each customer
turn it sends your server one line of advice for the agent. It never speaks on the call, so the
customer hears only your agent. Start by coaching a call between two phones you own with SWML, then
attach and stop a sidecar on a call that's already in progress with REST.

## Pick the right product for AI sidecar

You can run a sidecar with SWML or the REST Calling API, but not every function is available on
each.

| Function | SWML | REST |
|---|---|---|
| Attach a sidecar as your SWML handles a call | <Icon icon="regular circle-check" color="var(--status-success)" /> | <Icon icon="regular circle-xmark" color="var(--status-error)" /> |
| Attach a sidecar to a call that's already in progress | <Icon icon="regular circle-xmark" color="var(--status-error)" /> | <Icon icon="regular circle-check" color="var(--status-success)" /> |
| Give the sidecar tools that run on your server | <Icon icon="regular circle-check" color="var(--status-success)" /> | <Icon icon="regular circle-check" color="var(--status-success)" /> |
| Receive the sidecar's advice at a webhook | <Icon icon="regular circle-check" color="var(--status-success)" /> | <Icon icon="regular circle-check" color="var(--status-success)" /> |
| Stop the sidecar while the call continues | <Icon icon="regular circle-xmark" color="var(--status-error)" /> | <Icon icon="regular circle-check" color="var(--status-success)" /> |

- [SWML][swml-intro] is the document that describes how a call should flow. The
  [`ai_sidecar`][ai-sidecar] method attaches the sidecar as part of that flow.
- The [REST Calling API][call-commands] sends commands to a live call by its ID, from any process.
  It takes the same sidecar settings as the SWML method.

## How the sidecar works

The sidecar hears both sides of the call. Each time the customer finishes speaking, it sends the
conversation so far to an AI model, together with your prompt and your tools. The model then writes
one line of advice for the agent, calls one of your tools first to look something up, or calls the
built-in `sidecar_skip` tool to stay quiet. SignalWire posts each of these steps to your server as a
callback.

`ai_sidecar` starts the sidecar and the document moves straight on, usually to a
[`connect`][connect] that bridges the customer to your agent. The sidecar runs until the call ends
or you stop it.

## Prepare for AI sidecar

Start with working call setup from [Make and receive calls][make-and-receive-calls]. Have these
ready:

- Your Project ID and an API token with the **Voice** permission, from the Dashboard's
  [API credentials][api-credentials] page, if you'll use REST.
- A phone number in your Space.
- Two phones you can answer: one plays the customer and one plays the agent.
- A machine that can run a small server, and a tunnel such as [ngrok](https://ngrok.com/) that
  gives it a public HTTPS URL.

<Warning title="Trial projects only call and receive calls from verified numbers">
A [trial project][trial-mode] only places calls to and receives calls from numbers you've
purchased or verified. Verify both phones before you start, as
[Prepare for your first call][prepare-calls] shows.
</Warning>

Replace these values in the samples:

| Value | Replace with |
|---|---|
| `<YOUR_PUBLIC_HOST>` | The public hostname of your server's tunnel, such as `abc123.ngrok.app` |
| `<YOUR_BASIC_AUTH_PASSWORD>` | A password you choose for your server, letters and digits only, because it appears inside URLs |
| `<YOUR_CALLER_ID>` | Your SignalWire phone number, or a [verified caller ID][caller-id], in E.164 format |
| `<YOUR_DESTINATION>` | The phone that plays the agent, in E.164 format |

## Coach your first call

This walkthrough coaches a dispatcher at Bayview Taxi, a fictional cab company. When the customer
reads out a booking code, the sidecar looks the booking up on your server and tells the dispatcher
what it found.

<Steps>

<Step title="Run the coaching server" id="run-the-coaching-server">

This server serves the call's SWML document at its root URL, answers the sidecar's tool calls at
`/swaig`, and prints the sidecar's advice from the callbacks it receives at `/events`. Every route
requires the username `signalwire` and your password, and the document passes the same credentials
inside the URLs it gives the sidecar.

<CodeBlocks>
<CodeBlock title="Python — SWML builder">
```python
# Install: python -m pip install signalwire-sdk==3.4.1
# Save as dispatch_coach.py and run: python dispatch_coach.py
from signalwire import FunctionResult, SWMLBuilder, SWMLService

PASSWORD = "<YOUR_BASIC_AUTH_PASSWORD>"
BASE_URL = f"https://signalwire:{PASSWORD}@<YOUR_PUBLIC_HOST>"

# Stands in for Bayview Taxi's booking system.
BOOKINGS = {"BT1042": "Driver Sam, silver Prius, 6 minutes from 200 Harbor Avenue."}

PROMPT = (
    "You coach a Bayview Taxi dispatcher during a live call with a customer. "
    "Speak to the dispatcher in one short sentence. When the customer gives a "
    "booking code, call lookup_booking and pass on what it returns. If the "
    "dispatcher needs no help, call sidecar_skip instead of giving advice."
)

LOOKUP_DESCRIPTION = "Look up a ride booking by its confirmation code."
LOOKUP_PARAMETERS = {
    "type": "object",
    "properties": {
        "confirmation": {"type": "string", "description": "The code, such as BT1042."},
    },
    "required": ["confirmation"],
}

service = SWMLService(name="dispatch-coach", basic_auth=("signalwire", PASSWORD))
swml = SWMLBuilder(service)
swml.answer()
swml.ai_sidecar(
    prompt=PROMPT,
    lang="en-US",
    url=f"{BASE_URL}/events",
    SWAIG={
        "defaults": {"web_hook_url": f"{BASE_URL}/swaig"},
        "functions": [
            {
                "function": "lookup_booking",
                "description": LOOKUP_DESCRIPTION,
                "parameters": LOOKUP_PARAMETERS,
            },
        ],
    },
)
# "from" is a Python keyword, so it's passed in a dictionary.
swml.connect(to="<YOUR_DESTINATION>", **{"from": "<YOUR_CALLER_ID>"})


# The sidecar calls this tool on your server's /swaig route.
def lookup_booking(args, raw_data):
    code = args["confirmation"].replace(" ", "").upper()
    return FunctionResult(BOOKINGS.get(code, f"No booking matches {code}."))


service.define_tool(
    name="lookup_booking",
    description=LOOKUP_DESCRIPTION,
    parameters=LOOKUP_PARAMETERS,
    handler=lookup_booking,
)


# The sidecar posts its callbacks to /events.
def on_event(body, headers):
    event = body.get("sidecar_event")
    if event is None:
        return None  # a transcription event, which shares the URL
    if event["type"] == "insight":
        print(f"Advice: {event['raw']}")
    elif event["type"] == "tool_call" and event["name"] != "sidecar_skip":
        print(f"Tool call: {event['name']} {event.get('arguments', '')}")
    elif event["type"] == "final":
        print(f"Sidecar finished: {event['stop_reason']}")
    return None


service.register_routing_callback(on_event, path="/events")

service.serve(host="0.0.0.0", port=8080)
```
</CodeBlock>
<CodeBlock title="TypeScript — SWML builder">
```typescript
// Install: npm install @signalwire/sdk@2.0.5
// Save as dispatch-coach.mts and run: npx tsx dispatch-coach.mts
import { FunctionResult, SWMLService } from "@signalwire/sdk";

const PASSWORD = "<YOUR_BASIC_AUTH_PASSWORD>";
const BASE_URL = `https://signalwire:${PASSWORD}@<YOUR_PUBLIC_HOST>`;

// Stands in for Bayview Taxi's booking system.
const BOOKINGS = new Map([["BT1042", "Driver Sam, silver Prius, 6 minutes from 200 Harbor Avenue."]]);

const PROMPT =
  "You coach a Bayview Taxi dispatcher during a live call with a customer. " +
  "Speak to the dispatcher in one short sentence. When the customer gives a " +
  "booking code, call lookup_booking and pass on what it returns. If the " +
  "dispatcher needs no help, call sidecar_skip instead of giving advice.";

const LOOKUP_DESCRIPTION = "Look up a ride booking by its confirmation code.";
const LOOKUP_PARAMETERS = {
  type: "object",
  properties: {
    confirmation: { type: "string", description: "The code, such as BT1042." },
  },
  required: ["confirmation"],
};

interface SidecarEvent {
  type: string;
  raw?: string;
  name?: string;
  arguments?: string;
  stop_reason?: string;
}

const service = new SWMLService({
  name: "dispatch-coach",
  basicAuth: ["signalwire", PASSWORD],
});
const swml = service.getBuilder();
swml.answer();
// This SDK version's builder has no ai_sidecar method, so the verb is added by name.
swml.addVerb("ai_sidecar", {
  prompt: PROMPT,
  lang: "en-US",
  url: `${BASE_URL}/events`,
  SWAIG: {
    defaults: { web_hook_url: `${BASE_URL}/swaig` },
    functions: [
      {
        function: "lookup_booking",
        description: LOOKUP_DESCRIPTION,
        parameters: LOOKUP_PARAMETERS,
      },
    ],
  },
});
swml.connect({ to: "<YOUR_DESTINATION>", from: "<YOUR_CALLER_ID>" });

// The sidecar calls this tool on your server's /swaig route. Return a plain
// object, which the SDK sends back as the tool's reply.
service.defineTool({
  name: "lookup_booking",
  description: LOOKUP_DESCRIPTION,
  parameters: LOOKUP_PARAMETERS,
  handler: (args) => {
    const code = String(args.confirmation).replace(/\s/g, "").toUpperCase();
    return new FunctionResult(BOOKINGS.get(code) ?? `No booking matches ${code}.`).toDict();
  },
});

// The sidecar posts its callbacks to /events. Return null to acknowledge each
// one: any other value tells the SDK to redirect the request.
service.registerRoutingCallback((body) => {
  const event = body.sidecar_event as SidecarEvent | undefined;
  if (event === undefined) {
    return null; // a transcription event, which shares the URL
  }
  if (event.type === "insight") {
    console.log(`Advice: ${event.raw}`);
  } else if (event.type === "tool_call" && event.name !== "sidecar_skip") {
    console.log(`Tool call: ${event.name} ${event.arguments ?? ""}`);
  } else if (event.type === "final") {
    console.log(`Sidecar finished: ${event.stop_reason}`);
  }
  return null;
}, "/events");

await service.run({ port: 8080 });
```
</CodeBlock>
</CodeBlocks>

The [Server SDKs][server-sdks] build the document with the SWML builder and serve it through
`SWMLService`. Start a tunnel to port `8080`, such as `ngrok http 8080`, and check that the document
is reachable through it:

```bash
curl -u "signalwire:<YOUR_BASIC_AUTH_PASSWORD>" "https://<YOUR_PUBLIC_HOST>/"
```

The response is the SWML document. A `401` means the password doesn't match the one in your server.

4. Select **Create**.

<Step title="Call your number and talk" id="call-your-number-and-talk">

From the phone that plays the customer, call your SignalWire number, and answer on the phone that
plays the dispatcher. As the customer, say "Hi, my booking code is BT1042, where's my driver?" and
pause. The server prints the tool call and the sidecar's advice, in wording that changes from call
to call:

```text
Tool call: lookup_booking {"confirmation":"BT1042"}
Advice: Driver Sam is 6 minutes away in a silver Prius, pickup at 200 Harbor Avenue.
```

When you hang up, the server prints `Sidecar finished: transcribe_close`.

If the call connects but the server prints nothing, the sidecar couldn't start or couldn't reach
your `/events` URL. A sidecar that fails to start doesn't stop the document, so the call still
connects. Check that the document sets `lang`, that the tunnel points at port `8080`, and that the
password in the URLs matches your server's.

</Step>

</Steps>

The server serves this document, shown here in YAML:

```yaml
version: 1.0.0
sections:
  main:
    - answer: {}
    - ai_sidecar:
        prompt: >-
          You coach a Bayview Taxi dispatcher during a live call with a customer.
          Speak to the dispatcher in one short sentence. When the customer gives a
          booking code, call lookup_booking and pass on what it returns. If the
          dispatcher needs no help, call sidecar_skip instead of giving advice.
        lang: en-US
        url: 'https://signalwire:<YOUR_BASIC_AUTH_PASSWORD>@<YOUR_PUBLIC_HOST>/events'
        SWAIG:
          defaults:
            web_hook_url: 'https://signalwire:<YOUR_BASIC_AUTH_PASSWORD>@<YOUR_PUBLIC_HOST>/swaig'
          functions:
            - function: lookup_booking
              description: Look up a ride booking by its confirmation code.
              parameters:
                type: object
                properties:
                  confirmation:
                    type: string
                    description: The code, such as BT1042.
                required:
                  - confirmation
    - connect:
        to: '<YOUR_DESTINATION>'
        from: '<YOUR_CALLER_ID>'
```

`lang` is the only required setting. Place `ai_sidecar` before `connect` so the sidecar hears the
whole conversation.

## Read the sidecar's callbacks

Each callback is a `POST` to your `url`, with the event under a `sidecar_event` key and a `type`
that says what happened. The same URL also receives transcription events that have no
`sidecar_event` key, so check for it before you read `type`. The types a basic app needs:

| `type` | When it arrives | Field to read |
|---|---|---|
| `insight` | The sidecar has advice for the agent | `raw`, the advice |
| `skip` | The model chose to stay quiet this turn | `reason` |
| `tool_call` | The model called a tool | `name`, `arguments` |
| `final` | The sidecar stopped, usually because the call ended | `stop_reason`, plus a record of the session |

The sidecar runs one evaluation as soon as it attaches, so a `skip` or `insight` can arrive before
anyone speaks. The [callback catalog][callback-types] lists every type and field.

## Attach and stop a sidecar on a call in progress

To coach a call that's already connected, such as one your agent picked up from a queue, attach the
sidecar by the call's ID. You can also stop a sidecar while the call carries on.

### Attach and stop a sidecar via REST

The Server SDKs' REST client doesn't include the sidecar commands in this version, so send them to
[Call commands][call-commands] directly. To attach a sidecar, send `calling.ai_sidecar` with the
same settings as the SWML method in `params`. Point `url` and the SWAIG `web_hook_url` at your
server, as in the first call:

<EndpointRequestSnippet endpoint="POST /api/calling/calls" example="calling.ai_sidecar" />

To stop it, send `calling.ai_sidecar.stop`. The sidecar sends its `final` callback with
`stop_reason: api_stop`, and the call stays connected:

<EndpointRequestSnippet endpoint="POST /api/calling/calls" example="calling.ai_sidecar.stop" />

A call runs one sidecar at a time, so attaching a second one returns an error.

## Write a prompt that coaches well

Your prompt describes the coaching. The sidecar already knows that it's a silent coach and that its
advice goes only to the agent. Tell the model to call `sidecar_skip` when no advice is needed;
without that line, it tends to offer advice on every turn. Ask for one short sentence, because the
agent reads it mid-conversation, and tie each tool to a trigger, such as "When the customer gives a
booking code, call lookup_booking".
