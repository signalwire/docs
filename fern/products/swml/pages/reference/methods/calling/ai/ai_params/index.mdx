Parameters for AI that can be passed in `ai.params` at the top level of the [`ai` method](/docs/swml/reference/calling/ai).
These parameters control the fundamental behavior and capabilities of the AI agent, including model selection, conversation management, and advanced features like thinking and vision.
Timing parameters take a number or a duration string such as `"1.5s"` or `"20m"`; see [Duration values](#duration-values).

## **Properties**

<ParamField path="ai.params" type="object" toc={true}>
  An object that accepts the following properties.
</ParamField>

<Indent>

<ParamField path="params.ai_model" type="string" default="gpt-4o-mini" toc={true}>
  The AI model for the conversation, used when [`prompt.model`](/docs/swml/reference/calling/ai/prompt#promptmodel) isn't set. Name a model on the [supported model list](/docs/swml/reference/calling/ai/prompt#supported-models), optionally as `model@provider`. Any other name runs as `gpt-4o-mini`, and the call gets a non-fatal `calling.error` whose `error` is `model_substituted`.
</ParamField>

<ParamField path="params.ai_name" type="string" default="computer" toc={true}>
  Sets the name the AI agent responds to for wake/activation purposes. When using `enable_pause`, `start_paused`, or `speak_when_spoken_to`, the user must say this name to get the agent's attention. The name matching is case-insensitive.
</ParamField>


<ParamField path="params.app_name" type="string" default="swml app" toc={true}>
  A custom identifier for the AI application instance. This name is included in webhook payloads (`post_prompt_url`, SWAIG function calls), allowing backend systems to identify which AI configuration made the request.
</ParamField>


<ParamField path="params.conscience" type="string" toc={true}>
  Sets the prompt which binds the agent to its purpose. This prompt helps reinforce the AI’s behavior after SWAIG function calls.

  It is used to reinforce the AI agent’s behavior and guardrails throughout the conversation.
</ParamField>


<ParamField path="params.convo" type="object[]" toc={true}>
  Injects pre-existing conversation history into the AI session at startup.
  This allows you to seed the AI agent with context from a previous conversation or provide example interactions.
</ParamField>

<Indent>

<ParamField path="convo[].role" type="string" required={true} toc={true}>
  The role of the message sender. Valid values:
  - `user` - A message from the human caller/user interacting with the AI agent.
  - `assistant` - A message from the AI agent itself.
  - `system` - A system message providing instructions or context to guide the AI's behavior.
</ParamField>

<ParamField path="convo[].content" type="string" required={true} toc={true}>
  The text content of the message. With [`redact_prompt`](#paramsredact_prompt) set, `user` entries are exported as `----` in the call logs.
</ParamField>

<ParamField path="convo[].lang" type="string" default="en" toc={true}>
  The language code for the message. Uses standard ISO language codes such as `en`, `en-US`, `es`, `fr`, `de`, etc.
</ParamField>

</Indent>


<ParamField path="params.conversation_id" type="string" toc={true}>
  Used by `check_for_input` and `save_conversation` to identify an individual conversation.
</ParamField>


<ParamField path="params.conversation_sliding_window" type="integer" toc={true}>
  Sets the size of the sliding window for conversation history. This limits how much conversation history is sent to the AI model. The current step's instructions and the current gather question are never dropped from the window.
</ParamField>


<ParamField path="params.direction" type="string" default="the natural direction of the call" toc={true}>
  Forces the direction of the call to the assistant. Valid values are `inbound` and `outbound`.
</ParamField>


<ParamField path="params.double_turns" type="boolean" default="false" toc={true}>
  Before each reply, a smaller planning model reviews the conversation and the available functions, then gives the agent a short directive on how to respond. This can improve function use and coherence. The reply waits for the plan, which adds latency to every turn. The planning model is [`utility_model`](#paramsutility_model) if set, otherwise `ai_model`. Billed separately from the agent's per-minute rate. To cover the wait, set [`double_turn_fillers`](/docs/swml/reference/calling/ai/languages#languagesdouble_turn_fillers) on each entry in `languages`.
</ParamField>


<ParamField path="params.enable_end_call" type="boolean" default="true" toc={true}>
  Whether the model can end the call itself. Set it to `false` and the call ends only when the caller hangs up, through a SWAIG action such as `hangup`, `transfer`, or `stop`, or through [`hard_stop_time`](#paramshard_stop_time) or [`inactivity_timeout`](#paramsinactivity_timeout). With it off:

  - The model isn't taught how to hang up.
  - An end-call marker the model writes anyway is removed from the spoken words, and no hangup is queued.
  - A hangup tool call is refused, and the model is told to continue the conversation.

  `false`, `0`, and the strings `"false"`, `"no"`, `"off"`, `"f"`, `"disabled"`, `"inactive"`, `"disallow"`, and `"0"` turn it off. Any other value, `1` included, leaves it on.
</ParamField>


<ParamField path="params.enable_inner_dialog" type="boolean" default="false" toc={true}>
  Enables the inner dialog feature, which runs a separate AI process in the background that analyzes the conversation and provides real-time insights to the main AI agent. This gives the agent a form of "internal thought process" that can help it make better decisions.
</ParamField>


<ParamField path="params.enable_pause" type="boolean" default="false" toc={true}>
  Enables the pause/resume functionality for the AI agent. When enabled, a `pause_conversation` function is automatically added that the AI can call when the user says things like "hold on", "wait", or "pause". While paused, the agent stops responding until the user speaks the agent's name (set via `ai_name`) to resume. Cannot be used together with `speak_when_spoken_to`.
</ParamField>


<ParamField path="params.enable_thinking" type="boolean" default="false" toc={true}>
  Enables thinking output for the AI Agent. When set to `true`, the AI Agent will be able to utilize thinking capabilities. This may introduce a little bit of latency as the AI will use an additional turn in the conversation to think about the query.
</ParamField>

<ParamField path="params.enable_turn_detection" type="string | boolean" default="both" toc={true}>
  How the agent recognizes that the caller has finished speaking. Two signals feed the decision: sentence-ending punctuation in the partial transcript, and an acoustic read of the caller's intonation.

  - `both` — Use both signals. Punctuation ends the turn, while the acoustic signal can hold the turn open for another word when the caller sounds mid-sentence, or end it when the caller trails off without punctuation. `true` is an alias.
  - `punct_only` — Punctuation alone ends the turn.
  - `acoustic_only` — The acoustic signal alone ends the turn.
  - `off` — Neither signal is used, and the agent waits out [`end_of_speech_timeout`](#paramsend_of_speech_timeout) silence instead. `false` is an alias.

  The `both` and `punct_only` modes are tuned by [`turn_detection_min_length`](#paramsturn_detection_min_length) and [`turn_detection_timeout`](#paramsturn_detection_timeout); `acoustic_only` uses neither. The parameter is also accepted under the name `turn_detection`.
</ParamField>


<ParamField path="params.enable_vision" type="boolean" default="false" toc={true}>
  Enables visual input processing for the AI Agent. When set to `true`, the AI Agent will be able to utilize visual processing capabilities. The image used for visual processing will be gathered from the user's camera if video is available on the call, leveraging the [`get_visual_input`][get-visual-input] function.
</ParamField>

<ParamField path="params.languages_enabled" type="boolean" toc={true}>
  Has no effect and can be omitted.

  A [`languages`][ai-languages] array takes effect because it is set, not because of this flag, so setting this to `false` does not disable one. The separate [`multilingual`][ai-multilingual] object is likewise switched on by being set.
</ParamField>


<ParamField path="params.local_tz" type="string" default="US/Central" toc={true}>
  The local timezone setting for the AI. Value should use [IANA TZ ID][iana-tz]
</ParamField>


<ParamField path="params.redact_prompt" type="string" toc={true}>
  A plain-language description of sensitive content to redact from everything the platform records or transmits about the call — logs, events, webhook payloads, the call timeline, and the post-conversation `call_log` and `raw_call_log`. For example: `"credit card numbers, social security numbers, and full names"`. Redacted content is replaced with `----`. Set this parameter to enable redaction; omit it to leave redaction off.

  The caller still hears the content in full, and **the AI still receives the real text** — redaction protects what is recorded and transmitted, not what the AI processes. Redaction can occasionally miss content, so treat it as a safeguard for your logs and integrations rather than an absolute guarantee.

  With redaction on, these are also masked:

  - A caller turn with no redacted form is exported as `----`, never as said. That covers a turn whose redaction failed, a turn that doesn't wake the agent (under `speak_when_spoken_to`, or while paused), and `user` entries given in [`convo`](#paramsconvo).
  - Recognizer details on caller entries, such as an entity's value and the raw and formatted text of each formatting span, show `----`.
  - Words from other speakers under [`asr_speaker_affinity`](#paramsasr_speaker_affinity) are exported as `Speaker N said: ----`.
  - `calling.ai.partial_result` is sent without its text, and `calling.ai.speech_detect` isn't sent.
</ParamField>


<ParamField path="params.rescue_model" type="string" default="gpt-6-luna" toc={true}>
  The model that answers a turn the agent's model couldn't. A model name, or `model@provider`. When the agent's model gives unusable replies, the turn goes once to the rescue model instead of the platform retrying the same model until the call fails. The rescue model gets the same conversation, tools, and step, and its reply is spoken and kept like any other. The next turn goes back to the agent's model.

  A turn goes to the rescue model when any of these happens:

  - Two replies in one request are discarded as degenerate output, such as padding or a word repeated without end.
  - A reply writes a tool call as text instead of making it, twice in one request.
  - The provider refuses the model's calls to a tool the request didn't offer more than twice in one caller turn.
  - The provider refuses the request even when it is sent again without tools.

  There is no rescue when the agent's model is the rescue model, when the name isn't a model the platform has configured, or for HTTP errors and timeouts. To turn rescue off, set this to the agent's own model.
</ParamField>


<ParamField path="params.save_conversation" type="boolean" default="false" toc={true}>
  Send a summary of the conversation after the call ends. This requires [`post_prompt_url`][post-prompt-url] to be set and the `conversation_id` defined. This eliminates the need for a `post_prompt` in the `ai` parameters.

  The platform stores nothing: the summary goes to `post_prompt_url` as `conversation_summary`, and keeping it is up to you. The next call that starts with the same `conversation_id` asks `post_prompt_url` for the summary you stored, and resumes the conversation with the `conversation_summary` in your reply. See [responding to post prompt requests](/docs/swml/reference/calling/ai#responding-to-post-prompt-requests) for the reply format.
</ParamField>


<ParamField path="params.summary_mode" type="string" toc={true}>
  Summary generation mode. Only `"string"` and `"original"` are accepted.
</ParamField>


<ParamField path="params.thinking_model" type="string" default="Value of ai_model parameter" toc={true}>
  The AI model that the AI Agent will use when utilizing thinking capabilities.
</ParamField>

<ParamField path="params.utility_model" type="string" default="Value of ai_model parameter" toc={true}>
  The AI model used for lightweight background tasks such as redaction (`redact_prompt`) and transcription cleanup (`auto_correct`). Choose a small, fast model, such as `gpt-4o-mini`, `gpt-4.1-mini`, or `gpt-4.1-nano` — these tasks run while the caller is waiting for a response. A value that is not a recognized model is ignored, and the agent's main model is used instead.
</ParamField>

<ParamField path="params.transfer_summary" type="boolean" default="false" toc={true}>
  Pass a summary of a conversation from one AI agent to another. For example, transfer a call summary between support agents in two departments.
</ParamField>


<ParamField path="params.vision_model" type="string" default="Value of ai_model parameter" toc={true}>
  The AI model that the AI Agent will use when utilizing vision capabilities.
</ParamField>

<ParamField path="params.visual_input" type="boolean | integer" default="1" toc={true}>
  How many of the caller's newest video frames [`get_visual_input`][get-visual-input] sends, oldest first, taken at most one per second: `true` is `1`, or a whole number from `1` to `5`. Any other value keeps the default. This doesn't affect the `visual_input` of a [semantic gate][semantic-gates] or a [SWAIG function][functions-fillers], which each set their own count.
</ParamField>

<ParamField path="params.wait_for_user" type="boolean" default="false" toc={true}>
  When false, AI agent will initialize dialogue after call is setup. When true, agent will wait for the user to speak first.
</ParamField>


### Speech Recognition

Configure how the AI agent processes and understands spoken input, including speaker identification, voice activity detection, and transcription settings.

<ParamField path="params.asr_diarize" type="boolean" default="false" toc={true}>
  If true, enables speaker diarization in ASR (Automatic Speech Recognition). This will break up the transcript into chunks, with each chunk containing a unique identity (e.g speaker1, speaker2, etc.) and the text they spoke.
</ParamField>


<ParamField path="params.background_sounds" type="boolean" default="false" toc={true}>
  Tells the model about sounds in the background of the caller's turn. The groups are dog barking, phone ringing, alarm going off, and siren. On a turn with words, the groups heard are added after the caller's words, each once and in the order heard, so the model reads `Yes. (background: dog barking, phone ringing)`. The note becomes part of the caller's turn text.

  Sounds heard with no words after them don't start a turn or move any of the caller's timers. Each adds a system-log entry with `action: "background_sound"` and the group to the call log.
</ParamField>


<ParamField path="params.asr_smart_format" type="boolean" default="false" toc={true}>
  Enables smart formatting in ASR (Automatic Speech Recognition). This improves the formatting of numbers, dates, times, and other entities in the transcript.
</ParamField>


<ParamField path="params.auto_correct" type="boolean" default="false" toc={true}>
  Cleans up the transcription of the caller's speech before the AI reads it — converting spoken numbers to digits, formatting addresses and phone numbers, and fixing obvious mishearings — without changing the meaning. Cannot be used together with `enable_text_normalization`, which is on by default: set `enable_text_normalization` to `"off"` to use `auto_correct`; otherwise `auto_correct` has no effect. When used alongside `redact_prompt`, cleanup and redaction happen together in a single step, which keeps responses fast.
</ParamField>


<ParamField path="params.enable_text_normalization" type="string" default="both" toc={true}>
  Converts numbers, currency, dates, and similar values between their written and spoken forms so the AI understands callers more accurately and speaks its responses more naturally. For example, a caller who says "twenty three dollars" is understood as `$23`, and the AI's `$23` is spoken back as "twenty three dollars". Applies in both directions by default. See [accepted values](#text-normalization-values) below.
</ParamField>


<ParamField path="params.asr_speaker_affinity" type="boolean" default="false" toc={true}>
  If true, will force the AI Agent to only respond to the speaker who responds to the AI Agent first. Any other speaker will be ignored. With [`redact_prompt`](#paramsredact_prompt) set, other speakers' words are exported as `Speaker N said: ----`.
</ParamField>


<ParamField path="params.end_of_speech_timeout" type="integer | string" default="700" toc={true}>
  Amount of silence, in ms, at the end of an utterance to detect end of speech. Allowed values from `0`-`10,000`. Also accepts a [duration](#duration-values).
</ParamField>


<ParamField path="params.energy_level" type="number" default="52" toc={true}>
  Amount of energy necessary for bot to hear you (in dB). Allowed values from `0.0`-`100.0`.
</ParamField>


<ParamField path="params.first_word_timeout" type="integer | string" default="1000" toc={true}>
  Amount of time, in ms, to wait for the first word after speech is detected. Allowed values from `0`-`10,000`. Also accepts a [duration](#duration-values).
</ParamField>


<ParamField path="params.llm_diarize_aware" type="boolean" default="false" toc={true}>
  If true, the AI Agent will be involved with the diarization process. Users can state who they are at the start of the conversation and the AI Agent will be able to correctly identify them when they are speaking later in the conversation.
</ParamField>


<ParamField path="params.noisy_line_ms" type="integer | string" default="4000" toc={true}>
  How much loud audio with no recognized words, in ms, the caller's line can carry before the agent says it seems very noisy on the caller's side, that it might have trouble hearing them, and asks whether they can make it a little quieter. The agent says this in the language of the conversation. Allowed values from `0` to `600,000`, where `0` turns the notice off. Also accepts a [duration](#duration-values).

  Two things trigger it:

  - Sustained noise. Loud audio with no words is counted from a baseline taken 1 second after the agent stops speaking. Once the count passes this value, while the agent isn't speaking and no request is out, the model's next turn gives the notice, unless the caller has said something since. It's given again only after the caller has said words and the count has passed the threshold again.
  - A noisy turn. A turn that ended with no words over noise filling most of it, or with noise after its last words, also gets the notice. With no words, the notice is its own turn; with words, the reply that answers them includes it. It's given again only after a turn that wasn't noisy.

  Loud audio is never taken for speech: no turn is ended, held, or re-asked because of it. Each notice adds a system-log entry with `action: "noisy_line"` to the call log. The notice needs a speech recognizer that reports line loudness.
</ParamField>


<ParamField path="params.openai_asr_engine" type="string" default="deepgram:nova-3" toc={true}>
  The ASR (Automatic Speech Recognition) engine to use. Common values include `deepgram:nova-2`, `deepgram:nova-3`, and other supported ASR engines.
</ParamField>


<ParamField path="params.text_normalization_show_heard" type="boolean" default="false" toc={true}>
  When the Deepgram recognizer formats the transcript, the model also reads the words as spoken after each span the formatting changed. For example, the model reads `The order number is w7123456 (heard: w seven one two three four five six).` The annotation becomes part of the caller's turn text.

  Nothing is added for a span the formatter restored to its spoken words, or for one that can't be placed in the text. Recognizers that don't format the transcript themselves get no annotation.
</ParamField>


#### Values for `enable_text_normalization` [#text-normalization-values]

| Value | Applies to | What it does |
|---|---|---|
| `heard` | Caller input | Converts what the caller says into written form before the AI reads it — for example, "twenty three dollars" becomes `$23`. |
| `spoken` | AI responses | Converts the AI's written response into spoken form before it is read aloud — for example, `$23` becomes "twenty three dollars". |
| `both` | Caller input and AI responses | Applies both conversions. This is the default. |
| `false` / `off` / `none` | — | Turns text normalization off. |
| `true` / `on` | Caller input and AI responses | Same as `both`. |

Text normalization is applied per language and adapts automatically if the conversation switches languages.

<Note>
If text normalization isn't available for the language being spoken, that direction is simply skipped and the conversation continues uninterrupted. Some languages support only one direction; in that case, `both` applies whichever is available.
</Note>


### Speech Synthesis

Customize the AI agent's voice output, including volume control, voice characteristics, emotional range, and video avatars for visual interactions.

<ParamField path="params.ai_volume" type="integer" default="0" toc={true}>
  Adjust the volume of the AI. Allowed values from `-50`-`50`.
</ParamField>


<ParamField path="params.cartesia_max_buffer_delay_ms" type="integer | string" default="500" toc={true}>
  The maximum buffer delay, in ms, for Cartesia voices. Allowed values from `0` to `5,000`. Also accepts a duration with units, such as `"0.5s"`, read as a [strict millisecond value](#duration-values). A value out of range, or one that's neither a number nor a duration, keeps the default.
</ParamField>


<ParamField path="params.heygen_key" type="string" toc={true}>
  Your HeyGen API key, used by HeyGen Voice (`heygen.<voice>` voices). Without it, the platform's key is used. The key can contain only letters, digits, `-`, `_`, and `.`; a key with other characters doesn't open. It needs HeyGen's `voices:write` scope, and HeyGen refuses a key without it.
</ParamField>


<ParamField path="params.heygen_model" type="string" default="heygen-voice-1-turbo" toc={true}>
  The HeyGen Voice model, used when the voice string doesn't name one (`heygen.<voice>:<model>`). Valid values:

  - `heygen-voice-1-turbo`: lower latency.
  - `heygen-voice-1`: higher latency, especially on short phrases.

  Any other value uses the default.
</ParamField>


<ParamField path="params.heygen_stream_first" type="boolean" default="true" toc={true}>
  Whether a HeyGen voice streams each reply's first sentence, so playback starts at its first audio while the rest is generated in the background. Set it to `false` to turn that streaming off.
</ParamField>


<ParamField path="params.max_emotion" type="integer" toc={true}>
  Has no effect and can be omitted. Setting it does not change the voice.
</ParamField>


<ParamField path="params.speech_gen_quick_stops" type="integer" default="3" toc={true}>
  Number of quick stops for speech generation. Allowed values from `0`-`10`.
</ParamField>


<ParamField path="params.tts_number_format" type="string" default="e164" toc={true}>
  The format of the number the AI will reference the phone number. Valid values: `e164` (e.g. +12345678901), `international` (e.g. +1 234-567-8901), or `national` (e.g. (234) 567-8901). `e.164` is accepted as another spelling of `e164`.
</ParamField>


<ParamField path="params.tts_pause_cap_ms" type="integer | string" default="300" toc={true}>
  The longest pause, in ms, that plays inside the agent's speech. Some voices pause for most of a second after a short sentence such as "Yes.", and a caller can take that pause as the end of the agent's turn. A quiet stretch between two sounds of a reply plays up to the cap, and the rest is dropped. Quiet before a reply's first sound and after its last isn't played. Quiet means a 20 ms frame below about −45 dBFS, or digital silence.

  Allowed values from `0` to `2,000`, where `0` plays speech as the engine made it. A value outside the range is clamped to it. Also accepts a duration, read as a [strict millisecond value](#duration-values); a value that's neither a number nor a duration keeps the default.

  The cap applies to the platform's built-in TTS engines, such as ElevenLabs, Cartesia, Rime, OpenAI, Deepgram, and Azure, when they don't stream. Speech plays as made on a voice with `streaming: true` and on the `polly`, `gcloud`, and `amazon` engines.
</ParamField>

<ParamField path="params.video_blank_image" type="string" toc={true}>
  What the caller sees on a video call without avatar clips (no `video_talking_file`): an `http://` or `https://` URL to a PNG, shown as a still image. The image can be up to 4 MB and 3840 x 2160 pixels, and is scaled to fit within 1280 x 720. Any other value is ignored. Without it, the still is black.

  The still shows when the call captures the caller's video frames, through `enable_vision` or the `visual_input` of a [semantic gate][semantic-gates] or SWAIG function, or when this param is set. Set it whenever you capture frames on a video call without avatar clips, so the caller doesn't see a black screen.
</ParamField>


<ParamField path="params.video_idle_file" type="string" toc={true}>
  URL of a video file to play when AI is idle. Only works for calls that support video.
</ParamField>


<ParamField path="params.video_listening_file" type="string" toc={true}>
  URL of a video file to play when AI is listening to the user speak. Only works for calls that support video.
</ParamField>


<ParamField path="params.video_talking_file" type="string" toc={true}>
  URL of a video file to play when AI is talking. Only works for calls that support video.
</ParamField>


<ParamField path="params.eleven_labs_similarity" type="number" deprecated={true} default="0.75" toc={true}>
  The similarity slider dictates how closely the AI should adhere to the original voice when attempting to replicate it. The higher the similarity, the closer the AI will sound to the original voice. Valid values range from `0.0` to `1.0`. **Deprecated**: Use [`languages[].params.similarity`][ai-languages-params] instead.
</ParamField>


<ParamField path="params.eleven_labs_stability" type="number" deprecated={true} default="0.50" toc={true}>
  The stability slider determines how stable the voice is and the randomness between each generation. Lowering this slider introduces a broader emotional range for the voice. Valid values range from `0.0` to `1.0`. **Deprecated**: Use [`languages[].params.stability`][ai-languages-params] instead.
</ParamField>


### Interruption & Barge Control

Manage how the AI agent handles interruptions when users speak over it, including when to stop speaking, acknowledge interruptions, or continue regardless.

<ParamField path="params.acknowledge_interruptions" type="boolean | integer" default="false" toc={true}>
  Instructs the agent to acknowledge crosstalk and confirm user input when the user speaks over the agent. `true` acknowledges up to one interruption; a positive integer sets the maximum number of interruptions to acknowledge.
</ParamField>


<ParamField path="params.barge_functions" type="boolean" default="false" toc={true}>
  Allow functions to be called during barging. When `false`, functions are not executed if the user is speaking.

  With `false`, a function's filler holds back the caller's words while it is playing or queued, and neither keypad input nor [`interrupt_on_noise`](#paramsinterrupt_on_noise) cuts it. Once the calls have returned and no filler or `say` is left, the reply after them can be barged. Under [`transparent_barge`](#paramstransparent_barge), a turn whose function ran is kept rather than discarded. A function has run once its call was sent; a call that a semantic gate blocked, or that names no available function, didn't run.

  With `true`, a turn that transparent barge discards also loses its tool calls and results: actions it queued with `post_process` don't run, and a call that hadn't run yet is dropped.
</ParamField>


<ParamField path="params.barge_match_string" type="string" toc={true}>
  Takes a string, including a regular expression, defining barge behavior. For example, this param can direct the AI to stop when the word "hippopotamus" is input.
</ParamField>


<ParamField path="params.barge_min_words" type="integer" toc={true}>
  Defines the number of words that must be input before triggering barge behavior. Allowed values from `1`-`99`.
</ParamField>


<ParamField path="params.enable_barge" type="string" toc={true}>
  Controls when user can interrupt the AI. Valid values: `"complete"`, `"partial"`, `"all"`, or boolean. Set to `false` to disable barging.

  With partial transcripts enabled (the default includes `partial`), a partial transcript that passes the barge checks while the model request is still out, before any of its reply has played, cancels that request, and none of the reply plays. [`barge_min_words`](#paramsbarge_min_words), [`barge_match_string`](#paramsbarge_match_string), and [`barge_functions`](#paramsbarge_functions) apply as they do while the agent speaks. Under [`transparent_barge`](#paramstransparent_barge), only a statement begun inside the window cancels the request; one begun later is the caller's next turn, and the reply plays first. `calling.ai.partial_result` carries `barged: true` when a partial cut the reply or cancelled the request.
</ParamField>


<ParamField path="params.ignore_backchannels" type="boolean" default="true" toc={true}>
  Ignores a bare acknowledgement that the caller says over the agent's speech, such as "mm-hmm", "uh-huh", "yeah", "okay", "right", or "got it": it doesn't interrupt the agent and isn't treated as a turn. "Yes", "no", "stop", and "wait" are never treated as acknowledgements, and "Yeah, but the…" barges as usual. Set it to `false` to treat acknowledgements like any other speech.

  - Over the agent's speech means the caller began while the agent's audio was playing, or during the stretch of audio just before it, such as a filler. Speech begun in a silence between them, or before the agent's first audio, doesn't count.
  - Said into silence, an acknowledgement is a turn as usual.
  - During a reply that a `no_barge_next_response` action protects, an acknowledgement is held until the reply has played, and then it's the caller's answer.
  - Each ignored acknowledgement adds a system-log entry with `action: "backchannel"` to the call log.

  "Okay", "alright", and "right" also answer questions, so one said over the end of a question the agent is still finishing is ignored.
</ParamField>


<ParamField path="params.interrupt_on_noise" type="boolean" default="false" toc={true}>
  When enabled, barges agent upon any sound interruption longer than 1 second. The 1-second threshold can't be changed. With [`barge_functions`](#paramsbarge_functions) off, it doesn't cut a function's filler.
</ParamField>


<ParamField path="params.interrupt_prompt" type="string" toc={true}>
  A prompt that is used to help the AI agent respond to interruptions.

  **Default:** "The user didn't wait for you to finish responding and started talking over you. As part of your next response, make a comment about how you were both talking at the same time and verify you properly understand what the user said."
</ParamField>


<ParamField path="params.transparent_barge" type="boolean" default="true" toc={true}>
  Lets the caller correct or extend what they just said. When the caller's next statement begins within [`transparent_barge_max_time`](#paramstransparent_barge_max_time) of their previous one, the agent's turn in between is discarded and the two statements go to the model as one, each part as said. Off when [`barge_match_string`](#paramsbarge_match_string) is set.

  - Inside the window, the turn in between is discarded whether its reply was whole, partial, or not started, and whether or not any of it played. A request still in flight is cancelled.
  - At or past the window, the agent's turn stands and the new words are a turn of their own. A request in flight runs on and its reply plays.
  - Speech the barge settings hold back never discards a turn on its own: speech with `enable_barge` off, below `barge_min_words`, or said over a function's filler with `barge_functions` off.
  - With [`barge_functions`](#paramsbarge_functions) off, a turn whose function ran is kept.
  - The greeting comes before the caller's first statement and is never discarded.
</ParamField>


<ParamField path="params.transparent_barge_max_time" type="integer | string" default="3000" toc={true}>
  The transparent barge window, in ms. It runs from when the caller's previous final transcript arrived to when their next statement began: its first partial transcript with words, its final transcript if no partial came first, or the first key for keypad input. Allowed values from `0` to `60,000`, where `0` means no limit, so every next statement is inside the window. Also accepts a [duration](#duration-values).
</ParamField>

## Duration values

A timing parameter takes a number or a duration string. A string with a unit letter or a colon is read as a duration, so `"20m"` is 20 minutes and `"1.5s"` is one and a half seconds.

- Units are `h` (hours), `m` (minutes), `s` (seconds), and `ms` (milliseconds). They are case-insensitive, and spaces are allowed anywhere, as in `"1h 30m"`.
- Several units combine with the larger unit first, each at most once: `"1h30m"`, `"2m30s"`, `"1s500ms"`. `"30m1h"` and `"1m1m"` aren't durations.
- Decimals are allowed: `"1.5s"`, `".5m"`, `"1.25h"`.
- A bare number after a unit is in the next smaller unit: `"1h30"` is 1 hour 30 minutes, `"2m30"` is 2 minutes 30 seconds, and `"1s500"` is 1.5 seconds.
- Clock form is `[[h:]m:]s`: `"1:30"` is 90 seconds, and `"1:02:30"` is 1 hour, 2 minutes, and 30 seconds. Minutes and seconds go up to `59`. Colons can't be mixed with unit letters or decimals. A colon at the start or end is ignored (`":30"` is 30 seconds), and two colons side by side aren't a duration.
- The result is rounded to the nearest millisecond, or to the nearest second for a value counted in seconds.
- A parameter's range applies to the result: `"15m"` for `inactivity_timeout` is `900000` ms, which is inside its range.

How a parameter reads a value depends on which of three kinds it is:

| Kind | Parameters | How a value is read |
|---|---|---|
| Millisecond | Every parameter on this page whose value is in ms, except the strict ones | A number is milliseconds, and a duration is converted to milliseconds, so `"1:30"` is `90000`, not 1.3 seconds. Any other string is read by its leading whole number: `"700"` is `700`, `"1500.25"` is `1500`, and a word is `0`. |
| Strict millisecond | [`semantic_gate_timeout_ms`](#paramssemantic_gate_timeout_ms), [`tts_pause_cap_ms`](#paramstts_pause_cap_ms), [`cartesia_max_buffer_delay_ms`](#paramscartesia_max_buffer_delay_ms) | A number is milliseconds. A string must be a whole number in digits or a duration with units; anything else, including a bare decimal such as `"0.5"`, keeps the default. |
| Second | [`hard_stop_time`](#paramshard_stop_time), and the `hold` function result action | A bare number is seconds, and the result is rounded to the second. |

## debug_webhook_url callback

A diagnostic feed for a call that is still in progress. Set `debug_webhook_url` and every step the
agent takes is posted to that URL as it happens: speech recognized, model called, tool invoked,
context switched, error hit. Use it to work out why a call went the way it did — which tool the agent
reached for, what came back, where a turn went wrong — or to react while the call is still live, such
as paging a supervisor.

Each request carries `call_info` plus one or more event properties, where the property name is the
event. One moment can produce several: evaluating a
[`data_map`](/docs/swml/reference/calling/ai/swaig/functions/data-map) webhook sends `webhook`,
`input`, `output`, `error_keys`, and `match` together. Handle the properties you recognize and ignore
the rest, since the set grows over time.
