`functions[].data_map` defines how a [`SWAIG function`](/docs/swml/reference/calling/ai/swaig/functions) should process and respond to the user's input data.

<ParamField path="functions[].data_map" type="object" toc={true}>
  An object that processes function inputs and executes operations through expressions, webhooks, or direct output.
</ParamField>

<Warning title="Processing order">
The components are processed in the following sequence:

1. `expressions` - Processes data using pattern matching (includes its own `output`)
2. `webhooks` - Makes external API calls (includes its own `output` and `expressions`)
3. `output` - Returns a direct response and actions to perform
</Warning>

Similar to a `return` statement in conventional programming languages,
when a valid [`output`](#data_mapoutput) is encountered within any component,
it immediately terminates function execution.
The `output` provides:
1. An optional `response`: the result the AI agent reads next, as a string or an object
2. An optional `action`: an action, or a list of actions, to be triggered

If no component produces a valid `output`, the system continues processing in sequence:
- First attempts `expressions`
- If unsuccessful, tries `webhooks`
- If still unsuccessful, attempts top-level `output`
- If all fail, returns a generic fallback error message


## **Properties**

<ParamField path="data_map.expressions" type="object[]" toc={true}>
  An array of objects that define plain string or regex patterns to match against the user's input. Expressions are tried in order; the first one that matches returns its `output`. Each expression sets either `string` with `pattern`, or `expr`.
</ParamField>

<Indent>

<ParamField path="expressions[].string" type="string" toc={true}>
  The value to test, after variable expansion, such as `%{args.reason}`. Matched against `pattern`. Required unless `expr` is set.
</ParamField>

<ParamField path="expressions[].pattern" type="string" toc={true}>
  A regular expression to match against `string`. It matches case-insensitively unless written in `/pattern/flags` form. Required with `string`.
</ParamField>

<ParamField path="expressions[].expr" type="string" toc={true}>
  An expression evaluated after variable expansion, used instead of `string`. The expression matches when it evaluates to a nonzero value. When it doesn't match and `pattern` is set, `pattern` is tried against the same text.
</ParamField>

<ParamField path="expressions[].output" type="object" required={true} toc={true}>
  Defines the response or action to be taken when the expression matches.
  See [`output`](#data_mapoutput) for details.
</ParamField>

<ParamField path="expressions[].nomatch-output" type="object" toc={true}>
  The result to return when the expression doesn't match, in the same shape as [`output`](#data_mapoutput). When omitted, the next expression is tried.
</ParamField>

</Indent>


<ParamField path="data_map.webhooks" type="object[]" toc={true}>
  An array of objects that define external API calls. If a webhook defines `foreach`, `expressions`, and `output`, they are evaluated in that order. Each webhook needs `output`, `expressions`, or both.
  See [webhook runtime request](#webhook-runtime-request) for how the webhooks are tried.
</ParamField>

<Indent>

<ParamField path="webhooks[].url" type="string" required={true} toc={true}>
  The endpoint for the external service or API. Authentication can also be set in the url in the format of `username:password@url`. See [webhook runtime request](#webhook-runtime-request) for details on template variable substitution and request behavior.
</ParamField>

<ParamField path="webhooks[].method" type="string" default="GET" toc={true}>
  The HTTP method for the API call: `GET` or `POST`. A request with a body, which it has when `params` is set or `input_args_as_params` is `true`, is always sent as a `POST`, whatever this is set to.
</ParamField>

<ParamField path="webhooks[].headers" type="object" toc={true}>
  Any necessary headers for the API call, as string values. Header values are sent exactly as written; variables in them are not expanded.
</ParamField>

<ParamField path="webhooks[].form_param" type="string" toc={true}>
  Sends the request body as a single URL-encoded form field with this name, instead of as JSON. The whole JSON body becomes the value of that one field. Whenever this is set, the request's `Content-Type` is `application/x-www-form-urlencoded`, even when the request has no body.
</ParamField>

<ParamField path="webhooks[].params" type="object" toc={true}>
  An object of any necessary parameters for the API call. The key is the parameter name and the value is the parameter value.
</ParamField>

<ParamField path="webhooks[].input_args_as_params" type="boolean" default="false" toc={true}>
  A boolean to determine if the input [parameters](/docs/swml/reference/calling/ai/swaig/functions/parameters) should be passed as parameters.
</ParamField>

<ParamField path="webhooks[].require_args" type="string | string[]" toc={true}>
  The names of function [arguments](/docs/swml/reference/calling/ai/swaig/functions/parameters) that must be present for this webhook to be used. With an array, any one of the listed arguments is enough. An argument counts as present when the AI supplied it, whatever its value. An empty array means the webhook is never used. When the condition isn't met, the next webhook is tried.
</ParamField>

<ParamField path="webhooks[].error_keys" type="string | string[]" toc={true}>
  A string or array of strings that represent the keys to be used for error handling.
</ParamField>

<ParamField path="webhooks[].expressions" type="object[]" toc={true}>
  A list of expressions to be evaluated upon matching. Required unless `output` is set.
  See [`expressions`](#data_mapexpressions) for details.
</ParamField>

<ParamField path="webhooks[].foreach" type="object" toc={true}>
  Iterates over an array of objects and processes an output based on each element in the array. Works similarly to JavaScript's [forEach](https://www.w3schools.com/jsref/jsref_foreach.asp) method.
</ParamField>

<Indent>

<ParamField path="foreach.input_key" type="string" required={true} toc={true}>
  The key to be used to access the current element in the array.
</ParamField>

<ParamField path="foreach.output_key" type="string" required={true} toc={true}>
  The key that can be referenced in the output of the `foreach` iteration. The values that are stored from `append` will be stored in this key.
</ParamField>

<ParamField path="foreach.append" type="string" required={true} toc={true}>
  The values to append to the `output_key`.
  Properties from the object can be referenced and added to the `output_key` by using the following syntax: `${this.property_name}`.
  The `this` keyword is used to reference the current object in the array.
</ParamField>

<ParamField path="foreach.max" type="integer" toc={true}>
  The max amount of elements that are iterated over in the array. This will start at the beginning of the array.
</ParamField>

</Indent>

<ParamField path="webhooks[].output" type="object" toc={true}>
  Defines the response or action to be taken when the webhook is successfully triggered. Required unless `expressions` is set.
  See [`output`](#data_mapoutput) for details.
</ParamField>

</Indent>


<ParamField path="data_map.output" type="object" toc={true}>
  Similar to a `return` statement in conventional programming languages, the `data_map.output` object immediately
  terminates function execution and returns control to the caller.
</ParamField>

<Indent>

<ParamField path="output.response" type="string | object" toc={true}>
  The result the agent reads next. A string becomes the tool message as written. An object splits it into
  `tool_result`, the data the agent reads, and `tool_prompt`, an instruction added right after it.
  When omitted, the agent gets a default result.
</ParamField>

<ParamField path="output.action" type="object | object[]" toc={true}>
  An action, or a list of actions, for the platform to perform on the call.
  See [list of valid actions](#list-of-valid-actions) for details.
</ParamField>

<ParamField path="output.post_process" type="boolean" default="false" toc={true}>
  If `true`, the actions run after the agent has spoken its reply rather than immediately.
</ParamField>

</Indent>

## **Webhook runtime request**

When the AI triggers a function that uses `data_map.webhooks`, SignalWire tries the webhooks in order. A webhook whose
`require_args` aren't met is skipped. The first webhook that is called is the only one used: later webhooks
aren't called, even when the request fails or `error_keys` marks the response as failed. In that case the function
falls back to `data_map.output`.

### Template variables

The `url` and `params` fields support `%{variable}` substitution.
Nested properties use dot notation — for example,
`https://api.example.com/weather?city=%{args.location}` substitutes the value the AI extracted for `location`.
For more on [variables](/docs/swml/reference/variables) and scopes, see the [Variables reference](/docs/swml/reference/variables).

### Request body

When `params` is defined, SignalWire sends the `params` object as the JSON request body (or as a single URL-encoded form field when `form_param` is set), as a `POST`.
Template variables in `params` values are expanded before sending.

If no `params` are defined and `method` is not `POST`, the request is sent without a body.

If [`input_args_as_params`](#properties) is `true`, the function arguments extracted by the AI
are merged into `params`. If no `params` are defined, the arguments become the entire request body.

### Response processing

The JSON response from the webhook is processed through the [`output`](#data_mapoutput) template.
Fields from the response can be referenced using `%{key}` syntax in the output's `response` string.
For example, if the webhook returns `{"temp": 72, "conditions": "sunny"}`, an output of
`"The weather is %{temp}°F with %{conditions}"` will produce `"The weather is 72°F with sunny"`.


## **Examples**

### expressions

<CodeBlocks>
<CodeBlock title="YAML">
```yaml
data_map:
  expressions:
    - string: "starwars"
      pattern: "(?i)star\\s*wars"
      output:
        response: "May the Force be with you!"
    - string: "startrek"
      pattern: "(?i)star\\s*trek"
      output:
        response: "Live long and prosper!"
```
</CodeBlock>
<CodeBlock title="JSON">
```json
{
  "data_map": {
    "expressions": [
      {
        "string": "starwars",
        "pattern": "(?i)star\\s*wars",
        "output": {
          "response": "May the Force be with you!"
        }
      },
      {
        "string": "startrek",
        "pattern": "(?i)star\\s*trek",
        "output": {
          "response": "Live long and prosper!"
        }
      }
    ]
  }
}
```
</CodeBlock>
</CodeBlocks>

### webhooks with explicit params

<CodeBlocks>
<CodeBlock title="YAML">
```yaml
data_map:
  webhooks:
    - url: https://api.example.com/weather
      method: POST
      params:
        call_id: "%{call_id}"
        city: "%{args.location}"
      output:
        response: "The weather in %{city} is %{temp}°F and %{conditions}."
```
</CodeBlock>
<CodeBlock title="JSON">
```json
{
  "data_map": {
    "webhooks": [
      {
        "url": "https://api.example.com/weather",
        "method": "POST",
        "params": {
          "call_id": "%{call_id}",
          "city": "%{args.location}"
        },
        "output": {
          "response": "The weather in %{city} is %{temp}°F and %{conditions}."
        }
      }
    ]
  }
}
```
</CodeBlock>
</CodeBlocks>

Sends the following request body to `https://api.example.com/weather`:

```json
{
  "call_id": "xxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "city": "New York"
}
```

### webhooks with input_args_as_params

<CodeBlocks>
<CodeBlock title="YAML">
```yaml
data_map:
  webhooks:
    - url: https://api.example.com/weather
      method: POST
      input_args_as_params: true
      output:
        response: "The weather is %{temp}°F and %{conditions}."
```
</CodeBlock>
<CodeBlock title="JSON">
```json
{
  "data_map": {
    "webhooks": [
      {
        "url": "https://api.example.com/weather",
        "method": "POST",
        "input_args_as_params": true,
        "output": {
          "response": "The weather is %{temp}°F and %{conditions}."
        }
      }
    ]
  }
}
```
</CodeBlock>
</CodeBlocks>

Sends the AI-extracted arguments directly as the request body:

```json
{
  "location": "New York"
}
```

### output with action

<CodeBlocks>
<CodeBlock title="YAML">

                type: object

                    type: string
