Defines the AI agent's personality, goals, behaviors, and instructions for handling conversations.
The prompt establishes how the agent should interact with callers, what information it should gather,
and how it should respond to various scenarios.

It is recommended to write prompts using markdown formatting as LLMs better understand structured content.
It is also recommended to read the [prompt engineering][prompt-engineering] guide.

### Prompt types

There are three ways to define prompt content, each suited for different use cases:

- **Text prompt** — A single string containing the full prompt. Best for simple agents where the entire personality, instructions, and rules fit naturally into one block of text.

- **POM (Prompt Object Model)** — A structured array of sections with titles, body text, and bullet points. Best for complex prompts that benefit from clear organization. SignalWire renders the POM into a markdown document before sending it to the LLM.

- **Contexts** — A system of named conversation flows, each with its own steps, memory settings, and transition logic. Best for multi-stage conversations where the agent needs to switch between distinct modes (e.g., greeting → support → billing). Requires a `default` context as the entry point. See [Contexts](#contexts) below.

Text and POM are mutually exclusive — use one or the other. Contexts can be combined with either a text or POM prompt to add structured conversation flows on top of the base prompt.

<ParamField path="contexts.default" type="object" required={true} toc={true}>
  The default context used at the beginning of the conversation.

<ParamField path="*.prompt" type="string" toc={true}>
  Instructions for this context. They are added to the instructions of each step in the context.

<ParamField path="*.pom" type="object[]" toc={true}>

<ParamField path="*.initial_step" type="string" toc={true}>
  The name of the step to start at when this context is entered, matched case-insensitively. When omitted, or when no step has that name, the context starts at its first step.

<ParamField path="*.history" type="string" default="default" toc={true}>
  How much of the earlier conversation the AI sees when it moves from one step to the next in this context:

  - `default` hides the instructions of earlier steps but keeps the conversation.
  - `keep` keeps the instructions of earlier steps and the conversation.
  - `hide` hides the instructions of earlier steps and the earlier conversation, including function calls and their results.
</ParamField>

<ParamField path="*.valid_steps" type="string[]" toc={true}>
  Steps the AI can move to when it switches to this context, before the current step's own `valid_steps` apply. Include `next` to allow the following step.
</ParamField>

<ParamField path="*.valid_contexts" type="string[]" toc={true}>
  Contexts the AI can switch to when it switches to this context, before the current step's own `valid_contexts` apply.
</ParamField>

<ParamField path="*.post_prompt" type="object" toc={true}>
  A post-prompt for the end-of-call summary. While this context is active, including when it is the starting context, it replaces [`ai.post_prompt`](/docs/swml/reference/calling/ai#aipost_prompt); switching to a context without one restores `ai.post_prompt`. Takes the same properties as `ai.post_prompt` except `model`.
</ParamField>

<ParamField path="*.isolated" type="boolean" default="false" toc={true}>
  When `true`, resets conversation history to only the system prompt when entering this context. Useful for focused tasks that shouldn't be influenced by previous conversation.
</ParamField>

<ParamField path="*.enter_fillers" type="object" toc={true}>
  Filler phrases played when entering this context, keyed by language code. One phrase is picked at random.

  The agent looks for an entry matching the language being spoken, then `auto`, then `default`, and plays nothing when none of the three is set.
</ParamField>

<Indent>

<ParamField path="enter_fillers.*" type="string[]" toc={true}>
  An array of filler phrases for one language code. See [filler language codes](/docs/swml/reference/calling/ai/swaig#filler-language-codes) for the codes in common use. Two keys are not language codes: `auto` has the phrases translated into whichever language is being spoken, and `default` covers every language you have not listed.
</ParamField>

</Indent>

<ParamField path="*.exit_fillers" type="object" toc={true}>
  Filler phrases played when leaving this context. Same format as `enter_fillers`.
</ParamField>

</Indent>

</Indent>

<ParamField path="prompt.steps" type="object[]" toc={true}>
  An array of steps for a conversation that needs only one context. It works like the `steps` of a `default` context, with the properties described in [steps](#step-properties). Ignored when `prompt.contexts` is set.
</ParamField>

### Steps [#step-properties]

Each entry in a context's `steps`, or in `prompt.steps`, is a step object. A step gives its instructions in `text` or `pom`; a step with `gather_info` doesn't need either, and a step with `reset` doesn't use them.

<ParamField path="steps[].name" type="string" required={true} toc={true}>
  The name of the step, unique within its context. It can't be `next`, which refers to the following step.
</ParamField>

<ParamField path="steps[].text" type="string" toc={true}>
  The instructions for this step. Required unless the step sets `pom`, `reset`, or `gather_info`. Set either `text` or `pom`, not both.
</ParamField>

<ParamField path="steps[].pom" type="object[]" toc={true}>
  The instructions for this step as a POM. Sections take the same properties as [`prompt.pom`](#promptpom).
</ParamField>

<ParamField path="steps[].step_criteria" type="string" toc={true}>
  The criteria that must be met before the AI moves on from this step, given to the AI as an instruction. Custom criteria are highly recommended to get the intended behavior.
</ParamField>

<ParamField path="steps[].functions" type="string[]" toc={true}>
  Names of the SWAIG functions the AI can call during this step. When omitted, the functions that were already available stay available. An empty array makes none of the SWAIG functions available during this step.
</ParamField>

<ParamField path="steps[].valid_steps" type="string[]" toc={true}>
  Names of the steps the AI can move to from this step. Include `next` to allow the following step. When omitted, the AI can move to the next step in the context. An empty array means that, once the AI's available functions are refreshed for this step (for example, when the step sets `functions`), it is no longer offered a move to another step. A `change_step` action returned by a SWAIG function still works.
</ParamField>

<ParamField path="steps[].valid_contexts" type="string[]" toc={true}>
  Names of the contexts the AI can switch to from this step. Each must be a context defined in `prompt.contexts`.
</ParamField>

<ParamField path="steps[].skip_user_turn" type="boolean" default="false" toc={true}>
  If `true`, the AI responds to this step's instructions without waiting for the caller to speak first. It doesn't move to the next step on its own; set `skip_to_next_step` as well for that.
</ParamField>

<ParamField path="steps[].skip_to_next_step" type="boolean" default="false" toc={true}>
  Used together with `skip_user_turn`: after the AI's response, the conversation moves to the next step. Has no effect on its own.
</ParamField>

<ParamField path="steps[].end" type="boolean" default="false" toc={true}>
  If `true`, this is the last step in the context. Can't be used together with `valid_steps`.
</ParamField>

<ParamField path="steps[].reset" type="object" toc={true}>
  Resets the conversation with new instructions when this step becomes active, and makes this the last step in the context, like `end`. When `reset` is set, the step's `text`, `pom` and `gather_info` are not used; put the new instructions in `reset.system_prompt`.
</ParamField>

<Indent>

<ParamField path="reset.system_prompt" type="string" toc={true}>
  The new instructions. [Variables](#variable-expansion) such as `${caller_id_number}` are expanded, as in `prompt.text`.
</ParamField>

<ParamField path="reset.user_prompt" type="string" toc={true}>
  A message added as if the caller had said it, right after the reset. When `consolidate` is not `true`, defaults to `hello`. Variables are expanded, as in `prompt.text`.
</ParamField>

<ParamField path="reset.consolidate" type="boolean" default="false" toc={true}>
  If `true`, the conversation so far is summarized and the summary is carried over after the reset.
</ParamField>

<ParamField path="reset.full_reset" type="boolean" default="false" toc={true}>
  If `true`, `system_prompt` replaces the agent's original prompt. Otherwise the conversation is cleared and `system_prompt` is added as a new instruction.
</ParamField>

</Indent>

<ParamField path="steps[].gather_info" type="object" toc={true}>
  Asks the caller a list of questions and stores the answers in [`global_data`](/docs/swml/reference/calling/ai#aiglobal_data). While questions remain, the AI asks them one at a time and doesn't move to another step.
</ParamField>

<Indent>

<ParamField path="gather_info.questions" type="object[]" required={true} toc={true}>
  The questions to ask, in order. At least one is required.
</ParamField>

<Indent>

<ParamField path="questions[].key" type="string" required={true} toc={true}>
  The key the answer is stored under in `global_data`, or under `output_key` when it is set.
</ParamField>

<ParamField path="questions[].question" type="string" required={true} toc={true}>
  The question the AI asks the caller.
</ParamField>

<ParamField path="questions[].type" type="string" default="string" toc={true}>
  The type of the answer, as a JSON Schema type such as `string`, `number`, `integer`, or `boolean`.
</ParamField>

<ParamField path="questions[].confirm" type="boolean" default="false" toc={true}>
  If `true`, the AI reads the answer back and gets the caller's confirmation before accepting it.
</ParamField>

<ParamField path="questions[].prompt" type="string" toc={true}>
  Extra instructions for this question, added after the question.
</ParamField>

<ParamField path="questions[].functions" type="string[]" toc={true}>
  Names of SWAIG functions the AI can call while asking this question. Other functions are unavailable during the question.
</ParamField>

<ParamField path="questions[].isolated" type="boolean" toc={true}>
  If `true`, the answers to the other questions in this gather are hidden from the AI while it asks this one, so it must ask rather than work out the answer. Defaults to the `isolated` value of `gather_info`.
</ParamField>

</Indent>

<ParamField path="gather_info.prompt" type="string" toc={true}>
  Instructions added before the first question.
</ParamField>

<ParamField path="gather_info.pom" type="object[]" toc={true}>
  Instructions added before the first question, as a POM. Used when `prompt` is not set.
</ParamField>

<ParamField path="gather_info.output_key" type="string" toc={true}>
  A `global_data` key to store all the answers under, as an object keyed by each question's `key`. When omitted, each answer is stored directly in `global_data` under its `key`.
</ParamField>

<ParamField path="gather_info.completion_action" type="string" toc={true}>
  What to do after the last question is answered: `next_step` moves to the following step, and any other value is the name of the step to move to. When omitted, the conversation stays on the current step.
</ParamField>

<ParamField path="gather_info.isolated" type="boolean" default="false" toc={true}>
  If `true`, the answers to the other questions are hidden from the AI while it asks each question. A question's own `isolated` overrides this.
</ParamField>

</Indent>

## **Examples**

### Basic prompt

<CodeBlocks>
<CodeBlock title="YAML">
```yaml
version: 1.0.0
sections:
  main:
    - ai:
        prompt:
          text: |
            You are a friendly customer service agent for a telecommunications company.
            Your name is Alex. Always greet the caller warmly and ask how you can help.

            ## Rules
            - Be polite and professional at all times
            - If the caller asks about billing, offer to transfer them to the billing department
            - If you cannot help with a request, apologize and suggest alternatives
          temperature: 0.8
          top_p: 0.9
```
</CodeBlock>
<CodeBlock title="JSON">
```json
{

  "sections": {

Always greet the caller warmly and ask how you can help.\n\n## Rules\n- Be polite and professional at all times\n- If the caller asks about billing, offer to transfer them to the billing department\n- If you cannot help with a request, apologize and suggest alternatives\n",
            "temperature": 0.8,
            "top_p": 0.9
          }
        }
      }
    ]
  }
}
```

### Advanced multi-context

This example demonstrates multiple contexts with different AI personalities, voice settings, and specialized knowledge domains:

<CodeBlocks>
<CodeBlock title="YAML">
```yaml
sections:
  main:
    - ai:
        hints:
          - StarWars
          - StarTrek
        languages:
          - name: Ryan-English
            voice: elevenlabs.patrick
            code: en-US
          - name: Luke-English
            voice: elevenlabs.fin
            code: en-US
          - name: Spock-English
            voice: elevenlabs.charlie
            code: en-US
        prompt:
          text: Help the user transfer to the Star Wars or Star Trek expert.
          contexts:
            default:
              steps:
                - name: start
                  text: |+
                    Your name is Ryan. You are a receptionist. Your only purpose is to change the context to starwars or startrek.
                  step_criteria: |+
                    Introduce yourself as Ryan.
                    Ask the user if he would like to talk to a star wars or star trek expert until they provide an adequate answer.
                - name: transfer
                  text: You will now successfully transfer the user to the Star Wars or Star Trek expert.
                  step_criteria: If the user has chosen a valid context, transfer them to the appropriate expert.
                  valid_contexts:
                    - starwars
                    - startrek
            starwars:
              steps:
                - name: start
                  text: |+
                    The user has been transferred to the Star Wars expert.
                    Until told otherwise, your name is Luke. Change the language to Luke-English.
                    Your current goal is to get the user to tell you their name.
                    Unless told otherwise, refer to the user as 'Padawan {users_name}'.
                  step_criteria: |+
                    Introduce yourself as Luke, the Star Wars expert.
                    The user must tell you their name if they only say one word assume that is their name.
                - name: question
                  text: |+
                    Your goal is to get the user to choose one of the following options.
                    - Jedi Order (advance to jedi_order step)
                    - The ways of the Force (advance to force step)
                    - Talk to the star trek expert. (change context to startrek)
                  step_criteria: +|
                    The user must provide a valid answer to continue.
                    Refer to the user as 'Padawan {users_name}' for the rest of the conversation.
                  valid_steps:
                    - jedi_order
                    - force
```
