Play a prompt and wait for input. The input can be received either as digits from the keypad, or from speech, or both depending on
what [properties](#properties) are set.

## **Properties**

<ParamField path="prompt" type="object" required={true} toc={true}>
  An object that accepts the following properties.
</ParamField>

<Indent>

<ParamField path="prompt.play" type="string | string[]" required={true} toc={true}>
  Either a [playable sound](#playable-sounds) or an array of [playable sounds](#playable-sounds). Each entry can also be a [SWML variable](/docs/swml/reference/variables) that resolves to a playable sound. Unlike the `play` method, `prompt.play` doesn't accept an object.
</ParamField>


<ParamField path="prompt.volume" type="number" default="0" toc={true}>
  Volume gain to apply to played URLs. Allowed values from `-40.0` to `40.0`.
</ParamField>


<ParamField path="prompt.say_voice" type="string" default="Polly.Salli" toc={true}>
  Voice to use with `say:` for text to speech. When not set, the `say_voice` [variable](#variables) is used if it is set. A voice name can't contain whitespace, double quotes, backticks, or any of the characters `,{}()[]<>=/;!@#$%^&*+|~?`.
</ParamField>


<ParamField path="prompt.say_language" type="string" default="en-US" toc={true}>
  Language to use with `say:` for text to speech, as a language tag such as `en-US`. When not set, the `say_language` [variable](#variables) is used if it is set, otherwise `en-US`.
</ParamField>


<ParamField path="prompt.say_gender" type="string" default="female" toc={true}>
  Gender to use with `say:` for text to speech. **Valid values:** `male`, `female`. When not set, the `say_gender` [variable](#variables) is used if it is set, otherwise `female`.
</ParamField>


<ParamField path="prompt.max_digits" type="integer" default="1" toc={true}>
  Number of digits to collect. Must be at least `1`. Values above `100` are capped at `100`.
</ParamField>


<ParamField path="prompt.terminators" type="string" toc={true}>
  Digits that terminate digit collection
</ParamField>


<ParamField path="prompt.digit_timeout" type="number" default="5.0 seconds" toc={true}>
  Time in seconds to wait for next digit. Must be at least `1`.
</ParamField>


<ParamField path="prompt.initial_timeout" type="number" default="5.0 seconds" toc={true}>
  Time in seconds to wait for start of input. Must be at least `1`. This sets the wait only; it doesn't select digit or speech input.
</ParamField>


<ParamField path="prompt.speech_timeout" type="number" toc={true}>
  Max time in seconds to wait for speech result. Must be at least `1`.
</ParamField>


<ParamField path="prompt.speech_end_timeout" type="number" toc={true}>
  Time in seconds to wait for end of speech utterance. Must be at least `1`.
</ParamField>


<ParamField path="prompt.speech_language" type="string" toc={true}>
  Language to detect speech in, as a language tag such as `en-US`. Extension and private-use subtags aren't accepted. A valid tag doesn't guarantee that every speech engine supports the language.
</ParamField>


<ParamField path="prompt.speech_hints" type="string[]" toc={true}>
  Expected words or phrases to help speech recognition. Each hint must be a non-empty string and is sent as written; SWML variables inside hints aren't expanded. Hints longer than 100 bytes or containing `=` are ignored, and hints after the first 5,000, or after 100,000 bytes in total, are dropped.
</ParamField>


<ParamField path="prompt.speech_engine" type="string" toc={true}>
  The engine selected for speech recognition. The engine must support the specified language. Valid values: `Google`, `Google.V2`, `Deepgram`. Default is not set (SignalWire picks the engine).
</ParamField>


<ParamField path="prompt.status_url" type="string" toc={true}>
  HTTP or HTTPS URL to deliver prompt status events, or a [SWML variable](/docs/swml/reference/variables) that resolves to one. Learn more about [status callbacks][statuscallbacks].
</ParamField>

</Indent>

<Note>
By default, only digit input via keypad is enabled. When **at least one** speech input based parameter
is set (`speech_timeout`, `speech_end_timeout`, `speech_language` or `speech_hints`), speech input is
enabled and digit input is disabled. Setting `speech_engine` alone doesn't enable speech input.

To enable speech and digit based input collection at once, set at least one speech input parameter
and at least one digit input based parameter (`max_digits`, `terminators`, or `digit_timeout`).
`initial_timeout` doesn't count as a digit input parameter.
</Note>

## Variables

Read by the method:

- **say_voice:** (in) - optional voice to use for text to speech.
- **say_language:** (in) - optional language to use for text to speech.
- **say_gender:** (in) - optional gender to use for text to speech.

## Possible values for voice, language, and ringtone

<Markdown src="/snippets/swml/_voice-table.mdx" />

### Set by the method

- **prompt_result:** (out) - usually `failed`, `no_input`, `match_speech`, `match_digits`, or `no_match`. If speech recognition reports an error, it can instead hold that error value.
- **prompt_value:** (out) - the digits collected, unchanged, or the recognized speech, normalized: converted to lowercase, with punctuation and other separators collapsed into single spaces and removed from the start and end. Apostrophes, hyphens, and non-ASCII characters are kept.
- **prompt_value_raw:** (out) - the digits or recognized speech exactly as collected, before normalization. Cleared along with `prompt_value` when nothing is collected or the method fails.
- **prompt_digit_terminator:** (out) - digit terminator collected, if any.
- **prompt_speech_confidence:** (out) - speech confidence measured, if any.

## **StatusCallbacks**

<Markdown src="/snippets/common/_status-callback-advisory.mdx" />

A POST request will be sent to `status_url` with a JSON payload like the following. The prompt sends two kinds of events to the same URL: `calling.call.collect` with the input result, and `calling.call.play` as the prompt audio plays.

<ParamField path="event_type" type="string" toc={true}>
  The type of event: `calling.call.collect` for the input result, or `calling.call.play` for prompt playback state.
</ParamField>


<ParamField path="event_channel" type="string" toc={true}>
  The channel for the event, includes the SWML session ID.
</ParamField>


<ParamField path="timestamp" type="number" toc={true}>
  Unix timestamp (float) when the event was generated.
</ParamField>


<ParamField path="project_id" type="string" toc={true}>
  The project ID associated with the call.
</ParamField>


<ParamField path="space_id" type="string" toc={true}>
  The Space ID associated with the call.
</ParamField>


<ParamField path="params" type="object" toc={true}>
  An object containing prompt-specific parameters.
</ParamField>

<Indent>

<ParamField path="params.call_id" type="string" toc={true}>
  The call ID.
</ParamField>


<ParamField path="params.node_id" type="string" toc={true}>
  The node handling the call.
</ParamField>


<ParamField path="params.control_id" type="string" toc={true}>
  The control ID for this prompt operation.
</ParamField>


<ParamField path="params.result" type="object" toc={true}>
  The collection result details. Present on `calling.call.collect` events.
</ParamField>

<Indent>

<ParamField path="params.result.type" type="string" toc={true}>
  The type of result. Standard values are `digit`, `speech`, `no_input`, `no_match`, and `error`. If speech recognition reports an error, it can instead hold that error value.
</ParamField>


<ParamField path="params.result.params" type="object" toc={true}>
  The collected input. Present when `type` is `digit` or `speech`.
</ParamField>

<Indent>

<ParamField path="params.result.params.digits" type="string" toc={true}>
  The DTMF digits collected (when `type` is `digit`).
</ParamField>


<ParamField path="params.result.params.terminator" type="string" toc={true}>
  The terminator digit that ended collection (when `type` is `digit`).
</ParamField>


<ParamField path="params.result.params.text" type="string" toc={true}>
  The recognized speech text, before the normalization applied to `prompt_value` (when `type` is `speech`).
</ParamField>


<ParamField path="params.result.params.confidence" type="number" toc={true}>
  The speech recognition confidence score (when `type` is `speech`).
</ParamField>

</Indent>

</Indent>

<ParamField path="params.state" type="string" toc={true}>
  On `calling.call.play` events, the playback state of the prompt audio. **Valid values:** `playing`, `finished`, `error`.

  On `calling.call.collect` events, the current collection state. Only present when continuous collect is enabled. **Valid values:** `collecting`, `finished`, `error`.
</ParamField>

</Indent>

### Error notifications

When the prompt request itself fails, `status_url` can also receive a separate event with `event_type` set to `calling.error`. Its `params.error` object carries the error `code` and `message`. Not every failure produces this event.

## **Examples**

The [`play` method](/docs/swml/reference/calling/play) also has examples related to playing sounds from URLs. Both
methods use the same [playable sound](#playable-sounds) syntax, but `prompt.play` takes only a string or an array of
strings, not a `play` object. Set `volume`, the `say_*` properties, and `status_url` directly on `prompt`; other `play`
properties, such as `loop` and `auto_answer`, aren't available.

### Play prompt and wait for digit press

<CodeBlocks>
<CodeBlock title="YAML">
```yaml
version: 1.0.0
sections:
  main:
    - prompt:
        play: 'say:Input a number'
    - switch:
        variable: prompt_value
        default:
          - play:
              url: 'say:You didn''t press one'
          - transfer:
              dest: main
        case:
          '1':
            - play:
                url: 'say:You pressed one'
```
</CodeBlock>
<CodeBlock title="JSON">
```json
{
  "version": "1.0.0",
  "sections": {
    "main": [
      {
        "prompt": {
          "play": "say:Input a number"
        }
      },
      {
        "switch": {
          "variable": "prompt_value",
          "default": [
            {
              "play": {
                "url": "say:You didn't press one"
              }
            },
            {
              "transfer": {
                "dest": "main"
              }
            }
          ],
          "case": {
            "1": [
              {
                "play": {
                  "url": "say:You pressed one"
                }
              }
            ]
          }
        }
      }
    ]
  }
}
```
</CodeBlock>
</CodeBlocks>

### Using terminators

<CodeBlocks>
<CodeBlock title="YAML">
```yaml
version: 1.0.0
sections:
  main:
    - prompt:
        play: 'say:PIN number please'

        terminators: '*#5'
    - play:
        url: 'say: ${prompt_value} was terminated by ${prompt_digit_terminator}'
```
</CodeBlock>
<CodeBlock title="JSON">

      },
      {
        "play": {

### Play prompt and collect digits, then pass the data to an external action

<CodeBlocks>
<CodeBlock title="YAML">
```yaml
version: 1.0.0
sections:
  main:
    - prompt:
        play: 'https://example.com/menu.wav'
    - transfer:
        dest: 'https://example.com/post_next_menu'
```
</CodeBlock>
<CodeBlock title="JSON">
```json
{
  "version": "1.0.0",
  "sections": {
    "main": [
      {
        "prompt": {
          "play": "https://example.com/menu.wav"
        }
      },
      {
        "transfer": {
          "dest": "https://example.com/post_next_menu"
        }
      }
    ]
  }
}
```
</CodeBlock>
</CodeBlocks>

In this case, the URL listed in transfer will be sent an HTTP POST request
with all the [out variables](#set-by-the-method) (like `prompt_value`) already set. For
more details on this behavior, refer to [`transfer`](/docs/swml/reference/calling/transfer)
statement's documentation.
