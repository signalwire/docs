Send SIP REFER to a SIP call. The [SIP REFER guide](/docs/platform/voice/sip-refer) explains what the far-end device must support and when to use a bridged transfer instead.

## **Properties**

<ParamField path="sip_refer" type="object" required={true} toc={true}>
  An object that accepts the following properties.
</ParamField>

<Indent>

<ParamField path="sip_refer.to_uri" type="string" toc={true}>
  SIP URI to REFER to. At least one of `to_uri` or `to` is required. When both are set, `to_uri` takes precedence unless it is empty after variable expansion.
</ParamField>


<ParamField path="sip_refer.to" type="string" toc={true}>
  Alias for `to_uri`. Used as the SIP URI to REFER to when `to_uri` is not set or is empty after variable expansion.
</ParamField>


<ParamField path="sip_refer.status_url" type="string" toc={true}>
  HTTP or HTTPS URL to deliver SIP REFER status events. Learn more about [status callbacks][statuscallbacks].
</ParamField>


<ParamField path="sip_refer.username" type="string" toc={true}>
  Username to use for SIP authentication.
</ParamField>


<ParamField path="sip_refer.password" type="string" toc={true}>
  Password to use for SIP authentication.
</ParamField>

</Indent>


## **Variables**

Set by the method:

- **sip_refer_to:** (out) The SIP URI the recipient is to INVITE.
- **sip_refer_result:** (out) Final SIP REFER result: `success`, `cancel`, `noAnswer`, `busy`, or `error`. Set to `error` when the REFER could not be executed. A `success` result doesn't by itself confirm that the refer target answered.
- **sip_refer_response_code:** (out) Recipient response to the REFER request.
- **sip_refer_to_response_code:** (out) INVITE response to the recipient.

## **StatusCallbacks**

<Markdown src="/snippets/common/_status-callback-advisory.mdx" />

A POST request will be sent to `status_url` with a JSON payload like the following, for a `calling.call.refer` event:

<ParamField path="event_type" type="string" toc={true}>
  The type of event. `calling.call.refer` for the SIP REFER status events described here. When the REFER can't be executed, an error event with event type `calling.error` may be sent instead; see [error events](#error-events).
</ParamField>


<ParamField path="event_channel" type="string" toc={true}>
  The channel for the event, includes the SWML session ID.
</ParamField>


<ParamField path="timestamp" type="number" toc={true}>
  Unix timestamp (float) when the event was generated.
</ParamField>


<ParamField path="project_id" type="string" toc={true}>
  The project ID associated with the call.
</ParamField>


<ParamField path="space_id" type="string" toc={true}>
  The Space ID associated with the call.
</ParamField>


<ParamField path="params" type="object" toc={true}>
  An object containing SIP REFER-specific parameters.
</ParamField>

<Indent>

<ParamField path="params.call_id" type="string" toc={true}>
  The call ID.
</ParamField>


<ParamField path="params.node_id" type="string" toc={true}>
  The node handling the call.
</ParamField>


<ParamField path="params.sip_refer_to" type="string" toc={true}>
  The SIP URI the recipient is being referred to.
</ParamField>


<ParamField path="params.state" type="string" toc={true}>
  The state of the SIP REFER operation. When the recipient accepts the REFER request, an intermediate event with state `inProgress` may be sent. The final event carries one of `success`, `cancel`, `noAnswer`, `busy`, or `error`. A `success` state doesn't by itself confirm that the refer target answered.
</ParamField>


<ParamField path="params.sip_refer_response_code" type="string" toc={true}>
  The SIP response code for the REFER request itself (e.g., `"202"`). Only present when a response has been received.
</ParamField>


<ParamField path="params.sip_notify_response_code" type="string" toc={true}>
  The SIP response code for the INVITE sent by the recipient to the refer target (e.g., `"200"`). Only present when a response has been received.
</ParamField>


<ParamField path="params.segment_id" type="string" toc={true}>
  The segment ID for the call leg. Present when available.
</ParamField>


<ParamField path="params.tag" type="string" toc={true}>
  The tag associated with the call. Present when set.
</ParamField>

</Indent>

### Raw JSON example

```json
{
  "event_type": "calling.call.refer",
  "event_channel": "swml:xxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "timestamp": 1640000000.123,
  "project_id": "xxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "space_id": "xxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "params": {
    "call_id": "xxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
    "node_id": "xxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
    "sip_refer_to": "sip:alice@example.com",
    "state": "success",
    "sip_refer_response_code": "202",
    "sip_notify_response_code": "200"
  }
}
```

### Error events

When the REFER can't be executed, for example because the call isn't a SIP call, SignalWire may send an event with `event_type` set to `calling.error` to `status_url` instead of a `calling.call.refer` event. Its `params` object doesn't contain the SIP REFER fields above. It carries the call identifiers and an `error` object:

<ParamField path="params.error.code" type="string" toc={true}>
  The error code (for example, `"409"`).
</ParamField>


<ParamField path="params.error.message" type="string" toc={true}>
  A description of the error.
</ParamField>

Check `event_type` before reading the rest of the payload. Not every failure produces an error event.

## **Examples**

### Send SIP REFER and post result

<CodeBlocks>
<CodeBlock title="YAML">
```yaml
version: 1.0.0
sections:
  main:
    - sip_refer:
        to_uri: 'sip:alice@example.com'
    - play:
        url: 'say: Connected. The SIP refer result is ${sip_refer_result}'
    - execute:
        dest: 'https://example.com/handle_sip_refer_result'
```
</CodeBlock>
