End the call with an optional reason.

## **Properties**

<ParamField path="hangup" type="object" required={true} toc={true}>
  An object that accepts the following properties.
</ParamField>

<Indent>

<ParamField path="hangup.reason" type="string" toc={true}>
  The reason for hanging up the call. One of `hangup`, `cancel`, `busy`, `noAnswer`, `decline`, or `error`. Also accepts a SWML variable reference (string) that resolves to one of these values.

  The reason only affects an inbound call that hasn't been answered yet. If `reason` is omitted or set to `hangup` or `busy`, the call is rejected as busy; any other value rejects it as declined. An answered call ends normally, and an unanswered outbound call is canceled, whatever the reason.
</ParamField>

</Indent>

## Variables

Set by the method:

- **hangup_result:** (out) `success` if the hangup request succeeded (including when the call had already ended), or `failed` if it didn't.

## **Examples**

### No parameters

<CodeBlocks>
<CodeBlock title="YAML">
```yaml
version: 1.0.0
sections:
  main:
    - answer: {}
    - hangup: {}
```
</CodeBlock>
<CodeBlock title="JSON">
```json
{
  "version": "1.0.0",
  "sections": {
    "main": [
      {
        "answer": {}
      },
      {
        "hangup": {}
      }
    ]
  }
}
```
</CodeBlock>
</CodeBlocks>

### Reject an unanswered inbound call as declined

The call isn't answered first, so the reason applies.

<CodeBlocks>
<CodeBlock title="YAML">
```yaml
version: 1.0.0
sections:
  main:
    - hangup:
        reason: "decline"
```
</CodeBlock>
<CodeBlock title="JSON">
```json
{
  "version": "1.0.0",
  "sections": {
    "main": [
      {
        "hangup": {
          "reason": "decline"
        }
      }
    ]
  }
}
```
</CodeBlock>
</CodeBlocks>
