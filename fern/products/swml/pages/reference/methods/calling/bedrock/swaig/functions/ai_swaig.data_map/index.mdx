`functions[].data_map` defines how a [`SWAIG function`](/docs/swml/reference/calling/amazon-bedrock/swaig/functions) should process and respond to the user's input data.

<ParamField path="functions[].data_map" type="object" toc={true}>
  An object that processes function inputs and executes operations through expressions, webhooks, or direct output.
</ParamField>

<Warning title="Processing order">
The components are processed in the following sequence:

1. `expressions` - Processes data using pattern matching (includes its own `output`)
2. `webhooks` - Makes external API calls (includes its own `output` and `expressions`)
3. `output` - Returns a direct response and actions to perform
</Warning>

Similar to a `return` statement in conventional programming languages,
when a valid [`output`](#output) is encountered within any component,
it immediately terminates function execution.
The `output` provides:
1. A `response` string: the result the agent reads next
2. An optional `action`: one or more actions to run once the agent has spoken its reply

If no component produces a valid `output`, the system continues processing in sequence:
- First attempts `expressions`
- If unsuccessful, tries `webhooks`
- If still unsuccessful, attempts top-level `output`
- If all fail, returns a generic fallback error message


## **Properties**

<ParamField path="data_map.expressions" type="object[]" toc={true}>
  An array of objects that test text against a regular expression. Expressions are tried in order, and the first one
  that returns a result ends the search.
</ParamField>

<Indent>

<ParamField path="expressions[].string" type="string" toc={true}>
  The text to test, after variable expansion. Each expression sets `string` or `expr`; when both are set, `string`
  is used.
</ParamField>

<ParamField path="expressions[].expr" type="string" toc={true}>
  Another name for `string`, used when `string` is not set. It is tested as text: it is not evaluated as an
  arithmetic or logical expression.
</ParamField>

<ParamField path="expressions[].pattern" type="string" toc={true}>
  A regular expression to match against the text. It matches case-insensitively unless written in `/pattern/flags`
  form. When omitted, the expression always matches.
</ParamField>

<ParamField path="expressions[].output" type="object" required={true} toc={true}>
  The result to return when the expression matches.
  See [`output`](#output) for details.
</ParamField>

<ParamField path="expressions[].nomatch-output" type="object" toc={true}>
  The result to return when `pattern` doesn't match. Returning it ends the search, as a match does. When omitted, the
  next expression is tried. See [`output`](#output) for details.
</ParamField>

</Indent>


<ParamField path="data_map.webhooks" type="object[]" toc={true}>
  An array of objects that define external API calls. Webhooks are tried in order, and the first one whose response is
  used ends the search. If a webhook defines `foreach`, `expressions`, and `output`, they are evaluated in that order.
</ParamField>

<Indent>

<ParamField path="webhooks[].url" type="string" required={true} toc={true}>
  The endpoint for the external service or API. Authentication can also be set in the url in the format of `username:password@url`. See [webhook runtime request](#webhook-runtime-request) for details on template variable substitution and request behavior.
</ParamField>

<ParamField path="webhooks[].method" type="string" default="GET" toc={true}>
  The HTTP method for the API call: `GET` or `POST`. The request is sent as a `POST` whenever it has a body, that is
  when `params` is set or `input_args_as_params` is `true`, whatever this is set to.
</ParamField>

<ParamField path="webhooks[].headers" type="object" toc={true}>
  Any necessary headers for the API call, as string values. Header values are sent exactly as written; a value that is
  not a string is skipped.
</ParamField>

<ParamField path="webhooks[].params" type="object" toc={true}>
  An object of any necessary parameters for the API call. The key is the parameter name and the value is the parameter value.
</ParamField>

<ParamField path="webhooks[].form_param" type="string" toc={true}>
  Sends the request body as a single URL-encoded form field with this name, instead of as JSON. The whole JSON body
  becomes the value of that one field. Only applies when the request has a body.
</ParamField>

<ParamField path="webhooks[].input_args_as_params" type="boolean" default="false" toc={true}>
  A boolean to determine if the input [parameters](/docs/swml/reference/calling/amazon-bedrock/swaig/functions/parameters) should be passed as parameters.
</ParamField>

<ParamField path="webhooks[].error_keys" type="string[]" toc={true}>
  Keys that mark the API response as failed. When any of them is present at the top level of the response, whatever
  its value, the response is not used and the next webhook is tried.
</ParamField>

<ParamField path="webhooks[].expressions" type="object[]" toc={true}>
  An array of expressions evaluated against the API response, before `output`.
  See [`expressions`](#expressions) for details.
</ParamField>

<ParamField path="webhooks[].foreach" type="object" toc={true}>
  Iterates over an array of objects and processes an output based on each element in the array. Works similarly to JavaScript's [forEach](https://www.w3schools.com/jsref/jsref_foreach.asp) method.
</ParamField>

<Indent>

<ParamField path="foreach.input_key" type="string" required={true} toc={true}>
  The key in the API response that holds the array to iterate over.
</ParamField>

<ParamField path="foreach.output_key" type="string" required={true} toc={true}>
  The key that can be referenced in the output of the `foreach` iteration. The values that are stored from `append` will be stored in this key.
</ParamField>

<ParamField path="foreach.append" type="string" required={true} toc={true}>
  The values to append to the `output_key`.
  Properties from the object can be referenced and added to the `output_key` by using the following syntax: `${this.property_name}`.
  The `this` keyword is used to reference the current object in the array.
</ParamField>

<ParamField path="foreach.max" type="integer" default="10" toc={true}>
  The maximum number of array elements to iterate over, starting at the beginning of the array.
</ParamField>

</Indent>

<ParamField path="webhooks[].output" type="object" toc={true}>
  The result to return when the API call succeeds and no expression returns a result. Each webhook needs `output`,
  `expressions`, or both; a webhook with neither is skipped.
  See [`output`](#output) for details.
</ParamField>

</Indent>


<ParamField path="data_map.output" type="object" toc={true}>
  Similar to a `return` statement in conventional programming languages, the `data_map.output` object immediately
  terminates function execution and returns control to the caller.
</ParamField>

<Indent>

<ParamField path="output.response" type="string" toc={true}>
  The result the agent reads next. When it is absent or not a string, the agent reads `Function completed.` and
  carries on.
</ParamField>

<ParamField path="output.action" type="object | object[]" toc={true}>
  An action, or a list of actions, to run once the agent has spoken its reply.
  See [list of valid actions](#list-of-valid-actions) for details.
</ParamField>

</Indent>

## **Webhook runtime request**

When the AI triggers a function that uses `data_map.webhooks`, SignalWire sends a request to each configured `url`.

### Template variables

The `url` and `params` fields, and the `string` or `expr` of a top-level expression, support `%{variable}` substitution.
Nested properties use dot notation — for example,
`https://api.example.com/weather?city=%{args.location}` substitutes the value the AI extracted for `location`.
For more on [variables](/docs/swml/reference/variables) and scopes, see the [Variables reference](/docs/swml/reference/variables).

<ParamField path="args" type="object" toc={true}>
  Function argument values extracted by the AI, keyed by argument name.
</ParamField>

<Indent>

<ParamField path="args.*" type="any" toc={true}>
  Individual argument value. The key matches an argument name from the function's [`parameters`](/docs/swml/reference/calling/amazon-bedrock/swaig/functions/parameters) schema.
</ParamField>

</Indent>

<ParamField path="session_data" type="object" toc={true}>
  Details of the current session.
</ParamField>

<Indent>

<ParamField path="session_data.uuid" type="string" toc={true}>
  Unique identifier for the current call.
</ParamField>

<ParamField path="session_data.caller_id" type="string" toc={true}>
  The caller's phone number.
</ParamField>

<ParamField path="session_data.global_data" type="object" toc={true}>
  The agent's [`global_data`](/docs/swml/reference/calling/amazon-bedrock#properties).
</ParamField>

<ParamField path="session_data.meta_data" type="object" toc={true}>
  This function's [`meta_data`](/docs/swml/reference/calling/amazon-bedrock/swaig/functions#properties).
</ParamField>

</Indent>

### Request body

When `params` is set, SignalWire sends the `params` object as the JSON request body, as a `POST`.
Template variables in `params` values are expanded before sending.

If no `params` are set and `input_args_as_params` is not `true`, the request is sent without a body.

If [`input_args_as_params`](#properties) is `true`, the function arguments extracted by the AI
are merged into `params`. If no `params` are defined, the arguments become the entire request body.

### Response processing

The JSON response from the webhook is processed through the webhook's `foreach`, `expressions`, and
[`output`](#output) templates. They can reference the response's top-level fields with `%{key}` syntax, the agent's
global data as `%{global_data.key}`, and the [template variables](#template-variables) above under `input`, such as
`%{input.args.location}`.
For example, if the webhook returns `{"temp": 72, "conditions": "sunny"}`, an output of
`"The weather is %{temp}°F with %{conditions}"` will produce `"The weather is 72°F with sunny"`.

A top-level `data_map.output` can reference the template variables above, and the agent's global data as
`%{global_data.key}`.


## **Examples**

### expressions

<CodeBlocks>
<CodeBlock title="YAML">
```yaml
data_map:
  expressions:
    - string: "starwars"
      pattern: "(?i)star\\s*wars"
      output:
        response: "May the Force be with you!"
    - string: "startrek"
      pattern: "(?i)star\\s*trek"
      output:
        response: "Live long and prosper!"
```
</CodeBlock>
<CodeBlock title="JSON">
```json
{
  "data_map": {
    "expressions": [
      {
        "string": "starwars",
        "pattern": "(?i)star\\s*wars",
        "output": {
          "response": "May the Force be with you!"
        }
      },
      {
        "string": "startrek",
        "pattern": "(?i)star\\s*trek",
        "output": {
          "response": "Live long and prosper!"
        }
      }
    ]
  }
}
```
</CodeBlock>
</CodeBlocks>

### webhooks with explicit params

<CodeBlocks>
<CodeBlock title="YAML">
```yaml
data_map:
  webhooks:
    - url: https://api.example.com/weather
      method: POST
      params:
        call_id: "%{session_data.uuid}"
        city: "%{args.location}"
      output:
        response: "The weather in %{city} is %{temp}°F and %{conditions}."
```
</CodeBlock>
<CodeBlock title="JSON">
```json
{
  "data_map": {
    "webhooks": [
      {
        "url": "https://api.example.com/weather",
        "method": "POST",
        "params": {
          "call_id": "%{session_data.uuid}",
          "city": "%{args.location}"
        },
        "output": {
          "response": "The weather in %{city} is %{temp}°F and %{conditions}."
        }
      }
    ]
  }
}
```
</CodeBlock>
</CodeBlocks>

Sends the following request body to `https://api.example.com/weather`:

```json
{
  "call_id": "xxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "city": "New York"
}
```

### webhooks with input_args_as_params

<CodeBlocks>
<CodeBlock title="YAML">
```yaml
data_map:
  webhooks:
    - url: https://api.example.com/weather
      method: POST
      input_args_as_params: true
      output:
        response: "The weather is %{temp}°F and %{conditions}."
```
</CodeBlock>
<CodeBlock title="JSON">
```json
{
  "data_map": {
    "webhooks": [
      {
        "url": "https://api.example.com/weather",
        "method": "POST",
        "input_args_as_params": true,
        "output": {
          "response": "The weather is %{temp}°F and %{conditions}."
        }
      }
    ]
  }
}
```
</CodeBlock>
</CodeBlocks>

Sends the AI-extracted arguments directly as the request body:

```json
{
  "location": "New York"
}
```
