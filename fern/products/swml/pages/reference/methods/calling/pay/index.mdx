Enable secure payment processing during voice calls. 
When implemented in your voice application, it manages the entire payment flow — 
collecting card details (or bank account details, with `payment_method: ach-debit`) from the caller via DTMF, then POSTing them to a `payment_connector_url` you host. 
Your server is responsible for charging the payment method through your payment processor (Stripe, Braintree, etc.) and returning the result to SignalWire.

## **Transaction Types**

The `pay` method supports two primary transaction types: `charges` and `tokenization`.

### Charges

When you need to process a payment right away, use a charge transaction. 
This collects the payment details and processes the transaction in real-time.

<CodeBlocks>
<CodeBlock title="YAML">
```yaml
version: 1.0.0
sections:
  main:
    - pay:
        charge_amount: "25.00"
        payment_connector_url: "https://example.com/process"
```
</CodeBlock>
<CodeBlock title="JSON">
```json
{
  "version": "1.0.0",
  "sections": {
    "main": [
      {
        "pay": {
          "charge_amount": "25.00",
          "payment_connector_url": "https://example.com/process"
        }
      }
    ]
  }
}
```
</CodeBlock>
</CodeBlocks>
Setting any positive value for `charge_amount` initiates a charge transaction.

### Tokenization

Tokenization allows you to securely store payment information for future use. Instead of processing a payment immediately, it generates a secure token that represents the payment method.
To initiate a tokenization transaction, either pass `charge_amount` as `0` or omit the `charge_amount` attribute entirely.

<Note>
The token is provided and stored by your payment processor and can be used for future transactions without requiring customers
to re-enter their payment details. Note that this behavior may vary depending on the payment processor you are using.
</Note>

<CodeBlocks>
<CodeBlock title="YAML">
```yaml
version: 1.0.0
sections:
  main:
    - pay:
        charge_amount: "0"
        payment_connector_url: "https://example.com/process"
```
</CodeBlock>
<CodeBlock title="JSON">
```json
{
  "version": "1.0.0",
  "sections": {
    "main": [
      {
        "pay": {
          "charge_amount": "0",
          "payment_connector_url": "https://example.com/process"
        }
      }
    ]
  }
}
```
</CodeBlock>
</CodeBlocks>

## **Properties**

<Indent>

  The URL to make `POST` requests with all the gathered payment details. Must be an HTTPS URL. This URL processes the final payment transaction and returns the results in the response. See [`payment_connector_url` details](#payment_connector_url) below.
</ParamField>


<ParamField path="pay.charge_amount" type="string" default="0.00" toc={true}>
  The amount to charge against payment method passed in the request. `Float` value with no currency prefix passed as string. When omitted, `0.00` is sent to your payment connector.
</ParamField>


<ParamField path="pay.currency" type="string" default="usd" toc={true}>
  Uses the [ISO 4217 currency code][currency-code] of the charge amount.
</ParamField>


<ParamField path="pay.description" type="string" toc={true}>
  Custom description of the payment provided in the request.
</ParamField>


<ParamField path="pay.input" type="string" default="dtmf" toc={true}>
  The method of how to collect the payment details. Currently only `dtmf` mode is supported.

  While entering a value (card number, expiration date, security code, or postal code), the caller can press `#` to submit the entry immediately instead of waiting for the `timeout`. Pressing `*` cancels the payment, and `pay_result` becomes `caller-interrupted-with-star`.
</ParamField>


<ParamField path="pay.language" type="string" default="en-US" toc={true}>
  Language to use for prompts being played to the caller by the `pay` method. Supported languages are listed in the [Voice and Languages][supported-languages-voice] page.
</ParamField>


<ParamField path="pay.max_attempts" type="integer" default="1" toc={true}>
  Total number of attempts the caller gets to enter each payment detail, such as the card number or expiration date.
  Each detail has its own attempts.
  Values from `1` to `3` take effect; any other value keeps the default `1`, which means the caller gets no retry after a failed entry.
</ParamField>


<ParamField path="pay.min_postal_code_length" type="integer" default="0" toc={true}>
  The minimum length of the postal code the user must enter.
</ParamField>


<ParamField path="pay.parameters" type="object[]" toc={true}>
  Array of parameter objects to pass to your payment processor.
  Enables you to pass custom parameters or include additional payment details not covered by the standard `pay` attributes.
  See the [payment connector request body](#request-body) for how they're sent.
</ParamField>

<Indent>

<ParamField path="parameters[].name" type="string" required={true} toc={true}>
  The identifier for your custom parameter. This will be the key in the `parameters` object.
</ParamField>

<ParamField path="parameters[].value" type="string" required={true} toc={true}>
  The value associated with the parameter. This will be the value in the `parameters` object.
</ParamField>

</Indent>


<ParamField path="pay.payment_method" type="string" default="credit-card" toc={true}>
  The payment method to collect from the caller. Allowed values:

  - `credit-card` - Collect a card number, expiration date, and (by default) security code and postal code.
  - `ach-debit` - Collect a bank routing number and bank account number.

  Whether your payment processor accepts a given method is up to your payment connector.
</ParamField>


<ParamField path="pay.bank_account_type" type="string" default="consumer-checking" toc={true}>
  The bank account type sent to your payment connector. Applies when `payment_method` is `ach-debit`.
  Allowed values: `consumer-checking`, `consumer-savings`, `commercial-checking`.
</ParamField>


<ParamField path="pay.postal_code" type="string" default="true" toc={true}>
  Whether to prompt for the postal code, passed as a string. Applies to card payments.
  Use `"true"` to prompt or `"false"` to skip the prompt.
  Pass a postal code instead, such as `"94107"`, when you already know it: the caller isn't prompted and that value is sent to your payment connector.
</ParamField>


<ParamField path="pay.prompts" type="object[]" toc={true}>
  Array of prompt objects for customizing the audio prompts played during different stages of the payment process.
  If no custom prompts are provided, default prompts will be used.
  If custom prompts are provided but certain payment steps are omitted, the system will fall back to the default prompts for those steps.
</ParamField>

<Indent>

<ParamField path="prompts[].for" type="string" required={true} toc={true}>
  The payment step this prompt is for. Possible values:

  - `payment-card-number` - Collect the payment card number. Default: *"Please enter your credit card number"*
  - `expiration-date` - Collect the expiration date. Default: *"Please enter your credit card's expiration date. 2 digits for the month and 2 digits for the year"*
  - `security-code` - Collect the security code. Default: *"Please enter your credit card's security code. It's the 3 digits located on the back of your card"*
  - `postal-code` - Collect the postal code. Default: *"Please enter your billing postal code"*
  - `bank-routing-number` - Collect the bank routing number. Default: *"Please enter your bank routing number. It's the 9 digits at the bottom left of your check"*
  - `bank-account-number` - Collect the bank account number. Default: *"Please enter your bank account number, then press pound"*
  - `payment-processing` - Played during payment processing. Default: *"Payment processing. Please wait"*
  - `payment-completed` - Played when your payment connector responds with HTTP `200`. Check `pay_result` for the final outcome. Default: *"Payment completed. Thank you"*
  - `payment-failed` - Played when collecting payment details fails, or when your payment connector responds with a status other than `200`. Default: *"Payment failed"*
  - `payment-canceled` - Played when payment is cancelled. Default: *"Payment canceled"*
</ParamField>

<ParamField path="prompts[].actions" type="object[]" toc={true}>

<ParamField path="actions[].phrase" type="string" required={true} toc={true}>

## `payment_connector_url`

SignalWire sends a `POST` request to the `payment_connector_url` once all required payment information has been collected from the caller.
Your endpoint processes the payment and returns the result.

### Request body

<ParamField path="transaction_id" type="string" toc={true}>
  Unique identifier for the transaction.
</ParamField>

<ParamField path="method" type="string" toc={true}>
  The payment method: `credit-card` or `ach-debit`.
</ParamField>

<ParamField path="cardnumber" type="string" toc={true}>
  The full card number collected from the caller. Card payments only.
</ParamField>

<ParamField path="cvv" type="string" toc={true}>
  The full card security code collected from the caller. Card payments only.
</ParamField>

<ParamField path="expiry_month" type="string" toc={true}>
  The card expiry month (e.g., `12`). Card payments only.
</ParamField>

<ParamField path="expiry_year" type="string" toc={true}>
  The card expiry year (e.g., `99`). Card payments only.
</ParamField>

<ParamField path="postal_code" type="string" toc={true}>
  The billing postal code: the one the caller entered, or the postal code you passed in `pay.postal_code`. Card payments only.
</ParamField>

<ParamField path="routing_number" type="string" toc={true}>
  The bank routing number collected from the caller. `ach-debit` payments only.
</ParamField>

<ParamField path="account_number" type="string" toc={true}>
  The full bank account number collected from the caller. `ach-debit` payments only.
</ParamField>

<ParamField path="account_type" type="string" toc={true}>
  The bank account type from `pay.bank_account_type`: `consumer-checking`, `consumer-savings`, or `commercial-checking`. `ach-debit` payments only.
</ParamField>

<ParamField path="chargeAmount" type="string" toc={true}>
  The amount to charge.
</ParamField>

<ParamField path="currency_code" type="string" toc={true}>
  The [ISO 4217](https://en.wikipedia.org/wiki/ISO_4217) currency code.
</ParamField>

<ParamField path="token_type" type="string" toc={true}>
  The token type (`one-time` or `reusable`).
</ParamField>

<ParamField path="description" type="string" toc={true}>
  The payment description provided in the `pay` method.
</ParamField>

<ParamField path="parameters" type="object[]" toc={true}>
  The custom parameters from `pay.parameters`, in the order you listed them.
  Each `name`/`value` entry becomes an object with a single key, so `{"name": "merchant_id", "value": "12345"}` is sent as `{"merchant_id": "12345"}`.
  Names don't have to be unique across entries.
  Present only when at least one parameter is set.
</ParamField>

#### Request example

The card number and security code are redacted in this example for display only.
Your endpoint receives the full card number and security code the caller entered.

```json
{
  "transaction_id": "8c9d14d5-52ae-4e2e-b880-a14e6e1cda7d",
  "method": "credit-card",
  "cardnumber": "************1234",
  "cvv": "***",
  "postal_code": "123456",
  "description": "Payment description",
  "chargeAmount": "10.55",
  "token_type": "reusable",
  "expiry_month": "12",
  "expiry_year": "99",
  "currency_code": "usd",
  "parameters": [
    { "merchant_id": "12345" }
  ]
}
```

### Response format

Your endpoint must respond with JSON.
SignalWire reads only `charge_id`, `error_code`, and `error_message` from the response.

<Tabs>
<Tab title="Successful transaction">

Return a `200` HTTP status code with:

<ParamField path="charge_id" type="string" toc={true}>
  A unique identifier for the successful transaction.
  A non-empty `charge_id` is required for `pay_result` to be `success`, whatever the `charge_amount`, so return one for tokenization as well as charges.
  It's available as `payment_confirmation_code` in `pay_payment_results`.
</ParamField>

<ParamField path="error_code" type="null" toc={true}>
  Must be `null` for successful transactions.
</ParamField>

<ParamField path="error_message" type="null" toc={true}>
  Must be `null` for successful transactions.
</ParamField>

```json
{
  "charge_id": "ch_123456789",
  "error_code": null,
  "error_message": null
}
```

</Tab>
<Tab title="Failed transaction">

Return a non-`200` HTTP status code with:

<ParamField path="charge_id" type="null" toc={true}>
  Must be `null` for failed transactions.
</ParamField>

<ParamField path="error_code" type="string" toc={true}>
  An error code identifying the type of failure.
</ParamField>

<ParamField path="error_message" type="string" toc={true}>
  A human-readable description of the error.
</ParamField>

```json
{
  "charge_id": null,
  "error_code": "insufficient_funds",
  "error_message": "Card has insufficient funds"
}
```

</Tab>
</Tabs>

<Note>
A non-`200` response plays the `payment-failed` prompt.
A `200` response plays the `payment-completed` prompt even when its body carries an error or has no `charge_id`, so check `pay_result` for the final outcome.
</Note>

## **Variables**

When the payment process completes, the following [variables](/docs/swml/reference/variables) are set in the `vars` scope.
Access them in subsequent SWML instructions using the `${variable}` syntax (e.g., `${pay_result}`).

<ParamField path="pay_result" type="string" toc={true}>
  The overall outcome of the payment process. Possible values:

  - `success` - The payment was successful.
  - `too-many-failed-attempts` - The caller exceeded the `max_attempts` limit.
  - `payment-connector-error` - The payment connector returned an error.
  - `caller-interrupted-with-star` - The caller pressed the `*` key to cancel.
  - `relay-pay-stop` - The payment was stopped via the `STOP` command.
  - `caller-hung-up` - The caller hung up before completing payment.
  - `validation-error` - Card details failed validation.
  - `internal-error` - An internal system error occurred.
  - `failed` - The `pay` method couldn't run or returned no payment results. `pay_payment_results` is cleared.
</ParamField>

<ParamField path="pay_payment_results" type="string" toc={true}>
  Detailed payment results, including card or bank account details, the token type, and any error information, stored as a JSON-encoded string.
  The variable holds the JSON text, not an object, so `${pay_payment_results.payment_confirmation_code}`-style dot notation doesn't reach the fields inside it.
  When decoded, the JSON object has the fields below.
</ParamField>

<Indent>

<ParamField path="pay_payment_results.result" type="string" toc={true}>
  The payment outcome. Same values as `pay_result`, except `failed`.
</ParamField>

<ParamField path="pay_payment_results.payment_token" type="string" toc={true}>
  The token type requested in `token_type`: `one-time` or `reusable`.
  This is a label, not a payment credential; any token your payment processor stores is managed by your payment connector.
</ParamField>

<ParamField path="pay_payment_results.payment_confirmation_code" type="string" toc={true}>
  The `charge_id` your payment connector returned for a successful transaction.
</ParamField>

<ParamField path="pay_payment_results.payment_method" type="string" toc={true}>
  The payment method used: `credit-card` or `ach-debit`.
</ParamField>

<ParamField path="pay_payment_results.payment_card_number" type="string" toc={true}>
  Redacted card number (e.g., `************1234`).
</ParamField>

<ParamField path="pay_payment_results.payment_card_type" type="string" toc={true}>
  Type of card used (e.g., `visa`, `mastercard`, `amex`).
</ParamField>

<ParamField path="pay_payment_results.payment_card_expiration_date" type="string" toc={true}>
  Card expiration date (e.g., `1225` for December 2025).
</ParamField>

<ParamField path="pay_payment_results.payment_card_security_code" type="string" toc={true}>
  Redacted security code (e.g., `***`).
</ParamField>

<ParamField path="pay_payment_results.payment_card_postal_code" type="string" toc={true}>
  Postal code entered by the caller.
</ParamField>

<ParamField path="pay_payment_results.bank_routing_number" type="string" toc={true}>
  The bank routing number the caller entered. Included only for `ach-debit` payments.
</ParamField>

<ParamField path="pay_payment_results.bank_account_number" type="string" toc={true}>
  The bank account number the caller entered, masked so that at most the last two digits are visible. Included only for `ach-debit` payments.
</ParamField>

<ParamField path="pay_payment_results.bank_account_type" type="string" toc={true}>
  The bank account type: `consumer-checking`, `consumer-savings`, or `commercial-checking`. Included only for `ach-debit` payments.
</ParamField>

<ParamField path="pay_payment_results.payment_error" type="string" toc={true}>
  Error description if the payment failed. Empty on success.
</ParamField>

<ParamField path="pay_payment_results.payment_error_code" type="string" toc={true}>
  Error code if the payment failed. Empty on success.
</ParamField>

<ParamField path="pay_payment_results.connector_error" type="object" toc={true}>
  Error details from the payment connector.
  The object is always included; its `code` and `message` are filled in only when your connector's response carried an `error_code` or `error_message`.
</ParamField>

<Indent>

<ParamField path="connector_error.code" type="string" toc={true}>

</ParamField>

<ParamField path="connector_error.message" type="string" toc={true}>

</ParamField>

### Handling payment results
