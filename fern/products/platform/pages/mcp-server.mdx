An AI coding assistant that guesses at SignalWire's APIs writes code that fails at runtime. The SignalWire MCP server gives it the real answers instead: it searches these docs, reads any page as Markdown, recommends the right product for a goal, returns verified SWML and cXML starters, and maps error messages to their likely causes and fixes.

The server speaks the [Model Context Protocol (MCP)](https://modelcontextprotocol.io), the open standard AI tools use to connect to outside data. SignalWire hosts it at one URL, and it needs no account, API token, or install:

```text
https://mcp.signalwire.com/mcp
```

<Note>
This page connects SignalWire knowledge to the AI tool you build with. To give your own SignalWire AI agent access to MCP tools during a call, see the [MCP Gateway][mcp-gateway] guide instead.
</Note>

## Add the server to your client

Every client below connects over Streamable HTTP, the MCP transport for hosted servers. Name the server `signalwire` so prompts that mention SignalWire route to it. Cursor and VS Code also have one-click installs in the page actions menu at the top of every docs page.

### Claude Code

Run this in your terminal:

```bash
claude mcp add --transport http signalwire https://mcp.signalwire.com/mcp
```

The server is added for you, in the current project only. Add `--scope user` to make it available in every project, or `--scope project` to share it with your team.

### Cursor

Open the page actions menu at the top of any docs page and choose **Connect to Cursor**, then confirm the install in Cursor.

To add it by hand, put this in `~/.cursor/mcp.json` for every project, or `.cursor/mcp.json` in one project:

```json title="mcp.json"
{
  "mcpServers": {
    "signalwire": {
      "url": "https://mcp.signalwire.com/mcp"
    }
  }
}
```

### VS Code

Open the page actions menu at the top of any docs page and choose **Connect to VS Code**, then confirm the install in VS Code.

To add it by hand, put this in `.vscode/mcp.json` in your workspace:

```json title=".vscode/mcp.json"
{
  "servers": {
    "signalwire": {
      "type": "http",
      "url": "https://mcp.signalwire.com/mcp"
    }
  }
}
```

### Codex

Run this in your terminal:

```bash
codex mcp add signalwire --url https://mcp.signalwire.com/mcp
```

### Other clients

Any client that supports remote MCP servers over Streamable HTTP connects with the server URL alone. Add a remote or custom server in your client's MCP settings and enter `https://mcp.signalwire.com/mcp`, with no authentication.

A client that only launches local servers can reach it through a local bridge such as the open-source `mcp-remote` package, run as `npx mcp-remote https://mcp.signalwire.com/mcp`.

## Check the connection

Ask your assistant to run the SignalWire MCP server's `health` tool. A working connection returns a status of `ok`. In Claude Code, `claude mcp list` also shows the server as connected, and Codex lists it under `codex mcp list`.

If the client reports that it can't connect, check that the URL ends in `/mcp` and that the client is set to the HTTP transport rather than SSE or a local command. Opening the URL in a browser returns an error by design: the server only answers MCP clients.

## How it works

Your assistant decides when to call the server's tools, based on your prompt and each tool's description. You don't call them yourself. Mention SignalWire in your request, or name a tool, and the assistant picks the one that fits:

| Tool | What it does |
|---|---|
| `orient` | Maps SignalWire's developer surfaces (SWML, cXML, the Server SDKs, the REST APIs, the Browser SDK, and Call Flow Builder): what each is, when to use it, and where its docs live. |
| `recommend` | Turns a goal such as "AI receptionist" or "port from Twilio" into the right surface and concrete first steps. |
| `search` | Full-text search across the SignalWire docs. Returns page titles, URLs, and matching excerpts. |
| `reference` | Fetches a docs page's current content as Markdown, by path or URL. |
| `scaffold` | Returns a starter SWML or cXML document for a common build: an IVR menu, an AI voice agent, a hello-world call, or an SMS auto-reply. |
| `troubleshoot` | Maps an error message, HTTP status, or symptom to likely causes and fixes, with links to the docs. |
| `health` | Reports whether the server is up. |

Answers come from the docs themselves. `search` runs over a recent snapshot of the docs, so a newly published page may not appear yet. `reference` fetches the live page, so use it when you need the latest wording. Results from `recommend`, `scaffold`, and `troubleshoot` link to the docs page each answer is based on.

The tools only read public documentation. They don't see your SignalWire Space, your phone numbers, or your logs, and they can't change anything in your account. To work with your account from code, give your assistant the [Server SDKs](/docs/server-sdks) or [REST APIs](/docs/apis) docs and your own credentials.

A few prompts that put the tools to work:

- "Using the SignalWire MCP server, which SignalWire product should I use to build an AI receptionist for my phone number?"
- "Scaffold a SignalWire IVR that asks callers to press 1 for sales or 2 for support."
- "My SignalWire REST request returns 401 Unauthorized. What's wrong?"
