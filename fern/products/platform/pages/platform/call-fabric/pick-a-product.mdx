SignalWire helps you build communications apps of any size,
from an AI voicemail assistant to a [HIPAA-compliant][hipaa] telehealth platform.
A SignalWire app can [make and receive phone calls][make-receive-calls] with an AI agent,
put calls and chat in a web page,
and text your customers.
You compose your app from a handful of products (SWML, the REST APIs, the Browser SDK, and Relay)
and most apps combine more than one.
Calls are where the products differ most, so most of this page is about calls.
[Messaging and fax](#messaging-and-fax) covers texting and faxing.

## How most SignalWire apps are built

Write your AI agents and call flows as SWML with the Agents namespace of the Server SDKs,
and use its REST namespace to send commands to live calls and manage your Resources.

A SWML script is a JSON or YAML document that defines the dialplan:
a set of rules for how the call proceeds and how it responds to the caller.
This can include forwarding the call, recording a voicemail, or running a full IVR system.
The Agents namespace generates the SWML for you,
with easier maintenance and better validation than writing it by hand.
It also serves the SWML and adapts it to each call's context.
SWML has deep AI integrations and webhook support,
so you can let AI handle most of the communication
and keep track of the call while it happens.

1. A phone number or [Address][addresses] points at a [Resource][resources].
   For a call you build in code,
   that Resource is a SWML Script set to an external URL
   that points at the agent running on your server.
2. When a call arrives,
   SignalWire sends your server a POST request with the call context,
   and runs the SWML document your server returns:
   answering, speaking, listening, recording, and running the AI conversation.
3. When the AI needs data or needs to act, such as looking up a booking,
   it calls a tool on your server through SWAIG (the SignalWire AI Gateway).
   The reply can steer the conversation and trigger actions on the call.
4. At any point,
   your backend can send the call a command through the REST APIs:
   inject a message into the conversation, start a recording, play audio, or transfer the call.

For example, this dialplan for Bayview Taxi
asks the caller to press 1 for Ada, the AI dispatcher, or 2 for a person,
then routes the call.
When Ada's conversation ends,
her `post_prompt` asks the AI for a summary,
and SignalWire posts it to the `post_prompt_url` on your server.
The Python code and the SWML it generates are shown below.

<CodeBlocks>

```python title="Python — Agents"
from signalwire import SWMLService

# call IDs of live calls, used by the call command example below
active_calls = {}


class BayviewTaxi(SWMLService):
    def on_request(self, request_data=None, callback_path=None):
        call = (request_data or {}).get("call", {})
        active_calls[call.get("call_id")] = call.get("from")


bayview = BayviewTaxi(name="bayview-taxi", route="/bayview")

bayview.answer()
bayview.prompt(
    play="say:Thanks for calling Bayview Taxi. Press 1 to book with Ada, our AI dispatcher, or 2 to speak with a person.",
    max_digits=1,
)
bayview.switch(
    variable="prompt_value",
    case={
        "1": [{"execute": {"dest": "ada"}}],
        "2": [{"execute": {"dest": "person"}}],
    },
    default=[{"play": {"url": "say:Sorry, I didn't get that. Goodbye."}}, {"hangup": {}}],
)

bayview.add_section("ada")
bayview.add_verb_to_section("ada", "ai", {
    "prompt": {"text": "You are Ada, the dispatcher for Bayview Taxi. Help the caller book a ride."},
    "post_prompt": {"text": "Summarize the call in two sentences, including the pickup address."},
    "post_prompt_url": "https://example.com/call-summary",
})

bayview.add_section("person")
bayview.add_verb_to_section("person", "connect", {"to": "<YOUR_DESTINATION>"})

bayview.serve()
```

```yaml title="YAML"
version: 1.0.0
sections:
  main:
  - answer: {}
  - prompt:
      play: say:Thanks for calling Bayview Taxi. Press 1 to book with Ada, our AI
        dispatcher, or 2 to speak with a person.
      max_digits: 1
  - switch:
      variable: prompt_value
      case:
        '1':
        - execute:
            dest: ada
        '2':
        - execute:
            dest: person
      default:
      - play:
          url: say:Sorry, I didn't get that. Goodbye.
      - hangup: {}
  ada:
  - ai:
      prompt:
        text: You are Ada, the dispatcher for Bayview Taxi. Help the caller book a
          ride.
      post_prompt:
        text: Summarize the call in two sentences, including the pickup address.
      post_prompt_url: https://example.com/call-summary
  person:
  - connect:
      to: <YOUR_DESTINATION>
```

</CodeBlocks>

The Server SDKs protect your server with basic auth.
Set `SWML_BASIC_AUTH_USER` and `SWML_BASIC_AUTH_PASSWORD` environment variables,
and put the same credentials in the SWML Script Resource's URL,
as in `https://user:pass@your-server.com/bayview`.

To steer a live call,
like the one the dialplan above answered,
send it a Calling API command from anywhere, at any time.
The Python code continues the dialplan above
and ends each call in `active_calls` with a message.
The TypeScript and cURL versions end one call:

<CodeBlocks>

```python title="Python — REST client"
from signalwire.rest import RestClient

client = RestClient(project="<YOUR_PROJECT_ID>", token="<YOUR_API_TOKEN>", host="<YOUR_SPACE>.signalwire.com")

for call_id in active_calls:
    client.calling.transfer(
        call_id,
        dest={
            "version": "1.0.0",
            "sections": {
                "main": [
                    {"play": {"url": "say:Sorry, we need to end this call for server maintenance. Please call back in 20 minutes."}},
                    {"hangup": {}},
                ]
            },
        },
    )
```

```typescript title="TypeScript — REST client"
import { RestClient } from '@signalwire/sdk';

const client = new RestClient({
  project: '<YOUR_PROJECT_ID>',
  token: '<YOUR_API_TOKEN>',
  host: '<YOUR_SPACE>.signalwire.com',
});

await client.calling.transfer('<YOUR_CALL_ID>', {
  dest: {
    version: '1.0.0',
    sections: {
      main: [
        { play: { url: 'say:Sorry, we need to end this call for server maintenance. Please call back in 20 minutes.' } },
        { hangup: {} },
      ],
    },
  },
});
```

```bash title="cURL — Calling API"
curl -X POST "https://<YOUR_SPACE>.signalwire.com/api/calling/calls" \
  -u "<YOUR_PROJECT_ID>:<YOUR_API_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "<YOUR_CALL_ID>",
    "command": "calling.transfer",
    "params": {
      "dest": {
        "version": "1.0.0",
        "sections": {
          "main": [
            { "play": { "url": "say:Sorry, we need to end this call for server maintenance. Please call back in 20 minutes." } },
            { "hangup": {} }
          ]
        }
      }
    }
  }'
```

</CodeBlocks>

Replace the placeholders with the values from your [API credentials][api-credentials] page
and `<YOUR_CALL_ID>` with the ID of the call to end.

## The products

| Product | Description | Execution environment | Use cases |
|---|---|---|---|
| SWML | JSON or YAML call flow, generated by the Server SDKs | Your web server, or hosted by SignalWire | Call flows and AI agents (the recommended starting point) |
| REST APIs | HTTP endpoints for resources, messaging, and call commands | Any server or script | Provisioning, outbound calls and messages, and controlling calls in progress |
| Browser SDK | JavaScript client for voice, video, and chat | The user's browser | Calling and chat from a web page |
| Relay | Persistent connection that streams call events to your code | A long-running process you host | Event-driven, step-by-step call control |

### SWML

[SWML][swml] (SignalWire Markup Language) describes how a call should go:
answer, play a greeting, run an AI agent, record, transfer.
With the Agents namespace of the [Server SDKs][server-sdks],
you create an [`AgentBase`][agent-base] in Python or TypeScript,
give it a prompt and tools,
and run it as a web server.

Use it for any call your code handles, with or without AI.
For a fixed flow with no server of your own,
you can paste the document into a SWML Script in your Dashboard,
and SignalWire hosts it.

The call runs on SignalWire,
so your server only answers short HTTP requests:
one for the document and one for each tool call.
Nothing holds a connection open,
so your server stays stateless and deploys anywhere that serves HTTPS.
The [Server SDKs quickstart][sdk-quickstart] builds your first agent.
This one gives Ada a tool that looks up a ride:

```python title="Python — Agents"
from signalwire import AgentBase, FunctionResult

agent = AgentBase(name="ada", route="/agent")
agent.prompt_add_section("Role", body="You are Ada, the dispatcher for Bayview Taxi. Help callers check on their ride.")


def check_ride(args, raw_data):
    ride = rides.lookup(args["booking_id"])
    return FunctionResult(f"The driver arrives in {ride.eta} minutes.")


agent.define_tool(
    name="check_ride",
    description="Look up a ride by its booking ID",
    parameters={
        "type": "object",
        "properties": {"booking_id": {"type": "string", "description": "The booking ID"}},
        "required": ["booking_id"],
    },
    handler=check_ride,
)

agent.run()
```

`rides.lookup` stands in for your booking system.

### REST APIs

The [REST APIs][rest-api] cover everything that isn't the call flow itself.
You buy phone numbers,
create Resources and Subscribers,
issue client tokens,
send messages,
fetch recordings and logs,
and upload documents to Datasphere.
From code, the [REST namespace][rest-client] of the Server SDKs wraps each endpoint in a method.

The Calling API controls live calls.
Its `dial` command starts a new call,
and its [call commands][call-commands] act on a call in progress:
`calling.play`, `calling.record`, `calling.transfer`, `calling.ai_message`, `calling.ai_hold`, `calling.end`,
and more than thirty others.
These are the same commands the Relay namespace sends over its WebSocket,
delivered over HTTP instead.

```python title="Python — REST client"
from signalwire.rest import RestClient

client = RestClient(project="<YOUR_PROJECT_ID>", token="<YOUR_API_TOKEN>", host="<YOUR_SPACE>.signalwire.com")

client.phone_numbers.set_swml_webhook("<YOUR_PHONE_NUMBER_ID>", url="https://example.com/bayview")
client.calling.dial(from_="<YOUR_CALLER_ID>", to="<YOUR_DESTINATION>", url="https://example.com/bayview")
client.calling.ai_message("<YOUR_CALL_ID>", role="system", message_text="Driver Sam has arrived.")
client.messages.create(from_="<YOUR_CALLER_ID>", to="<YOUR_DESTINATION>", body="Your Bayview Taxi driver is outside.")
```

### Browser SDK

The [Browser SDK][browser-sdk] (`@signalwire/js`) puts voice, video, and chat in a web page.
A signed-in user can dial an Address,
such as the one your agent answers,
and [receive calls][browser-inbound] addressed to them.
Your backend creates each user a short-lived [Subscriber token][browser-auth]
with the REST APIs,
since an API token never belongs in a browser.
For a public "call us" button,
the [click-to-call widget][click-to-call] needs no sign-in at all.

The Browser SDK is a participant in the call, not its controller.
When a browser user calls your agent,
the flow they hear still comes from SWML,
and your backend still steers it with REST commands.

```javascript title="JavaScript — Browser SDK"
import { SignalWire, StaticCredentialProvider } from "@signalwire/js";

const client = new SignalWire(
  new StaticCredentialProvider({ token: "<SUBSCRIBER_TOKEN_FROM_YOUR_BACKEND>" })
);

client.ready$.subscribe(async (ready) => {
  if (!ready) return;

  const call = await client.dial("/public/bayview-dispatch", { audio: true });
  call.status$.subscribe((status) => console.log("status:", status));
});
```

### Relay

The [Relay namespace][relay-client] of the Server SDKs holds a persistent WebSocket connection to SignalWire.
Your process subscribes to contexts,
receives each inbound call as it arrives,
and drives it with procedural code:
answer, play, collect digits, bridge.
Your code receives every call event as it happens
and reacts to it directly,
without the webhook layer.

<Accordion title="No-code options: Call Flow Builder and Dashboard AI Agents">

[Call Flow Builder][cfb] lets you draw a dialplan, one node per step.
An [AI Agent Resource][resources-dashboard] configures an agent's prompt, voice, and tools in the Dashboard.
Both produce Resources that you point a phone number at, with no code at all.

</Accordion>

## Messaging and fax

Messaging and fax use the same products as calls.

To send an SMS or MMS,
call the REST APIs' [Create message][create-message] endpoint,
which the REST namespace of the Server SDKs wraps as `messages.create`.
A Relay process can send one with [`send_message`][relay-send-message].
During a call, the SWML [`send_sms`][swml-send-sms] method or the [`send_sms`][fr-send-sms] tool action texts the caller.

To handle inbound texts,
point a phone number at a [Messaging SWML][swml-messaging] document,
or [receive them in a Relay process][relay-receive].
Messaging SWML is a separate flavor of SWML with methods such as `reply`.
The Agents namespace generates calling SWML only,
so you write Messaging SWML as YAML or JSON yourself.

Fax runs on a call.
To send one, place a call with the REST `dial` command and have its SWML run [`send_fax`][swml-send-fax].
To receive faxes, set a phone number to accept incoming calls as fax
and point it at SWML that runs [`receive_fax`][swml-receive-fax].
The Agents namespace generates both methods,
and Relay has `send_fax` and `receive_fax` on its call object.
[First steps with fax][fax] walks through both directions.

## Match your use case to a product

| You're building | Use |
|---|---|
| An AI agent that answers your phone number | Server SDKs (Agents namespace) |
| A phone menu or call forwarding | Server SDKs (Agents namespace) |
| An agent that answers from your documents | Server SDKs (Agents namespace) with the [`datasphere` skill][datasphere-skill] |
| Outbound reminder or survey calls | REST `dial`, running your Server SDKs (Agents namespace) flow |
| Buttons that record, transfer, or hold a live call | [REST call commands][call-commands] |
| Text notifications and confirmations | [REST messages][create-message] |
| Two-way texting or automatic replies | [Messaging SWML][swml-messaging] or Relay |
| Sending or receiving faxes | Server SDKs (Agents namespace) with [`send_fax`][swml-send-fax] and [`receive_fax`][swml-receive-fax] |
| A "call us" button on a web page | [Click-to-call widget][click-to-call] |
| Voice or video calling between your users | [Browser SDK][browser-sdk] |

## The building blocks every product shares

| Building block | What it is | Where you work with it |
|---|---|---|
| [Phone numbers][phone-numbers] | Numbers on your Space that receive and place calls and messages | Buy and assign them in the Dashboard or with [REST][purchase-number]. Each one points at a Resource. |
| [Resources][resources] and [Addresses][addresses] | Anything that handles a call (SWML Script, AI Agent, Subscriber, Video Room, Call Flow), and the paths that reach it, such as `/public/bayview-dispatch` | Create them in the Dashboard or with REST. SWML, the Browser SDK, and Relay all dial Addresses. |
| [Subscribers][subscribers] and tokens | The people who sign in to your app, and the short-lived tokens their browsers use | [Create Subscribers][create-subscriber] and [tokens][subscriber-token] with REST, then use them in the Browser SDK |
| SWAIG tools | Functions on your server that an AI agent calls mid-conversation | Declare them on the agent. Their replies can carry [actions][result-actions] on the call. See [Tool calling][tool-calling]. |
| Datasphere | Document storage with semantic search, for agents that answer from your content | Upload documents with the [REST namespace][py-rest-datasphere], then give the agent the [`datasphere` skill][datasphere-skill] |
| [Webhooks and status callbacks][webhooks] | HTTP requests SignalWire sends your server when a call or message changes state | Set a `status_url` on REST commands, or a callback on a SWML method |
| Recordings | Audio files from recorded calls | Start them from any product, then [list, fetch, and delete][list-recordings] them with REST |

## How the pieces work together

These patterns continue the Bayview Taxi example,
whose AI dispatcher Ada answers the phone.

### Steer a running agent from your backend with REST commands

Every SWAIG request your agent receives carries the call's `call_id`,
so your server can store it with the booking.
When a driver accepts the ride,
your dispatch system sends [`calling.ai_message`][call-commands] to that call through the REST APIs.
Ada receives it as a system instruction the caller doesn't hear,
and tells the caller their driver is on the way.
See the [Python][py-rest-calling] and [TypeScript][ts-rest-calling] REST client references for every command.

### Let a tool act on the call

A tool's [reply][function-result] can carry actions on the call as well as text.
Ada's `book_ride` tool can [text the caller a confirmation][fr-send-sms],
start a recording,
transfer the call to a person,
or [send a message to the agent on another call][fr-rpc-ai-message].
Use tool actions when the conversation decides what happens next,
and REST commands when something outside the conversation does, like a driver accepting.

### Reach the same agent from a phone or a browser

Give the agent's SWML Script Resource two Addresses:
a phone number for callers on the phone network,
and an alias such as `/public/bayview-dispatch` for Browser SDK users.
Both reach the same agent.
The [Mapping numbers guide][mapping-numbers] walks through it.

### Update a browser from inside the call

When the caller is in a browser,
your server can push JSON to the page during the call
with the SWML [`user_event`][swml-user-event] method,
the [`swml_user_event`][fr-user-event] tool action,
or the [`calling.user_event`][call-commands] REST command.
The Browser SDK [receives it on the call object][browser-user-events],
so Ada can put the driver's name and plate on screen while she says them.
