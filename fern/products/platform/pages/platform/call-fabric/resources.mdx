A Resource is whatever answers when someone reaches your Space: an AI Agent that holds a
conversation, a SWML Script that runs call logic, a Subscriber whose devices ring, or a room that
several people join. Every Resource has a type, and the type decides what happens to a call or
message the Resource receives.

Callers never dial a Resource directly. They reach it through an [Address][addresses], such as a
phone number, a SIP URI, or an alias like `/public/support`. Every type is reached and managed the
same way, so you can put a different Resource behind an Address without changing anything on the
caller's side.

## Resource types

Create a Resource by picking its type in the Dashboard's Resource picker. Some types are grouped
under a category, shown in the second column.

| Type | Picker | What it does |
|---|---|---|
| [AI Agent][ai] | **AI Agent** | Holds automated conversations with your callers, using a prompt, voice, and functions you configure in the Dashboard |
| [Call Flow][cfb] | **Call Flow** | Routes calls with logic you build in the visual Call Flow Builder |
| FreeSWITCH Connector | **FreeSWITCH Connector** | Sends traffic from SignalWire to your own FreeSWITCH infrastructure |
| [Relay Application][relay-client] | **Relay Application** | Hands calls and messages to your own server over a real-time WebSocket connection from the Server SDKs |
| [SWML Script][swml] | **Script** | Controls calls and messages with a SWML document in JSON or YAML, stored in your Space or served from your own URL |
| [SIP Credential][sip-credentials] | **SIP** | Gives your SIP phones and softphones a username and password to register with and place calls from |
| [SIP Gateway][sip-gateways] | **SIP** | Connects to an external SIP network so calls can be sent out to it |
| [Subscriber][subscribers] | **Subscriber** | Represents a user of your application, with sign-in credentials and devices that ring when the user is called |
| [Video Room][video] | **Video Room** | Gives participants a shared room to join by video, audio, or both |

## Resources and Addresses

A Resource and its Addresses are separate objects. The Resource holds the logic, and each Address
is one way in. A Resource can carry any number of Addresses, and each Address hands its calls to
one Resource, called its **handler**. A phone number is the one case with two handlers, one for
calls and one for messages.

SignalWire gives every new Resource one [alias][aliases] so it's reachable right away. The alias
name is a URL-safe form of the Resource name, so an AI Agent named `Support Agent` is reachable at
`/private/support-agent`. If that name is already taken in the alias's context, SignalWire adds a
short random suffix. Renaming the Resource later keeps the alias it already has.

You can add more Addresses in either of two places:

- On the Resource itself, from its **Addresses & Phone Numbers** tab.
- On the **Addresses** page in the left sidebar, which lists every Address in your project. You
  create the Address there and assign it to a Resource in the same form.

Phone numbers and SIP Addresses can be moved to a different Resource later, so the number or SIP
URI your callers use stays the same when you change the logic behind it. The
[Addresses guide][addresses] covers each Address type, contexts, and every way to add, move, and
remove an Address.

## Manage Resources

### With the REST API

The generic Resources endpoints work with every Resource type. Use them to
[list Resources][rest-list-resources], [retrieve][rest-get-resource] or
[delete][rest-delete-resource] one by ID, and [list a Resource's Addresses][rest-list-addresses]
when you don't know its type in advance.

To create or update a Resource, use the endpoints for its type. For example, create a SWML Script
with [Create SWML Script][rest-create-swml-script].

### In the Dashboard

The [SignalWire Dashboard](https://my.signalwire.com/resources) lists every Resource in your
project under **My Resources**, where you can create, edit, and delete them.

<Info title="No My Resources page?">
If the left sidebar doesn't show **My Resources**, your Space is on the Legacy Dashboard.
[Contact Support](https://support.signalwire.com/) to move your Space to the current Dashboard.
</Info>

#### Create

<Steps>
<Step title="Open the Resource picker">

Select **My Resources** in the left sidebar, then select <kbd>+ Add</kbd>. You can also start
from a type's own page under **My Resources**, such as **AI Agents** or **Scripts**, or from the
shortcuts on the Dashboard home page.

</Step>
<Step title="Choose a type">

Pick the Resource type. **Script** asks you to choose **SWML Script**, **AI Agent** offers a custom
agent or a Google Dialogflow agent, and **SIP** asks you to choose **SIP Credential** or
**SIP Gateway**.

</Step>
<Step title="Configure it">

Fill in the form for that type and select <kbd>Create</kbd>. The fields depend on the type. The
new Resource's alias appears on its **Addresses & Phone Numbers** tab.

</Step>
</Steps>

#### Give it an Address

A new Resource is reachable at the alias SignalWire creates from its name. To take calls from the
phone network or from SIP systems outside SignalWire, open the Resource, select its **Addresses &
Phone Numbers** tab, select <kbd>+ Add</kbd>, and choose **Assign a Phone Number**, **Assign a SIP
Address**, or **Add an Alias**. You can also start from the **Addresses** page and pick this
Resource there. [Manage Addresses][manage-addresses] walks through each path.

#### Modify or delete

Select a Resource on the **My Resources** page to open it. Its **Configuration** tab holds the
settings for its type, and its **Addresses & Phone Numbers** tab lists every Address that reaches
it. Some types add their own tabs, such as **SIP Endpoints** on a Subscriber.

<llms-ignore>

<Frame caption="The list of Resources in a SignalWire Space">
  ![The list of Resources in a SignalWire Space.](/assets/images/dashboard/resources/resource-list.webp)
</Frame>

</llms-ignore>

<llms-only>

The **My Resources** page lists each Resource's name, type, and last update time. Use its search and **Filter** controls to find a Resource, then select it to open it.

</llms-only>

To delete a Resource, open it, select **Delete**, and confirm. Calls already in progress continue,
and the Resource's aliases are deleted along with it.

A Resource stays in place while it's assigned as a handler: the call or message handler of a phone
number or WhatsApp number, the handler of a SIP Address, or the Resource a SIP Credential sends its
calls to. Deleting it then fails with the message that a resource currently assigned as a call or
message handler can't be deleted. Assign those to another Resource, or remove this Resource from
them, and then delete it.
