A customer opens a chat with your business in WhatsApp and taps the call button. The call arrives at
SignalWire, runs whatever Resource you attached to the number, and records, transcribes, and shows up
in your logs the way the rest of your traffic does.

WhatsApp calling uses the same Meta-verified business number as
[WhatsApp messaging](/docs/platform/messaging/whatsapp), so a number your customers already message
can take their calls too. It handles calls that customers place to your business number from
WhatsApp. SignalWire doesn't place calls to WhatsApp users, so a `whatsapp:` number isn't a valid
destination for the `connect` method or the Calls API.

## Before you start

You need a [WhatsApp business number connected to your Space](/docs/platform/voice/whatsapp/onboarding),
voice [enabled on that number](/docs/platform/voice/whatsapp/enable-voice), and a
[Resource](/docs/platform/resources) to answer the call.

## How a call reaches your code

A WhatsApp number can't answer on its own. You pick the [Resource](/docs/platform/resources) that
should answer, such as an AI Agent, a SWML Script, or a Call Flow, and attach the number to it as the
Resource's calling handler. From then on every call placed to the number runs that Resource: the
agent picks up, the script executes, or the Call Flow starts. Which Resource answers, and what it
does with the call, is entirely yours to decide.

Each call arrives with your business number as `to`, carrying a `whatsapp:` prefix, and the caller's
number as plain E.164 in `from`. An agent built with the [Server SDKs](/docs/server-sdks) reads both
from the request SignalWire sends before the call starts, so one agent can serve your phone number
and your WhatsApp number and adjust to whichever channel the caller used:

<CodeBlocks>
```python title="Python"
from signalwire import AgentBase

agent = AgentBase(name="support", route="/support")
agent.set_prompt_text("You are a customer support agent.")

def configure_for_channel(query_params, body_params, headers, agent):
    call = body_params.get("call", {})
    if call.get("to", "").startswith("whatsapp:"):
        agent.prompt_add_section(
            "Channel",
            body="The caller reached you from WhatsApp. Thank them for calling on WhatsApp. "
            "Hold isn't available on this call, so never offer to place them on hold.",
        )

agent.set_dynamic_config_callback(configure_for_channel)
agent.serve()
```

```typescript title="TypeScript"
import { AgentBase } from '@signalwire/sdk';

const agent = new AgentBase({ name: 'support', route: '/support' });
agent.setPromptText('You are a customer support agent.');

agent.setDynamicConfigCallback((queryParams, bodyParams, headers, agentCopy) => {
  const call = (bodyParams.call ?? {}) as { to?: string };
  if (call.to?.startsWith('whatsapp:')) {
    agentCopy.promptAddSection('Channel', {
      body:
        'The caller reached you from WhatsApp. Thank them for calling on WhatsApp. ' +
        "Hold isn't available on this call, so never offer to place them on hold.",
    });
  }
});

await agent.serve();
```
</CodeBlocks>

The callback runs once per call with the request body and an ephemeral copy of the agent, so the
WhatsApp-specific section applies to that call only. [Receive WhatsApp calls](/docs/platform/voice/whatsapp/receive-calls#read-the-caller-and-business-numbers)
shows the body your server receives.

From there the call behaves like any other. Recording and transcription work, and
[AI Agents](/docs/platform/ai) answer WhatsApp calls the way they answer calls to a phone number.

## What to know before you build

WhatsApp calls are **audio only**. A caller cannot start a video call to your business number, even
when the Resource answering is a Video Room.

They also do not support **hold**. Putting a WhatsApp call on hold does not behave the way it does on
a phone call, so leave hold and hold music out of flows that handle them.
