Find out whether a person, an answering machine, or a fax machine is on a call, and choose what
the call does next. Each approach below starts by calling your own phone and hanging up on your
voicemail, then screens the calls your number receives and tracks each result. The examples
leave a message after the beep, hand a live answer to an AI agent, and send or receive a fax.

## Choose an approach

Detection runs inside the call logic you already use to place and answer calls, so pick the
approach your app uses and follow only its section. The sections don't build on each other.

- [SWML][swml-detect-machine] adds a `detect_machine` instruction to the document that runs the
  call. SignalWire branches on the result during the call and can post each result to your
  webhook. Choose it when you place calls with a REST `dial` request or answer them with a SWML
  Script.
- [WebSocket (Relay)][relay-guide] starts detection from your Relay client once the call is
  answered. Each result arrives as an event in your code, so you don't need a public URL.
- The [REST Calling API][call-commands] starts detection with the `calling.detect` command, by
  call ID, on a call that's already answered, from any process. Choose it when detection is
  decided after the call starts; see
  [Detect on a call already in progress via REST](#detect-on-a-call-already-in-progress-via-rest).

Detection runs in server-side call logic, so a Browser SDK page that needs it asks your backend to
place the call. A Compatibility API app turns on detection with `MachineDetection` when it
[creates a call][compat-create-call], and reads the result in `AnsweredBy`; this guide doesn't
cover that API.

## Prepare for detection

This guide adds detection to calls you already place and answer. If you haven't done that yet,
start with [Make and receive calls][make-and-receive-calls]: it covers credentials, placing a
call, and pointing your number at a SWML server or Relay client.

Have these values ready:

- The Space URL, Project ID, API token, and phone number from
  [Prepare for your first call][prepare-calls].
- A destination phone you can answer *and* send to voicemail. Declining the call is the quickest
  way to reach the greeting.
- To screen the calls your number receives, a number whose calls already reach your SWML server or
  Relay client.

<Warning title="Trial projects only call and receive calls from verified numbers">
A [trial project][trial-mode] only places calls to and receives calls from numbers you've
purchased or verified. [Prepare for your first call][prepare-calls] shows how to verify the phone
you'll test with.
</Warning>

<Warning title="Messages left by artificial voices are regulated">
Prerecorded and synthesized voicemail messages fall under consent, do-not-call, and calling-hour
rules. Read the [TCPA guide][tcpa] before you dial anyone but yourself.
</Warning>

## How detection works

Detection starts when the call is answered. SignalWire listens for the first voice activity,
then classifies what it hears:

- **Human.** A short greeting followed by silence, the way a person says "Hello?" and waits.
- **Machine.** Continuous speech longer than a threshold, or a single utterance with more words
  than a person's greeting usually has. Voicemail greetings and IVR menus both land here.
- **Fax.** A fax tone instead of speech. This takes the `fax` detector, which listens for one
  tone, separately from the `amd` detector that classifies speech.
- **Unknown.** No decision yet. An `UNKNOWN` event means nothing was heard before
  `initial_timeout`, but it doesn't end detection, which keeps listening until it reaches a
  decision or the overall `timeout` expires. Only then is the result `unknown`.

A `HUMAN` result ends detection. A `MACHINE` result ends it too, unless `detect_message_end` is
on. Then detection keeps listening until the greeting ends, either with a beep or with a pause of
`machine_ready_timeout`, and reports `READY`. That is the moment to start a voicemail message.
`READY` also fires whenever the detector hears a beep, even with `detect_message_end` off.

Each outcome surfaces in two forms: a lowercase value in the SWML `detect_result` variable, and an
uppercase event in status callbacks and Relay events.

| `detect_result` | Event | What SignalWire heard | Typical action |
|---|---|---|---|
| `human` | `HUMAN` | A short greeting, then silence | Play your message, start an AI agent, or connect an agent |
| `machine` | `MACHINE` | Speech longer than the voice threshold, or more words than the words threshold | Hang up, or wait for `READY` and leave a message |
| `machine` | `READY` | A beep, or the end of the greeting when `detect_message_end` is on | Play the voicemail message |
| (none) | `NOT_READY` | The greeting started again after `READY` (REST and Relay, with `detect_interruptions`) | Wait for the next `READY` |
| `fax` | `CED` or `CNG` | The fax tone you set in `tone` | Send or receive a fax, or hang up |
| `unknown` | `UNKNOWN` | No decision before `timeout`; the event fires earlier, at `initial_timeout` | Treat as a person, or retry later |
| `detecting` | (none) | `wait: false` is set, so detection is still running in the background | Handle the result at `status_url` |
| `failed` | (none) | Detection couldn't start, such as a misspelled property, `wait: false` without `status_url`, or another detection already running on the call | Log it and choose a default |

Machine events report `detect.type` as `machine`, and fax events report it as `fax`, with the tone
as the event. Every detection ends with a `finished` event. `READY`, `NOT_READY`, and `finished`
appear in callbacks and Relay events but are never assigned to `detect_result`. The
[`detect_machine` reference][swml-detect-machine] lists every field.

REST and Relay also offer a `digit` detector. It reports each key the caller presses, not who
answered, so this guide doesn't cover it.

### Outbound and inbound calls

The detector is the same in both directions. What changes is who it listens to, when it starts,
and which fax tone to expect.

| | Outbound call you place | Inbound call your number receives |
|---|---|---|
| Who is classified | The party that answered | The caller |
| When detection starts | After the destination answers | After you answer, with SWML [`answer`][swml-answer] or Relay `answer()`. `detect_machine` answers the call itself if you haven't |
| Fax tone to detect | `CED`, which the answering fax machine sends (the default `tone`) | `CNG`, which the calling fax machine sends; set `tone: "CNG"` |
| What silence means | The greeting hasn't started; let `initial_timeout` run | A person waiting for your greeting; keep `initial_timeout` and `timeout` short, and treat `unknown` as a person |
| `detect_message_end` | Waits for the greeting and beep before you leave a message | Rarely useful; callers don't play greetings |
| Typical next step | Leave a message, start an AI agent, or send a fax | Receive a fax, turn away automated callers, or greet the person |

## Detect machines via SWML

[`detect_machine`][swml-detect-machine] listens once the call is answered and, by default, holds
the document until it has a result. The next instruction, usually [`switch`][swml-switch], reads
`detect_result` and picks a branch. The document reaches the call the same way any SWML does, so
this section changes only the document.

### Detect who answers a call you place via SWML

Send the document in the REST `dial` request, as in [Place a call via SWML][place-swml]. Only the
`amd` detector runs here; [Send a fax when a fax machine answers](#send-a-fax-when-a-fax-machine-answers)
adds the second one.

<Steps>

<Step title="Place the call with detection" id="place-the-call-with-detection-via-swml">

The [Server SDKs][server-sdks] build each branch of `switch` as its own list of instructions: the
samples build a branch's message with `say()` and pass its `main` section to `switch`.

<CodeBlocks>
<CodeBlock title="Python — REST client">
```python
# Install: python -m pip install signalwire-sdk==3.4.1
# Save as detect_machine.py and run: python detect_machine.py
from signalwire import SWMLBuilder, SWMLService
from signalwire.rest import RestClient

client = RestClient(
    project="<YOUR_PROJECT_ID>",
    token="<YOUR_API_TOKEN>",
    host="<YOUR_SPACE>.signalwire.com",
)

live = (
    SWMLBuilder(SWMLService(name="live-message"))
    .say("Hello! Your Bayview Taxi ride is confirmed for 8 AM tomorrow.")
    .build()["sections"]["main"]
)
hang_up = (
    SWMLBuilder(SWMLService(name="hang-up"))
    .hangup()
    .build()["sections"]["main"]
)

swml = (
    SWMLBuilder(SWMLService(name="detect-machine"))
    .detect_machine(detectors="amd", timeout=30)
    .switch(
        variable="detect_result",
        case={
            "human": live,
            "machine": hang_up,
        },
        default=live,
    )
    .hangup()
    .build()
)

call = client.calling.dial(
    from_="<YOUR_CALLER_ID>",
    to="<YOUR_DESTINATION>",
    swml=swml,
)
print(call["id"])
```
</CodeBlock>
<CodeBlock title="TypeScript — REST client">

The `default` branch catches `unknown` and `failed`, so a quiet person still hears the message.
Prefer [`cond`][swml-cond] when a branch needs a compound condition, such as checking
`detect_machine_beep` as well.

Everything outside `detect_machine` and `switch` places the call exactly as in
[Place a call via SWML][place-swml], which also covers the `dial()` response and the signature
change in newer SDK releases.

</Step>

<Step title="Answer, then send it to voicemail" id="answer-then-send-to-voicemail-via-swml">

Answer the call and say "Hello?". After a short pause you hear the ride confirmation, then the
call ends. Run the sample again and decline the call so it reaches voicemail: the call ends a few
seconds into your greeting and leaves no message.

If it doesn't work, check the symptom:

- **The second run plays the message into your voicemail.** The greeting was classified as
  `human` or `unknown`. A greeting that pauses after "Hi, you've reached…" looks like a person,
  and one that opens with silence longer than `initial_timeout` returns `unknown`.
- **The first run hangs up on you.** You spoke past the voice threshold without pausing.
- **The phone never rings.** The call itself didn't go out; see
  [Place a call via SWML][place-swml].

The [tuning table](#tune-detection-timeouts-thresholds-and-message-end) maps each misclassification
to its setting.

</Step>

### Screen a call to your number via SWML

Turn away automated callers and greet everyone else. Two things differ from a call you place: you
[`answer`][swml-answer] first, and a person who calls you waits for your greeting instead of
speaking. Silence from a person becomes `unknown` once `initial_timeout` expires, so keep that
timeout short and treat `unknown` as a person.

<Steps>

<Step title="Serve the screening document" id="serve-the-screening-document">

Run either server below in place of the one from [Answer a call via SWML][answer-swml]. It serves
the same `/swml` route with the same credentials, so the number's SWML Script doesn't change. For
a hosted SWML Script, paste the YAML or JSON into the script instead.

`answer` runs first, then `detect_machine` listens for up to five seconds before the greeting
plays. In SWML, a caller who stays silent comes back `unknown` only when `timeout` expires, so
`timeout` sets how long a quiet caller waits.

<CodeBlocks>
<CodeBlock title="Python — SWML builder">
```python
# Install: python -m pip install signalwire-sdk==3.4.1
# Save as inbound_screen.py and run: python inbound_screen.py
from signalwire import SWMLBuilder, SWMLService

reject = (
    SWMLBuilder(SWMLService(name="reject"))
    .say("This line doesn't accept automated calls. Goodbye.")
    .hangup()
    .build()["sections"]["main"]
)
greeting = (
    SWMLBuilder(SWMLService(name="greeting"))
    .say("Thanks for calling Bayview Taxi. A dispatcher will be with you shortly.")
    .build()["sections"]["main"]
)

service = SWMLService(
    name="inbound-screen",
    route="/swml",
    port=3000,
    basic_auth=("signalwire", "<YOUR_BASIC_AUTH_PASSWORD>"),
)
(
    SWMLBuilder(service)
    .answer()
    .detect_machine(detectors="amd", initial_timeout=2, timeout=5)
    .switch(
        variable="detect_result",
        case={"machine": reject},
        default=greeting,
    )
    .hangup()
)
service.serve()
```
</CodeBlock>

Each callback is a `calling.call.detect` event. The `params.detect.params.event` field carries the
result. Once a beep is heard, `beep: true` appears on that event and every later machine event;
fax events never carry it. The [webhooks guide][webhooks] covers endpoint setup and local
testing.

```json

  "event_channel": "swml:be38xxxx-8xxx-4xxxx-9fxx-bxxxxxxxxx",
  "timestamp": 1745332535.668522,
  "project_id": "xxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "space_id": "xxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "params": {
    "control_id": "xxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
    "detect": {
      "type": "machine",
      "params": {
        "event": "MACHINE",
        "beep": true
      }
    },
    "call_id": "xxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
    "node_id": "xxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
    "segment_id": "xxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"

```

Callbacks arrive in the order the detector reaches each state, and every run ends with
`finished`:

| Outcome | Callbacks, in order |
|---|---|
| A person answers | `HUMAN`, `finished` |
| A machine answers, `detect_message_end` off | `MACHINE`, `finished`, with `READY` between them if the line is already silent |
| A machine answers, `detect_message_end` on | `MACHINE`, `READY` once the greeting ends, `finished` |
| The detector hears a beep | `MACHINE` if it hasn't been sent yet, then `READY`, then `finished` |
| No decision | `UNKNOWN` at `initial_timeout`, then `finished` when `timeout` expires |
| A fax machine answers | `CED` or `CNG` with `detect.type` `fax`, then `finished` |

If the call hangs up while detection is running, the final `finished` callback isn't sent, so
don't wait for it before you clean up.

By default `detect_machine` waits for a result before the next instruction runs. Set
`wait: false` to keep the document moving while detection runs in the background, and handle
the outcome at `status_url` instead; asynchronous detection requires `status_url`. This document
plays the confirmation right away and reports the result to your webhook:

## Tune detection: timeouts, thresholds, and message end

The defaults suit most residential voicemail. Adjust them when a run misclassifies, and change
one setting at a time so you can see its effect. Every setting below is a `detect_machine`
property in SWML. In REST and Relay, `timeout` is its own argument and the rest go in the
detector's `params`.

| Symptom | Setting | Default | Change |
|---|---|---|---|
| Greeting begins with silence and comes back `unknown` | `initial_timeout` | 4.5 s | Raise it |
| A person who talks for a while is classified `machine` | `machine_voice_threshold` | 1.25 s | Raise it |
| A short, scripted greeting is classified `human` | `machine_words_threshold` | 6 words | Lower it |
| A person's pause after "Hello?" is too short to count as silence | `end_silence_timeout` | 1.0 s | Lower it |
| The voicemail message starts before the beep | `machine_ready_timeout` | Same as `end_silence_timeout` | Raise it |
| Long IVR menus never reach a result | `timeout` | 30 s | Raise it, or hang up on `machine` without waiting for `READY` |
| Detection stops on the first thing it hears | `detect_message_end` | `false` in SWML, `true` in REST and Relay | Set it explicitly |
| The greeting pauses, `READY` fires, then the greeting continues over your message | `detect_interruptions` (REST and Relay only) | `false` | Set it to `true`, and wait for the next `READY` after a `NOT_READY` event |
| Callers to your number wait in silence, then come back `unknown` | `timeout` and `initial_timeout` | 30 s and 4.5 s | Lower both on inbound calls, and greet `unknown` as a person. In SWML, `timeout` sets how long a silent caller waits |

A greeting from a business often runs past the defaults. To give it more room, change the
`detect_machine` instruction in
[Leave a message via SWML](#leave-a-message-via-swml); the highlighted lines are the changes.

### Compare the surfaces

SWML, the REST command, and Relay share one detector but expose it differently.

| Setting | SWML `detect_machine` | REST `calling.detect` | Relay `detect()` |
|---|---|---|---|
| `detect_message_end` default | `false` | `true` | `true` |
| Which detectors run | `detectors`, a comma-separated list of `amd` and `fax` with no spaces (default both) | One `detect.type` per command: `machine`, `fax`, or `digit` | One `detect.type` per `detect()` call; Python also has `detect_answering_machine()` and `detect_fax()` shortcuts |
| When both find something | A fax tone wins, so the result is `fax` | Not applicable | Not applicable |
| Blocking behavior | `wait` (default `true`) pauses the document | Returns immediately; results go to `status_url` | `wait()` resolves on the first result; events continue |
| `control_id` | None | Required, and the only way to stop it | Optional; the action's `stop()` uses it |
| Fax `tone` values | `CED` (default) or `CNG`, in either case | `CED` (default) or `CNG`, in either case | `CED` (default) or `CNG`, in either case |
| `machine_ready_timeout` | Yes | Yes | Yes, through `detect()`; the Python shortcut doesn't take it |
| `detect_interruptions` | No; setting it makes `detect_machine` fail | Yes | Yes |

```typescript
  .receive_fax({ status_url: "<YOUR_STATUS_WEBHOOK_URL>" })
  .document.sections.main;
const greeting = new SwmlBuilder()
  .say("Thanks for calling Bayview Taxi. A dispatcher will be with you shortly.")
  .document.sections.main;

const service = new SWMLService({
  name: "inbound-fax",
  route: "/swml",
  port: 3000,
  basicAuth: ["signalwire", "<YOUR_BASIC_AUTH_PASSWORD>"],
});
service.getBuilder()
  .answer()
  .detect_machine({ detectors: "fax", tone: "CNG", timeout: 5 })
  .switch({
    variable: "detect_result",
    case: { fax: takeFax },
    default: greeting,
  })
  .hangup();

await service.serve();
```

#### Receive a fax via WebSocket (Relay)

Detect the `CNG` tone with the `fax` detector, then call `receive_fax()`. The fax reports its
result in a `calling.call.fax` event whose `fax.type` is `finished`; `fax.params` holds the page
count, `success`, and the stored `document` URL. Run it in place of your handler, as in
[Screen a call to your number via WebSocket (Relay)](#screen-a-call-to-your-number-via-websocket-relay).

<CodeBlocks>
<CodeBlock title="Python — Relay client">
```python
# Install: python -m pip install signalwire-sdk==3.4.1
# Save as inbound_fax_relay.py and run: python inbound_fax_relay.py
from signalwire.relay import RelayClient
from signalwire.relay.event import FaxEvent

GREETING = "Thanks for calling Bayview Taxi. A dispatcher will be with you shortly."

client = RelayClient(
    project="<YOUR_PROJECT_ID>",
    token="<YOUR_API_TOKEN>",
    contexts=["inbound-calling"],
)

def is_fax(event) -> bool:
    detect = event.params.get("detect", {})
    return detect.get("params", {}).get("event") in ("CED", "CNG")

@client.on_call
async def handle_call(call):
    await call.answer()
    action = await call.detect_fax(tone="CNG", timeout=5)
    event = await action.wait()

    async def hang_up(_event=None):
        if call.state != "ended":
            await call.hangup()

    if is_fax(event):
        async def on_fax(fax_event: FaxEvent):
            if fax_event.fax.get("type") != "finished":
                return
            result = fax_event.fax.get("params", {})
            print(f"Received {result.get('pages', 0)} pages: {result.get('document', '')}")
            await hang_up()

        call.on("calling.call.fax", on_fax)
        await call.receive_fax()
    else:
        await call.play(
            [{"type": "tts", "params": {"text": GREETING}}],
            on_completed=hang_up,
        )
    await call.wait_for_ended()

client.run()
```

<CodeBlock title="TypeScript — Relay client">
```typescript
// Install: npm install @signalwire/sdk@2.0.5
// Save as inbound-fax-relay.mts and run: npx tsx inbound-fax-relay.mts
import { RelayClient, RelayEvent, FaxEvent } from "@signalwire/sdk";

const GREETING = "Thanks for calling Bayview Taxi. A dispatcher will be with you shortly.";

const client = new RelayClient({
  project: "<YOUR_PROJECT_ID>",
  token: "<YOUR_API_TOKEN>",
  contexts: ["inbound-calling"],
});

function isFax(event: RelayEvent): boolean {
  const detect = event.params.detect as { params?: { event?: string } } | undefined;
  return ["CED", "CNG"].includes(detect?.params?.event ?? "");
}

client.onCall(async (call) => {
  await call.answer();
  const action = await call.detect({ type: "fax", params: { tone: "CNG" } }, { timeout: 5 });
  const event = await action.wait();

  const hangUp = async () => {
    if (call.state !== "ended") await call.hangup();
  };

  if (isFax(event)) {
    call.on("calling.call.fax", async (faxEvent) => {
      const fax = (faxEvent as FaxEvent).fax as {
        type?: string;
        params?: { pages?: number; document?: string };
      };
      if (fax.type !== "finished") return;
      console.log(`Received ${fax.params?.pages ?? 0} pages: ${fax.params?.document ?? ""}`);
      await hangUp();
    });
    await call.receiveFax();
  } else {
    await call.play([{ type: "tts", text: GREETING }], { onCompleted: hangUp });
  }
  await call.waitForEnded();
});

await client.run();
```
