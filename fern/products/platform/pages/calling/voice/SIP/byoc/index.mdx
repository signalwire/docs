## Overview

Bring Your Own Carrier (BYOC) allows SignalWire users to retain their own carriers for connectivity instead of the vendors that we partner with. This allows you to use any carrier you want while still utilizing the **powerful programmatic control** for SIP from SignalWire!

This might be a good fit for you if:

- You like your current carrier but want to use our APIs to enhance your call flow
- You want international origination from a country we don't yet support
- The number cannot be ported into SignalWire
- You want to keep control of the number rather than port it to SignalWire
- You want to SIP trunk to/from a SIP Server (such as Kamailio)

## Inbound BYOC

To send traffic from your own carrier into SignalWire, you need a SIP host your carrier can
send INVITEs to, and a resource that handles the calls that arrive there.

That host comes from a **SIP Address**, which you create in your Dashboard under **My Resources**,
or over the API. In the API and in some older parts of the Dashboard the same object is called a
**domain application** — a SIP Address and a domain application are the same thing under two names,
and both produce the same inbound host.

### Your inbound SIP host

Give your carrier this host:

```
{space_name}-{identifier}.dapp.signalwire.com
```

For the space `my-space` and the identifier `byo-test`, a carrier sends INVITEs to
`sip:anything@my-space-byo-test.dapp.signalwire.com`. The user portion of the SIP URI is matched
against the address's `user` field, which defaults to `*` and accepts any user.

<Warning>

The `.dapp.` subdomain is what routes inbound calls. It's a different host from
`{space_name}.sip.signalwire.com`, which is where [SIP Credentials](/docs/platform/voice/sip/sip-credentials)
register their devices. Both resolve in DNS, so a carrier pointed at the `.sip.` host reaches
SignalWire and gets rejected rather than failing to connect.

</Warning>

### Create the SIP Address

The `domain` returned when you create a domain application is a label, not a routable host on its
own — append `.dapp.signalwire.com` to get the address your carrier needs.

<EndpointRequestSnippet endpoint="POST /api/relay/rest/domain_applications" />

<EndpointResponseSnippet endpoint="POST /api/relay/rest/domain_applications" />

A `domain` of `your-space-test_id` in that response means your carrier sends SIP to
`your-space-test_id.dapp.signalwire.com`.

To create the same object as a SIP Address on a resource you've already built, use the
[Create a SIP Address](/docs/apis/rest/sip-addresses/create-sip-address) endpoint instead. Its
response carries the full routable `uri`, so nothing needs to be assembled by hand.

<Warning>

Restrict the IP addresses allowed to send traffic to your address. Set `ip_auth_enabled` to `true`
and list your carrier's addresses in `ip_auth`, or anyone who knows the host can send calls to it.

</Warning>

### Troubleshooting inbound calls

A SIP `404 Domain unavailable` response means SignalWire received your INVITE but couldn't match
the host in its request URI to a SIP Address. Check that the host ends in `.dapp.signalwire.com`
rather than `.sip.signalwire.com`, and that the label before it is your space name and identifier
joined by a hyphen.

### Handling Inbound Calls

#### Using SWML

To handle incoming calls with SWML:

1. [Create an SWML Script resource](/docs/swml) holding the instructions to run when a call arrives.
2. Open that resource and go to its **Addresses & Phone Numbers** tab.
3. Select **+ Add**, then **SIP Address**, and create the address.
4. Give your carrier the resulting `.dapp.signalwire.com` host.

##### Example SWML Script

The following is a simple example of an SWML script that answers the call and plays a TTS message:

```yaml
version: 1.0.0
sections:
  main:
    - play:
        url: 'say: Hello, welcome to SignalWire!'
```

#### Using Call-Flow Builder

To handle incoming calls with a Call Flow:

1. Build the flow in the [Call Flow Builder](/docs/call-flow-builder) and save it as a resource.
2. Open that resource and go to its **Addresses & Phone Numbers** tab.
3. Select **+ Add**, then **SIP Address**, and create the address.
4. Give your carrier the resulting `.dapp.signalwire.com` host.

#### Using Relay

To handle incoming calls with a Relay Application:

1. Create a Relay Application resource set to the topic (V4) or context (V3) your code listens on. This example uses `office`.
2. Open that resource and go to its **Addresses & Phone Numbers** tab.
3. Select **+ Add**, then **SIP Address**, and create the address.
4. Give your carrier the resulting `.dapp.signalwire.com` host, then run code listening for calls on the `office` topic.

<Tabs>
<Tab title="Relay V3">

  ##### Relay V3 Example

```javascript
import { Voice } from "@signalwire/realtime-api";

const client = new Voice.Client({
  project: "<project-id>",
  token: "<api-token>",
  contexts: ["office"],
});

client.on("call.received", async (call) => {
  console.log("Got call", call.from, call.to);

  try {
    await call.answer();
    console.log("Inbound call answered");

    await call.playTTS({ text: "Hello! This is a test call." });
  } catch (error) {
    console.error("Error answering inbound call", error);
  }
});
```

In this example we're creating a Client and tying it to the `office` context.
Then, we tell it to listen for `call.received` events, and when a new call comes
in we answer it and say "Hello! This is a test call." to the caller.

</Tab>
<Tab title="Relay V4">

  ##### Relay V4 Example

## Outbound BYOC

If you are using BYOC to do outbound calls from SignalWire, you will need a SIP URL from your carrier that we can use to route calls to the right SIP trunk. Once you have that, you can [create a call using the Calling API](/docs/apis/rest/calls/call-commands) or [Realtime SDK](/docs/server-sdks/reference/python/relay/client/dial) using the SIP URL, SIP username, and SIP password. Let's look at some examples so you can see what we're talking about!

### Outbound Call Examples

#### Using Calling API/SWML

##### Calling API

To create an outbound call using the Calling API with curl, you can use the [Create a Call endpoint](/docs/apis/rest/calls/call-commands) with the following format:

```bash
curl -L 'https://<YOURSPACENAME>.signalwire.com/api/calling/calls' \
-H 'Content-Type: application/json' \
-H 'Accept: application/json' \
-H 'Authorization: Basic Base64-token-here' \
--data-raw '{
  "command": "dial",
  "params": {
    "url": "https://example.com/swml",
    "from": "sip:from-sip@example-112233445566.sip.signalwire.com",
    "to": "sip:from-sip@example-112233445567.sip.signalwire.com",
    "caller_id": "+1234567890",
    "fallback_url": "https://example.com/fallback"
  }
}'
```

In the `params` you can specify a `url` that points to an SWML script, or you can pass a `swml` key with the SWML script directly.

##### SWML

To create an outbound call using SWML, you can use the following format:

```yaml
version: 1.0.0
sections:
  main:
    - connect:
        to: "sip:user@domain.com"
        headers:
          - name: "x-FROM_NUMBER"
            value: "%2B123456789"
```
