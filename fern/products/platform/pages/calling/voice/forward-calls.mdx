Call forwarding sends calls to your SignalWire number on to another phone, so a caller reaches a
person wherever they are. Start by forwarding a call to your number to a second phone, then take a
voicemail when nobody answers, ring several phones, and track each forward as it happens.

## Choose an approach

Each approach forwards calls with its own code and its own kind of Resource on your phone number, so
pick one and follow only its section. All of them dial the destination and connect it to the caller
the same way, so the destinations, timeouts, and caller ID rules on this page apply to each.

- [SWML][swml-intro]: answer calls to your number with a document that SignalWire runs, served from
  your server or hosted in SignalWire. `connect` forwards the call, and the next instructions in the
  document run if nobody answers.
- [WebSocket (Relay)][relay-guide]: answer calls in code that holds a connection to SignalWire, and
  forward them with `call.connect()`. Forwarding events arrive in your code, so no webhook is needed.
- [REST](#forward-a-call-already-in-progress-via-rest): forward a call that's already in progress,
  such as one an AI agent is handling, by call ID from any process.

To forward calls without code, use the [Forward to Phone][cfb-forward] node in Call Flow Builder.

## Prepare for call forwarding

Start with working call setup from [Make and receive calls][make-and-receive-calls]. Have these
values ready:

- Your Space URL, such as `<YOUR_SPACE>.signalwire.com`.
- Your Project ID and an API token with the **Voice** permission.
- A phone number in your Space.
- Two phones you can answer: one to call your number from, and one that receives the forwarded
  call.

<Warning title="Trial projects only call and receive calls from verified numbers">
A [trial project][trial-mode] only places calls to and receives calls from numbers you've purchased
or verified, and can't call internationally. Verify both phones you'll test with, as
[Prepare for your first call][prepare-calls] shows.
</Warning>

Replace these values in the samples you run:

| Value | Replace with |
|---|---|
| `<YOUR_SPACE>` | Your Space's subdomain in `<YOUR_SPACE>.signalwire.com` |
| `<YOUR_PROJECT_ID>` | Your Project ID |
| `<YOUR_API_TOKEN>` | Your API token with the Voice permission, used only in server code |
| `<YOUR_DESTINATION>` | The phone that receives forwarded calls, in E.164 format, such as `+12025550123` |
| `<YOUR_BACKUP_DESTINATION>` | A second phone to ring, in E.164 format, when you ring several phones |
| `<YOUR_CALLER_ID>` | Your SignalWire phone number, or a [verified caller ID][caller-id], in E.164 format, when the forwarded call shows it instead of the caller's number |
| `<YOUR_BASIC_AUTH_PASSWORD>` | A password you choose for the SWML your server serves |
| `<YOUR_PUBLIC_HOST>` | The public hostname of your SWML server or tunnel |
| `<YOUR_STATUS_WEBHOOK_URL>` | An HTTPS endpoint you control that receives forwarding events |
| `<YOUR_CALL_ID>` | The ID of a live call, when you forward it over REST |

## How call forwarding works

A forwarded call is two calls joined together. The caller's call to your number is the first.
SignalWire then places a second call to the destination, and when the destination answers, bridges
the two so the caller and the destination hear each other. The forward ends when either side hangs
up. If the destination doesn't answer, is busy, or declines, the forward fails, and your fallback
runs instead.

Two settings shape every forward:

- **Timeout.** How long the destination rings before the forward fails. A voicemail system that
  answers counts as an answer, so keep the timeout shorter than the time the destination's phone
  takes to send calls to its own voicemail if you want [your own fallback](#take-a-voicemail-when-nobody-answers-via-swml)
  to run instead.
- **Caller ID.** The number the destination's phone shows. Show the caller's number so the person
  answering knows who's calling, or show your SignalWire number so they know the call came through
  your business line.

A destination can be a phone number, a SIP URI such as `sip:ada@example.com`, or a
[Resource Address][addresses] such as `/private/support-rep`. The samples on this page forward to a
phone number.

## Forward calls via SWML

[`connect`][swml-connect] places the call to the destination and bridges it to the caller. The
document waits at `connect` until the forward ends, then sets `connect_result` to `connected` or
`failed` and moves on to the next instruction. That's where a fallback goes.

### Forward a call via SWML

Bayview Taxi forwards calls to its business number to Ada, its dispatcher. This walkthrough forwards
a call to your number to your second phone.

<Steps>

<Step title="Build the forwarding document" id="build-the-forwarding-document">

The document has one instruction: `connect` to the destination, ringing it for up to twenty
seconds. `connect` shows the caller's number by default.

<CodeBlocks>

```python
    route="/swml",

# Serves the document at /swml. Put the credentials in the URL you give

service.serve()
```

### Take a voicemail when nobody answers via SWML

When the forward fails, `connect_result` is `failed`, and the document moves on. Add a
[`switch`][swml-switch] on `connect_result` that plays a message and records one with
[`record`][swml-record]. A forward that connected skips the `failed` branch and hangs up, so the
voicemail never plays after a finished conversation.

In your forwarding server, replace the `connect` line with these:

<CodeBlocks>

```python title="Python — SWML builder"
voicemail = (
    SWMLBuilder(SWMLService(name="voicemail"))
    .say("Sorry, Bayview Taxi can't take your call right now. "
         "Leave your name and pickup address after the beep.")
    .record(beep=True, end_silence_timeout=3, terminators="#", max_length=120)
    .build()["sections"]["main"]
)
(
    SWMLBuilder(service)
    .connect(to="<YOUR_DESTINATION>", timeout=20)
    .switch(variable="connect_result", case={"failed": voicemail})
    .hangup()
)
```

```typescript title="TypeScript — SWML builder"
// Add SwmlBuilder to the import: import { SWMLService, SwmlBuilder } from "@signalwire/sdk";
const voicemail = new SwmlBuilder()
  .say(
    "Sorry, Bayview Taxi can't take your call right now. " +
      "Leave your name and pickup address after the beep.",
  )
  .record({ beep: true, end_silence_timeout: 3, terminators: "#", max_length: 120 })
  .document.sections.main;

service.getBuilder()
  .connect({ to: "<YOUR_DESTINATION>", timeout: 20 })
  .switch({ variable: "connect_result", case: { failed: voicemail } })
  .hangup();
```

```yaml title="YAML"
version: 1.0.0
sections:
  main:
    - connect:
        to: <YOUR_DESTINATION>
        timeout: 20
    - switch:
        variable: connect_result
        case:
          failed:
            - play:
                url: say:Sorry, Bayview Taxi can't take your call right now. Leave your name and pickup address after the beep.
            - record:
                beep: true
                end_silence_timeout: 3
                terminators: '#'
                max_length: 120
    - hangup: {}
```

```json title="JSON"
{
  "version": "1.0.0",
  "sections": {
    "main": [
      {
        "connect": {
          "to": "<YOUR_DESTINATION>",
          "timeout": 20
        }
      },
      {
        "switch": {
          "variable": "connect_result",
          "case": {
            "failed": [
              { "play": { "url": "say:Sorry, Bayview Taxi can't take your call right now. Leave your name and pickup address after the beep." } },
              {
                "record": {
                  "beep": true,
                  "end_silence_timeout": 3,
                  "terminators": "#",
                  "max_length": 120
                }
              }
            ]
          }
        }
      },
      { "hangup": {} }
    ]
  }
}
```

</CodeBlocks>

Call your number and let the second phone ring without answering. After twenty seconds you hear the
message and a beep; leave a message and hang up. The recording appears under **Storage** in your
Space, and the [Recordings API][find-recordings] lists it too. [Record a single message or
voicemail][record-message] covers the recording settings.

`connect_failed_reason` holds the reason a forward failed. To read it in your server instead, send
the forward's events to a webhook, as [Track a forwarded call via SWML](#track-a-forwarded-call-via-swml)
shows.

### Ring several phones via SWML

`connect` can ring more than one destination. Replace `to` with one of these lists, where each entry
takes its own `to` and, optionally, its own `timeout` and `from`:

- `serial` rings each destination in turn, moving to the next when one doesn't answer, is busy, or
  declines.
- `parallel` rings every destination at once. The first to answer gets the call, and SignalWire
  stops ringing the rest.

This forward rings Ada for fifteen seconds, then a backup dispatcher for fifteen more. In your
forwarding server, replace the `connect` line with these:

<CodeBlocks>

```python title="Python — SWML builder"
SWMLBuilder(service).connect(serial=[
    {"to": "<YOUR_DESTINATION>", "timeout": 15},
    {"to": "<YOUR_BACKUP_DESTINATION>", "timeout": 15},
])
```

```typescript title="TypeScript — SWML builder"
service.getBuilder().connect({
  serial: [
    { to: "<YOUR_DESTINATION>", timeout: 15 },
    { to: "<YOUR_BACKUP_DESTINATION>", timeout: 15 },
  ],
});
```

```yaml title="YAML"
version: 1.0.0
sections:
  main:
    - connect:
        serial:
          - to: <YOUR_DESTINATION>
            timeout: 15
          - to: <YOUR_BACKUP_DESTINATION>
            timeout: 15
```

```json title="JSON"
{
  "version": "1.0.0",
  "sections": {
    "main": [
      {
        "connect": {
          "serial": [
            { "to": "<YOUR_DESTINATION>", "timeout": 15 },
            { "to": "<YOUR_BACKUP_DESTINATION>", "timeout": 15 }
          ]
        }
      }
    ]
  }
}
```

</CodeBlocks>

Call your number and let the first phone ring out: the second phone rings next. The forward fails
only when every destination has failed, so a voicemail fallback still works unchanged. To ring
groups of phones in turn, use `serial_parallel`, described in the [`connect` reference][swml-connect].

### Track a forwarded call via SWML

Add `status_url` to `connect` to receive a JSON webhook each time the forward changes state. See the
[webhooks guide][webhooks] for endpoint setup and testing.

| Webhook field | Value |
|---|---|
| `event_type` | `calling.call.connect` |
| `params.call_id` | The caller's call ID |
| `params.connect_state` | `connecting`, then `connected` and `disconnected`, or `failed` |
| `params.failed_reason` | Why the forward failed, when `connect_state` is `failed` |
| `params.peer.call_id` | The forwarded call's ID, when `connect_state` is `connected` |

```json
{
  "event_type": "calling.call.connect",
  "params": {
    "call_id": "2e1e66e5-5d07-413d-9668-55542992eec0",
    "connect_state": "connected",
    "peer": {
      "call_id": "76ac3c36-56da-4a3e-a0d6-b5f8df6da9ad"
    }
  }
}
```

To follow the forwarded call itself as it rings and is answered, add `call_state_url` and list the
states you want in `call_state_events`: `created`, `ringing`, `answered`, and `ended`, which is the
only one sent by default. Each webhook has `event_type` set to `calling.call.state` and the state in
`params.call_state`. When the state is `ended`, `params.end_reason` is one of `hangup`, `busy`,
`no_answer`, `cancel`, `declined`, or `error`, so you can tell an unanswered forward from a busy line.

## Forward calls via WebSocket (Relay)

Answer the call, then call `call.connect()` with the destinations to dial. `connect()` returns as
soon as SignalWire accepts the request, so the program follows the forward through
`calling.call.connect` events: `connecting`, then `connected` while the two phones talk and
`disconnected` when one hangs up, or `failed` if nobody answers.

### Forward a call via WebSocket (Relay)

This walkthrough forwards a call to your number to your second phone, showing the caller's number.

<Steps>

<Step title="Run the forwarding handler" id="run-the-forwarding-handler">

Run either handler below and leave it running while you test. It subscribes to the `forward-calls`
topic. When a call arrives, it answers, plays a ringtone to the caller, and rings your second phone
for up to twenty seconds. When the forward fails or ends, it hangs up.

<CodeBlocks>
<CodeBlock title="Python — Relay client">
```python
# Install: python -m pip install signalwire-sdk==3.4.1
# Save as forward_relay.py and run: python forward_relay.py
from signalwire.relay import ConnectEvent, RelayClient

client = RelayClient(
    project="<YOUR_PROJECT_ID>",
    token="<YOUR_API_TOKEN>",
    contexts=["forward-calls"],
)

@client.on_call
async def handle_call(call):
    caller = call.device.get("params", {}).get("from_number")

    async def on_connect(event: ConnectEvent):
        print(f"Forward: {event.connect_state}")
        # Nobody answered, or one of the phones hung up.
        if event.connect_state in ("failed", "disconnected") and call.state != "ended":
            await call.hangup()

    call.on("calling.call.connect", on_connect)
    await call.answer()
    await call.connect(
        devices=[[{
            "type": "phone",
            "params": {
                "to_number": "<YOUR_DESTINATION>",
                "from_number": caller,
                "timeout": 20,
            },
        }]],
        ringback=[{"type": "ringtone", "params": {"name": "us"}}],
    )
    await call.wait_for_ended()

client.run()
```
</CodeBlock>
<CodeBlock title="TypeScript — Relay client">
```typescript
// Install: npm install @signalwire/sdk@2.0.5
// This sample also runs as JavaScript: save as forward-relay.mjs,
// then run: node forward-relay.mjs
import { RelayClient } from "@signalwire/sdk";

const client = new RelayClient({
  project: "<YOUR_PROJECT_ID>",
  token: "<YOUR_API_TOKEN>",
  contexts: ["forward-calls"],
});

client.onCall(async (call) => {
  const caller = call.device.params?.from_number;

  call.on("calling.call.connect", async (event) => {
    const state = event.params.connect_state;
    console.log(`Forward: ${state}`);
    // Nobody answered, or one of the phones hung up.
    if ((state === "failed" || state === "disconnected") && call.state !== "ended") {
      await call.hangup();
    }
  });
  await call.answer();
  await call.connect(
    [[{
      type: "phone",
      params: {
        to_number: "<YOUR_DESTINATION>",
        from_number: caller,
        timeout: 20,
      },
    }]],
    { ringback: [{ type: "ringtone", name: "us" }] },
  );
  await call.waitForEnded();
});

await client.run();
```
</CodeBlock>
</CodeBlocks>

`from_number` sets the caller ID the second phone shows. The handler passes the caller's number,
read from the incoming call; to show your SignalWire number instead, set it to `<YOUR_CALLER_ID>`.
The [Server SDKs][server-sdks] document every `connect()` option.

</Step>

3. Select **Create**.

### Take a voicemail when nobody answers via WebSocket (Relay)

On `failed`, play a message and record one instead of hanging up. In the
[forwarding handler](#forward-a-call-via-websocket-relay), replace the `on_connect` listener with
this one:

<CodeBlocks>

```python title="Python — Relay client"
async def on_connect(event: ConnectEvent):
    print(f"Forward: {event.connect_state}")
    if call.state == "ended":
        return
    if event.connect_state == "failed":
        prompt = await call.play([{
            "type": "tts",
            "params": {"text": "Sorry, Bayview Taxi can't take your call right now. "
                               "Leave your name and pickup address after the beep."},
        }])
        await prompt.wait()
        recording = await call.record(
            audio={"beep": True, "end_silence_timeout": 3, "terminators": "#", "max_length": 120}
        )
        result = await recording.wait(timeout=180)
        print(f"Voicemail: {result.params.get('url')}")
        if call.state != "ended":
            await call.hangup()
    elif event.connect_state == "disconnected":
        await call.hangup()
```

```typescript title="TypeScript — Relay client"
call.on("calling.call.connect", async (event) => {
  const state = event.params.connect_state;
  console.log(`Forward: ${state}`);
  if (call.state === "ended") return;
  if (state === "failed") {
    const prompt = await call.play([{
      type: "tts",
      text: "Sorry, Bayview Taxi can't take your call right now. " +
        "Leave your name and pickup address after the beep.",
    }]);
    await prompt.wait();
    const recording = await call.record({
      beep: true, end_silence_timeout: 3, terminators: "#", max_length: 120,
    });
    const result = await recording.wait();
    console.log(`Voicemail: ${result.params.url}`);
    if (call.state !== "ended") await call.hangup();
  } else if (state === "disconnected") {
    await call.hangup();
  }
});
```

</CodeBlocks>

Call your number and let the second phone ring without answering. After twenty seconds you hear the
message and a beep; leave a message and hang up. The handler prints the recording's URL, and the
recording appears under **Storage** in your Space. [Record a single message or
voicemail][record-message] covers the recording settings.

### Ring several phones via WebSocket (Relay)

`devices` is a list of groups. SignalWire dials the groups in turn, moving to the next when nobody in
the current group answers, and rings every device in a group at once. In the
[forwarding handler](#forward-a-call-via-websocket-relay), replace the `connect` call with this one to
ring Ada, then a backup dispatcher:

<CodeBlocks>

```python title="Python — Relay client"
def phone(number):
    return {
        "type": "phone",
        "params": {"to_number": number, "from_number": caller, "timeout": 15},
    }

await call.connect(
    devices=[
        [phone("<YOUR_DESTINATION>")],
        [phone("<YOUR_BACKUP_DESTINATION>")],
    ],
    ringback=[{"type": "ringtone", "params": {"name": "us"}}],
)
```

```typescript title="TypeScript — Relay client"
const phone = (number: string) => ({
  type: "phone",
  params: { to_number: number, from_number: caller, timeout: 15 },
});

await call.connect(
  [
    [phone("<YOUR_DESTINATION>")],
    [phone("<YOUR_BACKUP_DESTINATION>")],
  ],
  { ringback: [{ type: "ringtone", name: "us" }] },
);
```

</CodeBlocks>

To ring both phones at once instead, put them in one group:
`[[phone("<YOUR_DESTINATION>"), phone("<YOUR_BACKUP_DESTINATION>")]]`. The first to answer gets the
call. `failed` arrives only when every group has failed, so a voicemail listener still works
unchanged.

### Track a forwarded call via WebSocket (Relay)

Forwarding events arrive in your code over the same connection, as `calling.call.connect`:

| Field | What it holds |
|---|---|
| `connect_state` | `connecting`, then `connected` and `disconnected`, or `failed` |
| `peer` | The forwarded call, with its `call_id`, when `connect_state` is `connected` |

The handlers above read `connect_state`. To log the forwarded call's ID, read `event.peer` on
`connected`. To send the same events to a webhook as well, pass `status_url` to `connect()`, as
`statusUrl` in TypeScript.

## Forward a call already in progress via REST

When a process that doesn't hold the call needs to forward it, such as a dashboard where a
dispatcher reroutes a caller, send the `calling.transfer` command with the call's ID and a SWML
document that uses `connect`. Whatever the call is doing stops, and the document takes over: the
destination rings, and when it answers, the caller is connected to it. The call ID is the `id` from
a `dial` response, or the `call_id` that SignalWire sends your SWML server or status webhook.

The [Server SDKs][server-sdks] wrap the command:

<CodeBlocks>
<CodeBlock title="Python — REST client">
```python
# Install: python -m pip install signalwire-sdk==3.4.1
# Save as forward_rest.py and run: python forward_rest.py
from signalwire import SWMLBuilder, SWMLService
from signalwire.rest import RestClient

client = RestClient(
    project="<YOUR_PROJECT_ID>",
    token="<YOUR_API_TOKEN>",
    host="<YOUR_SPACE>.signalwire.com",
)

swml = (
    SWMLBuilder(SWMLService(name="forward-in-progress"))
    .connect(to="<YOUR_DESTINATION>", timeout=20)
    .build()
)
client.calling.transfer("<YOUR_CALL_ID>", dest=swml)
print("Forwarding")
```
</CodeBlock>
<CodeBlock title="TypeScript — REST client">
```typescript
// Install: npm install @signalwire/sdk@2.0.5
// This sample also runs as JavaScript: save as forward-rest.mjs,
// then run: node forward-rest.mjs
import { RestClient, SwmlBuilder } from "@signalwire/sdk";

const client = new RestClient({
  project: "<YOUR_PROJECT_ID>",
  token: "<YOUR_API_TOKEN>",
  host: "<YOUR_SPACE>.signalwire.com",
});

const swml = new SwmlBuilder()
  .connect({ to: "<YOUR_DESTINATION>", timeout: 20 })
  .build();
await client.calling.transfer("<YOUR_CALL_ID>", { dest: swml });
console.log("Forwarding");
```
</CodeBlock>
<CodeBlock title="cURL — Calling API">
```bash
curl -X POST "https://<YOUR_SPACE>.signalwire.com/api/calling/calls" \
  -u "<YOUR_PROJECT_ID>:<YOUR_API_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "command": "calling.transfer",
    "id": "<YOUR_CALL_ID>",
    "params": {
      "dest": {
        "version": "1.0.0",
        "sections": {
          "main": [
            { "connect": { "to": "<YOUR_DESTINATION>", "timeout": 20 } }
          ]
        }
      }
    }
  }'
```
</CodeBlock>
</CodeBlocks>

The cURL example calls [Call commands][call-commands]. The command returns as soon as SignalWire
accepts it, and the call keeps the same ID. `dest` also takes the URL of a SWML document your server
serves. Any of the `connect` settings above, such as a voicemail fallback or several phones, work in
the transferred document too.
