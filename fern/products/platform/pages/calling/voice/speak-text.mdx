Text-to-speech (TTS) turns text into speech on a live call, so your app can read out a
confirmation, a menu, or an update the moment it has the words. Start by calling your own phone
and hearing a message in the voice you pick, then speak a menu and collect a key press, and stop
or track speech while it plays.

## How text-to-speech works on a call

You send SignalWire the text and a voice. SignalWire synthesizes the speech with that voice's
engine and plays it into the call, where the people on the call hear it.

A voice is a string in the form `engine.voice:model`, such as `elevenlabs.rachel` or
`gcloud.en-US-Neural2-A`. The engine is the TTS provider that synthesizes the speech, such as
ElevenLabs, Google Cloud, or Amazon Polly. To learn about each provider SignalWire offers, audition
its voices, and compare providers by language and SSML support, see
[TTS providers, voices, and languages][tts-voices]. [Voice identifier strings][tts-voice-strings]
explains the format.

<Warning title="Always name the voice and its engine">
Default voices and engines can change. A voice string without an engine resolves against the
current default engine, and a call that sets no voice uses the current default voice. Set a full
`engine.voice` string in every request so the call keeps sounding the same.
</Warning>

The approaches name the same settings differently:

| Setting | SWML | WebSocket (Relay) and REST |
|---|---|---|
| Text to speak | A `say:` URL, such as `say:Hello`, in `play` or `prompt` | `text` in a `tts` media item |
| Voice | `say_voice` | `voice` |
| Language | `say_language` | `language` |
| Gender | `say_gender` | `gender` |

Google Cloud and Amazon Polly voices also accept SSML (Speech Synthesis Markup Language) as text
wrapped in `<speak>` tags. An AI agent picks its voice in its [`languages`][swml-ai-languages]
settings instead; see [Voice and language][sdk-voice-language] in the Server SDKs.

## Choose an approach

Each approach is a separate way to put speech on a call, so follow the section for the one your
app uses:

- [SWML](#speak-text-on-a-call-via-swml) is a document of call instructions that SignalWire runs.
  Add `say:` text to `play` or `prompt` when you know the words before the call starts, or when
  you already answer calls with SWML.
- [WebSocket (Relay)](#speak-text-on-a-call-via-websocket-relay) is a Relay client in the
  [Server SDKs][server-sdks]. Your code speaks on a live call as it progresses, waits for the
  speech to finish, and reads the caller's input. It needs no public URL.
- [REST](#speak-text-on-a-call-already-in-progress-via-rest) sends a `calling.play` command by
  call ID from any process, such as a backend job that announces an update. Playback progress
  arrives at a webhook.

The Browser SDK has no method that speaks text; [Migrate from v3][browser-migrate] lists playback
as not implemented and points to SWML. A call placed from a browser hears speech from the SWML,
Relay, or REST commands applied to it. In Call Flow Builder, use the **Play Audio or TTS** node.

## Prepare to speak text on a call

Start with working call setup from [Make and receive calls][make-and-receive-calls]. Test with a
phone you can answer.

<Warning title="Trial projects only call and receive calls from verified numbers">
A [trial project][trial-mode] only places calls to and receives calls from numbers you've
purchased or verified. [Prepare for your first call][prepare-calls] shows how to verify the phone
you'll test with.
</Warning>

<Warning title="Calls that use an artificial voice are regulated">
Synthesized speech on a call counts as an artificial voice under consent, do-not-call, and
calling-hour rules. Read the [TCPA guide][tcpa] before you dial anyone but yourself.
</Warning>

Replace these values in the samples you run:

| Value | Replace with |
|---|---|
| `<YOUR_SPACE>` | Your Space's subdomain in `<YOUR_SPACE>.signalwire.com` |
| `<YOUR_PROJECT_ID>` | Your Project ID |
| `<YOUR_API_TOKEN>` | Your API token, used only in server code |
| `<YOUR_CALLER_ID>` | Your SignalWire phone number, or a [verified caller ID][caller-id], in E.164 format |
| `<YOUR_DESTINATION>` | The phone number you'll call, in E.164 format |
| `<YOUR_CALL_ID>` | The ID of an answered call, for the REST commands |
| `<YOUR_STATUS_WEBHOOK_URL>` | An HTTPS endpoint you control that receives playback progress |

## Speak text on a call via SWML

[`play`][swml-play] speaks any URL that starts with `say:`. Set `say_voice` on the same `play` to
choose the voice. The SDK's SWML builder has a `say()` method that writes this `play` for you.

### Speak a message via SWML

This program places a call as in [Place a call via SWML][place-swml]. When you answer, SignalWire
speaks a ride confirmation in the ElevenLabs Rachel voice, then hangs up.

<CodeBlocks>
<CodeBlock title="Python — REST client">
```python
# Install: python -m pip install signalwire-sdk==3.4.1
# Save as speak_message.py and run: python speak_message.py
from signalwire import SWMLBuilder, SWMLService
from signalwire.rest import RestClient

client = RestClient(
    project="<YOUR_PROJECT_ID>",
    token="<YOUR_API_TOKEN>",
    host="<YOUR_SPACE>.signalwire.com",
)

swml = (
    SWMLBuilder(SWMLService(name="speak-message"))
    .say(
        "Hello from Bayview Taxi. Your ride is confirmed for 8 AM tomorrow.",
        voice="elevenlabs.rachel",
    )
    .hangup()
    .build()
)

call = client.calling.dial(
    from_="<YOUR_CALLER_ID>",
    to="<YOUR_DESTINATION>",
    swml=swml,
)
print(call["id"])
```
</CodeBlock>

### Speak a menu and collect input via SWML

[`prompt`][swml-prompt] speaks its `play` text, then waits for key presses or speech. It stores
the input in `prompt_value` and the outcome in `prompt_result`; [`switch`][swml-switch] branches
on either.

This document sets the voice once with [`set`][swml-set]. Every `play` and `prompt` after it reads
`say_voice` from the document, so the menu and each reply share one voice without repeating it.

<CodeBlocks>
<CodeBlock title="Python — REST client">
```python
# Install: python -m pip install signalwire-sdk==3.4.1
# Save as ride_menu.py and run: python ride_menu.py
from signalwire import SWMLBuilder, SWMLService
from signalwire.rest import RestClient

client = RestClient(
    project="<YOUR_PROJECT_ID>",
    token="<YOUR_API_TOKEN>",
    host="<YOUR_SPACE>.signalwire.com",
)

confirmed = (
    SWMLBuilder(SWMLService(name="ride-confirmed"))
    .say("Your ride is confirmed. See you at 8 AM.")
    .build()["sections"]["main"]
)
canceled = (
    SWMLBuilder(SWMLService(name="ride-canceled"))
    .say("Your ride is canceled.")
    .build()["sections"]["main"]
)
no_choice = (
    SWMLBuilder(SWMLService(name="no-choice"))
    .say("We didn't get a choice, so your ride is still booked.")
    .build()["sections"]["main"]
)

swml = (
    SWMLBuilder(SWMLService(name="ride-menu"))
    .set(say_voice="elevenlabs.rachel")
    .prompt(
        play=["say:This is Bayview Taxi. Press 1 to confirm your 8 AM ride, or 2 to cancel it."],
        max_digits=1,
    )
    .switch(
        variable="prompt_value",
        case={
            "1": confirmed,
            "2": canceled,
        },
        default=no_choice,
    )
    .hangup()
    .build()
)

call = client.calling.dial(
    from_="<YOUR_CALLER_ID>",
    to="<YOUR_DESTINATION>",
    swml=swml,
)
print(call["id"])
```
</CodeBlock>

spoken answers as well as key presses, add the speech settings, such as `speech_hints`, from the
[`prompt` reference][swml-prompt].

## Speak text on a call via WebSocket (Relay)

A Relay client speaks with `play()` and a list of media items. A `tts` item carries the `text`
and, optionally, `voice`, `language`, and `gender`. `play()` returns an action once SignalWire
accepts the command: wait on it, or pass a completion callback, to act when the speech ends. Call
setup follows [Place a call via WebSocket (Relay)][place-relay]; for calls to your number, see
[Answer a call via WebSocket (Relay)][answer-relay].

### Speak a message via WebSocket (Relay)

This program dials your phone, speaks the ride confirmation once you answer, and hangs up when
the speech finishes.

<CodeBlocks>
<CodeBlock title="Python — Relay client">
```python
# Install: python -m pip install signalwire-sdk==3.4.1
# Save as speak_message_relay.py and run: python speak_message_relay.py
import asyncio
from signalwire.relay import RelayClient

client = RelayClient(
    project="<YOUR_PROJECT_ID>",
    token="<YOUR_API_TOKEN>",
    contexts=["default"],
)

async def main():
    async with client:
        call = await client.dial(
            devices=[[{
                "type": "phone",
                "params": {
                    "from_number": "<YOUR_CALLER_ID>",
                    "to_number": "<YOUR_DESTINATION>",
                    "timeout": 30,
                },
            }]],
        )

        async def hang_up_after_playback(_event):
            if call.state != "ended":
                await call.hangup()

        await call.play([{
            "type": "tts",
            "params": {
                "text": "Hello from Bayview Taxi. Your ride is confirmed for 8 AM tomorrow.",
                "voice": "elevenlabs.rachel",
            },
        }], on_completed=hang_up_after_playback)
        await call.wait_for_ended()

asyncio.run(main())
```
</CodeBlock>
<CodeBlock title="TypeScript — Relay client">
```typescript

}
```

Run the program and answer your phone. You hear the confirmation in the Rachel voice, then the
call ends. If the voice isn't the one you set, check the string against the
[voice catalog][tts-voices].

The TypeScript client also accepts the nested `{ type: "tts", params: { text } }` form the Python
sample uses. Pass several media items to `play()` to speak them in order; `audio`, `silence`, and
`ringtone` items mix with `tts` items in one list.

### Speak a menu and collect input via WebSocket (Relay)

`play_and_collect()` in Python, or `playAndCollect()` in TypeScript, speaks the media and collects
input in one operation, with one `control_id` for both. Its action resolves
with the collect result: `result.type` is `digit`, `speech`, `no_input`, or `no_match`, and a
`digit` result carries the key presses in `result.params.digits`.

<CodeBlocks>
<CodeBlock title="Python — Relay client">
```python
# Install: python -m pip install signalwire-sdk==3.4.1
# Save as ride_menu_relay.py and run: python ride_menu_relay.py
import asyncio
from signalwire.relay import RelayClient

VOICE = "elevenlabs.rachel"

client = RelayClient(
    project="<YOUR_PROJECT_ID>",
    token="<YOUR_API_TOKEN>",
    contexts=["default"],
)

def tts(text: str) -> dict:
    return {"type": "tts", "params": {"text": text, "voice": VOICE}}

async def main():
    async with client:
        call = await client.dial(
            devices=[[{
                "type": "phone",
                "params": {
                    "from_number": "<YOUR_CALLER_ID>",
                    "to_number": "<YOUR_DESTINATION>",
                    "timeout": 30,
                },
            }]],
        )
        menu = await call.play_and_collect(
            [tts("This is Bayview Taxi. Press 1 to confirm your 8 AM ride, or 2 to cancel it.")],
            {"digits": {"max": 1, "digit_timeout": 5}},
        )
        event = await menu.wait()
        if call.state == "ended":
            return

        result = event.params.get("result", {})
        digits = result.get("params", {}).get("digits", "")
        if digits == "1":
            reply = "Your ride is confirmed. See you at 8 AM."
        elif digits == "2":
            reply = "Your ride is canceled."
        else:
            reply = "We didn't get a choice, so your ride is still booked."

        async def hang_up_after_playback(_event):
            if call.state != "ended":
                await call.hangup()

        await call.play([tts(reply)], on_completed=hang_up_after_playback)
        await call.wait_for_ended()

asyncio.run(main())
```
</CodeBlock>
<CodeBlock title="TypeScript — Relay client">
```typescript

  }]]);
  const menu = await call.playAndCollect(
    [tts("This is Bayview Taxi. Press 1 to confirm your 8 AM ride, or 2 to cancel it.")],
    { digits: { max: 1, digit_timeout: 5 } },
  );
  const event = await menu.wait();

  if (call.state !== "ended") {

    const digits = result?.params?.digits ?? "";

```

`no_input` and the program keeps the booking. To accept speech, add a `speech` object beside
`digits` in the collect settings; a `speech` result carries the words in `result.params.text`.

### Stop, pause, or resume speech via WebSocket (Relay)

The action that `play()` returns controls the speech while it plays: `stop()` ends it, `pause()`
and `resume()` hold and continue it, and `volume()` changes its level in decibels, from -40
to 40.

This program repeats a hold message with `loop` set to `0`, which plays the list until you stop
it. After a stand-in for your own lookup, it stops the hold message and speaks the result.

<CodeBlocks>
<CodeBlock title="Python — Relay client">
```python
# Install: python -m pip install signalwire-sdk==3.4.1
# Save as hold_message_relay.py and run: python hold_message_relay.py
import asyncio
from signalwire.relay import RelayClient

VOICE = "elevenlabs.rachel"

client = RelayClient(
    project="<YOUR_PROJECT_ID>",
    token="<YOUR_API_TOKEN>",
    contexts=["default"],
)

def tts(text: str) -> dict:
    return {"type": "tts", "params": {"text": text, "voice": VOICE}}

async def main():
    async with client:
        call = await client.dial(
            devices=[[{
                "type": "phone",
                "params": {
                    "from_number": "<YOUR_CALLER_ID>",
                    "to_number": "<YOUR_DESTINATION>",
                    "timeout": 30,
                },
            }]],
        )
        hold = await call.play(
            [tts("Please hold while Bayview Taxi finds your driver."), {"type": "silence", "params": {"duration": 2}}],
            loop=0,
        )
        await asyncio.sleep(15)  # Stand-in for your dispatch lookup
        await hold.stop()

        async def hang_up_after_playback(_event):
            if call.state != "ended":
                await call.hangup()

        await call.play(
            [tts("Your driver is five minutes away. Goodbye.")],
            on_completed=hang_up_after_playback,
        )
        await call.wait_for_ended()

asyncio.run(main())
```

```typescript
    { loop: 0 },
  );
  await new Promise((resolve) => setTimeout(resolve, 15_000)); // Stand-in for your dispatch lookup
  await hold.stop();

  await call.play([tts("Your driver is five minutes away. Goodbye.")], {
    onCompleted: async () => {
      if (call.state !== "ended") await call.hangup();
    },
  });
  await call.waitForEnded();
} finally {
  await client.disconnect();
}
```
</CodeBlock>
</CodeBlocks>

Answer and listen: the hold message repeats for about 15 seconds, then the driver update plays
and the call ends. To follow playback without holding an action, register a handler for
`calling.call.play` events; each one reports the play's `control_id` and a `state` of `playing`,
`paused`, `finished`, or `error`.

## Speak text on a call already in progress via REST

When another process controls the call, send [`calling.play`][call-commands] with the answered
call's ID. The `play` list takes the same media items as Relay, with each item's settings in
`params`, and `control_id` names the operation so later commands can address it. Set
`status_url` to follow playback.

<CodeBlocks>
<CodeBlock title="Python — REST client">
```python

    token="<YOUR_API_TOKEN>",
    host="<YOUR_SPACE>.signalwire.com",

client.calling.play(
    "<YOUR_CALL_ID>",
    control_id="driver-update",
    play=[{
        "type": "tts",
        "params": {
            "text": "Your Bayview Taxi driver is five minutes away.",
            "voice": "elevenlabs.rachel",
        },
    }],
    status_url="<YOUR_STATUS_WEBHOOK_URL>",
)
```

The command returns as soon as SignalWire accepts it. Your webhook then receives the play's
`control_id` and its `state`: `playing` when speech starts, then `finished`, or `error` if
playback failed. See the [webhooks guide][webhooks] to set up and test the endpoint.

`direction` chooses who hears the speech:
`listen`, the default, plays it only to the caller; `speak` plays it only to the called party;
`both` plays it to both. `loop` repeats the whole list, and `0` repeats it until you stop it.

### Stop, pause, or resume speech via REST

Address the playback by its `control_id`. `calling.play.stop` ends it and sends `finished` to its
`status_url`. `calling.play.pause` and `calling.play.resume` hold and continue it, and
`calling.play.volume` changes its level in decibels, from -40 to 40.
