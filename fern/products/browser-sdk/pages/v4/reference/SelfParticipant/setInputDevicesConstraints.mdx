```ts
setInputDevicesConstraints(constraints): Promise<boolean>
```
Updates both audio and video input track constraints for the active call.

## **Parameters**

<ParamField path="constraints" type="{ audio: MediaTrackConstraints; video: MediaTrackConstraints; }" required toc={true}>
  Constraints for both audio and video input devices. See [`MediaTrackConstraints`](https://developer.mozilla.org/en-US/docs/Web/API/MediaTrackConstraints).
</ParamField>

## **Returns**

`Promise<boolean>` — whether **both** kinds took the constraints.

`false` is an outcome, not an error: the leg may have no live sender of that kind, or may carry media the SDK did not capture and may not replace (an `inputAudioStream`/`inputVideoStream` you supplied, a display capture, or pipeline output). Any failure behind a `false` is also reported on [`call.errors$`](/docs/browser-sdk/v4/reference/webrtc-call/errors$), so a caller that ignores the return value still learns of it there. A UI that reflects the change must read it.

## **Examples**

```ts
await selfParticipant.setInputDevicesConstraints(constraints);
```
