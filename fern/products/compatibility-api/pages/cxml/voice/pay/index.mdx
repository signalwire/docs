## Overview

The `<Pay>` verb enables secure payment processing during voice calls. When implemented in your voice application,
it handles the complete payment flow including data collection, validation, and processing through your configured payment gateway.

The `<Pay>` verb also has two nouns that are embedded within it:
- [`<Parameter>`](/docs/compatibility-api/cxml/reference/voice/pay/parameter): Pass custom parameters to your payment processor.
- [`<Prompt>`](/docs/compatibility-api/cxml/reference/voice/pay/prompt): Customize the prompts used during payment collection.

## Core functionality

- Secure payment information collection
- Real-time payment processing
- Payment method tokenization
- Multi-currency support
- Automated retry handling
- Status tracking via webhooks

---

## Transaction types

The `<Pay>` verb supports two primary transaction types: immediate charges and tokenization.

### Immediate charges
When you need to process a payment right away, use an immediate charge transaction. This collects the payment details and processes the transaction in one step.

To execute an immediate charge:
```xml
<Pay chargeAmount="25.00"/>
```
Setting any positive value for `chargeAmount` initiates an immediate charge transaction.

### Tokenization
Tokenization allows you to securely store payment information for future use. Instead of processing a payment, it generates a secure token that represents the payment method. This is particularly useful for:
- Subscription services
- Recurring billing

To tokenize payment information:
```xml
<Pay chargeAmount="0"/>
```

You can also omit the `chargeAmount` attribute entirely.

Your payment connector creates the token with your payment processor and returns it as `token_id`. SignalWire passes it to your `action` URL as `PaymentToken`, and you can use it for future transactions without asking the customer to re-enter their payment details. See the [tokenization example](#tokenize-a-card-end-to-end) for the full flow.

## Attributes

<ParamField path="paymentConnectorUrl" type="string" required={true} toc={true}>
  The HTTPS URL of your payment connector. SignalWire sends it a `POST` request with the collected payment details. See [`paymentConnectorUrl` request parameters](#paymentconnectorurl-request-parameters) and [securing your payment connector](#securing-your-payment-connector).
</ParamField>

<ParamField path="action" type="string" toc={true}>
  HTTPS endpoint that receives POST requests after payment completion. Must be HTTPS. Response determines next cXML instructions. For tokenization, receives the token as `PaymentToken`. For charges, receives `PaymentConfirmationCode`. Defaults to the current cXML document URL.
</ParamField>

<ParamField path="chargeAmount" type="decimal" toc={true}>
  Amount to charge. Set to 0 or omit for tokenization only. Must be between 0 and 1,000,000.
</ParamField>

<ParamField path="currency" type="string" default="usd" toc={true}>
  Three-letter currency code (e.g., `usd`, `eur`, `gbp`). Must be supported by selected payment connector. Currently only `usd` is accepted.
</ParamField>

<ParamField path="description" type="string" toc={true}>
  Transaction description passed to payment processor. Appears in transaction records.
</ParamField>

<ParamField path="input" type="string" default="dtmf" toc={true}>
  The only supported input method for payment data collection. All captured digits are automatically redacted in logs.
</ParamField>

<ParamField path="language" type="string" default="en-us" toc={true}>
  Controls prompt language. Supports `en-AU`, `en-CA`, `en-GB`, `en-IN`, `en-US` for all payments. Additional `es-ES`, `es-MX`, `fr-CA`, `fr-FR`, `de-DE`, `it-IT` for credit card only. See [language list](#language-support).
</ParamField>

<ParamField path="maxAttempts" type="integer" default="1" toc={true}>
  Maximum number of retry attempts when timeout occurs or invalid data is received. Allowed values are `1`, `2`, or `3`. Payment flow terminates after `maxAttempts` is reached.
</ParamField>

<ParamField path="minPostalCodeLength" type="integer" default="0" toc={true}>
  Minimum required length for postal code input. Used for input validation.
</ParamField>

<ParamField path="paymentMethod" type="string" default="credit-card" toc={true}>
  Determines payment collection flow. Credit card flow captures card number, expiration, security code, and postal code. ACH flow captures routing and account numbers.
</ParamField>

<ParamField path="postalCode" type="string | boolean" default="true" toc={true}>
  Controls postal code collection. When `false`, skips collection for postal code. When `true`, prompts the user for collection. When a String value, uses provided value without needing to collect the postal code from the user.
</ParamField>

<ParamField path="securityCode" type="boolean" default="true" toc={true}>
  Controls whether CVV/security code collection is required. When `false`, skips security code collection.
</ParamField>

<ParamField path="statusCallback" type="string" toc={true}>
  HTTPS endpoint that receives real-time payment status updates via POST requests. Includes details about current payment stage, errors, and attempt counts. See [Status Callback Parameters](#statuscallback-request-parameters) for more details.
</ParamField>

<ParamField path="timeout" type="integer" default="5" toc={true}>
  Number of seconds to wait for the next digit input before timing out. Must be a positive integer greater than 3 seconds. Applies to all input collection stages.
</ParamField>

<ParamField path="tokenType" type="string" default="reusable" toc={true}>
  Determines token persistence. Allowed values are `one-time` or `reusable`. One-time for single use, reusable for recurring use. Payment-method specific to certain processors.
</ParamField>

<ParamField path="validCardTypes" type="string" default="visa mastercard amex" toc={true}>
  Space-separated list of accepted card types. Validates card number against specified types. Allowed values: `visa`, `mastercard`, `amex`, `maestro`, `discover`, `optima`, `jcb`, `diners-club`, `enroute`.
</ParamField>


## Webhook request parameters

### `paymentConnectorUrl` request parameters

When all payment details have been collected from the caller, SignalWire sends a `POST` request with a JSON body to your `paymentConnectorUrl`.
Charges and [tokenization](#tokenization) send the same fields. SignalWire signs the request, so see [securing your payment connector](#securing-your-payment-connector) to verify it.

<Warning title="Response from paymentConnectorUrl">
A valid response from your `paymentConnectorUrl` must be provided to indicate the success or failure of the transaction.
More information can be found in the [Webhook Response](#paymentconnectorurl-response) section.
</Warning>

<ParamField path="transaction_id" type="string" toc={true}>
  Unique identifier for the transaction.
</ParamField>

<ParamField path="method" type="string" toc={true}>
  Payment method (`credit-card`).
</ParamField>

<ParamField path="cardnumber" type="string" toc={true}>
  Customer's full credit card number.
</ParamField>

<ParamField path="cvv" type="string" toc={true}>
  Card security code.
</ParamField>

<ParamField path="postal_code" type="string" toc={true}>
  Billing postal code.
</ParamField>

<ParamField path="description" type="string" toc={true}>
  Transaction description.
</ParamField>

<ParamField path="chargeAmount" type="string" toc={true}>
  Amount to charge, from the `chargeAmount` attribute. `0` for tokenization, or `0.00` when the attribute is omitted.
</ParamField>

<ParamField path="token_type" type="string" toc={true}>
  Token persistence (`reusable` or `one-time`), from the `tokenType` attribute.
</ParamField>

<ParamField path="expiry_month" type="string" toc={true}>
  Card expiration month (2 digits).
</ParamField>

<ParamField path="expiry_year" type="string" toc={true}>
  Card expiration year (2 digits).
</ParamField>

<ParamField path="currency_code" type="string" toc={true}>
  Three-letter currency code, from the `currency` attribute.
</ParamField>

<ParamField path="parameters" type="object[]" toc={true}>
  Custom parameters from the [`<Parameter>`](/docs/compatibility-api/cxml/reference/voice/pay/parameter) nouns, as an array with one single-key object per parameter. Omitted when `<Pay>` has no `<Parameter>`.
</ParamField>

#### Example

```json
{
  "transaction_id": "8c9d14d5-52ae-4e2e-b880-a14e6e1cda7d",
  "method": "credit-card",
  "cardnumber": "4242424242424242",
  "cvv": "123",
  "postal_code": "12345",
  "description": "renew plan",
  "chargeAmount": "123.45",
  "token_type": "reusable",
  "expiry_month": "01",
  "expiry_year": "38",
  "currency_code": "usd",
  "parameters": [
    { "custom1": "value1" }
  ]
}
```

A valid cXML response must be provided if the `action` URL is provided. More information can be found in the [Webhook Response](#action-response) section.
</Warning>


<ParamField path="BankAccountNumber" type="string" toc={true}>
  Masked bank account number. ACH payments only.
</ParamField>

<ParamField path="BankAccountType" type="string" toc={true}>
  Bank account type. ACH payments only.
</ParamField>

<ParamField path="BankRoutingNumber" type="string" toc={true}>
  Bank routing number. ACH payments only.

<ParamField path="PaymentCardExpirationDate" type="string" toc={true}>

<ParamField path="PaymentCardType" type="string" toc={true}>
  Card brand (visa, mastercard, etc.).
</ParamField>

<ParamField path="PaymentConfirmationCode" type="string" toc={true}>
  The `charge_id` your payment connector returned for a successful charge.
</ParamField>

<ParamField path="PaymentConnectorError" type="string" toc={true}>
  The `error_message` your payment connector returned.
</ParamField>

<ParamField path="PaymentConnectorErrorCode" type="string" toc={true}>
  The `error_code` your payment connector returned.
</ParamField>

<ParamField path="PaymentError" type="string" toc={true}>
  Detailed error information.
</ParamField>

<ParamField path="PaymentErrorCode" type="string" toc={true}>
  Numeric error reference.
</ParamField>

<ParamField path="PaymentMethod" type="string" toc={true}>
  Type of payment method used.
</ParamField>

<ParamField path="PaymentToken" type="string" toc={true}>
  The `token_id` your payment connector returned for a successful tokenization. Otherwise, the token type (`reusable` or `one-time`) from the `tokenType` attribute.
</ParamField>

<ParamField path="PayResult" type="string" toc={true}>
  Final outcome of the payment attempt. The possible values can be seen in the [Result Values](#result-values) table.
</ParamField>

#### Result values

| Value | Description |
|-------|-------------|
| `success` | Payment processed successfully |
| `too-many-failed-attempts` | Maximum retry attempts reached |
| `payment-connector-error` | Gateway communication failure |
| `caller-interrupted-with-star` | User canceled with * key |
| `caller-hung-up` | Call terminated by user |
| `validation-error` | Invalid parameter provided |
| `internal-error` | System processing error |

  Card expiration date.

  Indicates the present phase of the `<Pay>` request. The table below outlines the potential values. Possible values can be seen in the [For Values](#for-values) table.
</ParamField>

<ParamField path="PaymentCardNumber" type="string" toc={true}>
  Masked card number.
</ParamField>

<ParamField path="PaymentCardPostalCode" type="string" toc={true}>
  Postal code provided.
</ParamField>

<ParamField path="PaymentCardType" type="string" toc={true}>
  Type of card provided.
</ParamField>

<ParamField path="PaymentMethod" type="string" toc={true}>
  Type of payment being processed.
</ParamField>

<ParamField path="SecurityCode" type="string" toc={true}>
  Masked security code.
</ParamField>

#### For values

| Value | Description |
|-------|-------------|
| `payment-card-number` | Requesting the customer's credit or debit card details |
| `expiration-date` | Requesting the expiration date of the customer's payment card |
| `security-code` | Requesting the security code (CVV) of the customer's payment card |
| `postal-code` | Requesting the postal code linked to the customer's payment card |
| `bank-routing-number` | Requesting the customer's bank routing number |
| `bank-account-number` | Requesting the customer's bank account number |
| `payment-processing` | Sending the payment details to your payment connector |
| `payment-completed` | Your payment connector returned HTTP `200`. This doesn't mean the payment succeeded: a decline returned with HTTP `200` also sends `payment-completed` |
| `payment-failed` | Payment details couldn't be collected, or your payment connector didn't return HTTP `200` |
| `payment-canceled` | The caller pressed `*` to cancel |

To find out whether the payment succeeded, check `PayResult` on the [`action` request](#action-request-parameters).


#### Error types

| Error | Description |
|-------|-------------|
| `input-timeout` | User input timeout |
| `invalid-card-number` | Failed card validation |
| `invalid-card-type` | Unsupported card type |
| `invalid-date` | Invalid expiration date |
| `invalid-security-code` | Invalid CVV format |
| `invalid-postal-code` | Invalid postal code format |
| `invalid-bank-routing-number` | Invalid routing number |
| `invalid-bank-account-number` | Invalid account number |
| `session-in-progress` | Concurrent session attempt |

## Webhook response

### `paymentConnectorUrl` response

The response from your `paymentConnectorUrl` is used to inform if the transaction was successful or not.


#### Successful transaction

When a transaction is successful, the webhook should respond with one of the following formats (depending on the transaction type):

<CodeBlocks>
```json title="Successful Standard Credit Card Payment"
{
  "charge_id":"charge_id",
  "error_code":null,
  "error_message":null
}
```
```json title="Successful Tokenized Credit Card Payment"
{
  "token_id":"token_id",
  "error_code":null,
  "error_message":null
}
```
</CodeBlocks>

SignalWire passes `charge_id` to your `action` URL as `PaymentConfirmationCode`. When `chargeAmount` is zero or omitted, it passes `token_id` as `PaymentToken`.

#### Unsuccessful transaction

When a transaction is unsuccessful (declined by the payment processor), the webhook should respond with the following format:

<CodeBlocks>
```json title="Declined Standard Credit Card Payment"
{
  "charge_id": null,
  "error_code": "some error code",
  "error_message": "some error message"
}
```
```json title="Declined Tokenized Credit Card Payment"
{
  "token_id": null,
  "error_code": "some error code",
  "error_message": "some error message"
}
```
</CodeBlocks>

---

### `action` response

When a transaction is completed, SignalWire will `POST` to your `action` URL. The response should return valid cXML for the
next step in your application.


#### Example

```xml
<Response>
  <Say>Thank you for your payment. Your transaction has been completed.</Say>
  <Hangup/>
</Response>
```

## Language support

The `language` attribute controls the language of automated prompts during payment collection.

<Note title="You can customize prompt messages in any language using the [`<Prompt>`](/docs/compatibility-api/cxml/reference/voice/pay/prompt) noun, regardless of the selected `language` attribute."/>


### Credit card payments

All credit card payments support the following languages:

#### English variants
- en-AU (Australian English)
- en-CA (Canadian English) 
- en-GB (British English)
- en-IN (Indian English)
- en-US (American English)

#### Additional languages
- es-ES (European Spanish)
- es-MX (Mexican Spanish)
- fr-CA (Canadian French)
- fr-FR (European French)
- de-DE (German)
- it-IT (Italian)

## Examples


### Simple payment collection:
```xml
<?xml version="1.0" encoding="UTF-8"?>
<Response>
    <Say>Please enter your payment information</Say>
    <Pay chargeAmount="20.45"/>
</Response>
```

### Payment with status tracking:
```xml
<?xml version="1.0" encoding="UTF-8"?>
<Response>
    <Say>Please enter your payment information</Say>
    <Pay 
        chargeAmount="20.45"
        action="https://your-callback-url.example.com/pay"
        statusCallback="https://your-callback-url.example.com/status"
    />
</Response>
```

### Basic tokenization:
```xml
<?xml version="1.0" encoding="UTF-8"?>
<Response>
    <Say>Please enter your card information to save for future use</Say>
    <Pay 
        tokenType="reusable"
        chargeAmount="0"
    />
</Response>
```

### Tokenization with validation:
```xml
<?xml version="1.0" encoding="UTF-8"?>
<Response>
    <Say>Please enter your card information</Say>
    <Pay 
        tokenType="reusable"
        chargeAmount="0"
        validCardTypes="visa mastercard"
        securityCode="true"
        postalCode="true"
    />
</Response>
```

### Tokenize a card end to end

This `<Pay>` saves a card without charging it:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<Response>
    <Say>Please enter your card information to save for future use</Say>
    <Pay
        chargeAmount="0"
        tokenType="reusable"
        paymentConnectorUrl="https://pay.example.com/connector"
        action="https://example.com/pay-result"
    />
</Response>
```

SignalWire collects the card details and sends them to your payment connector with `"chargeAmount": "0"` and `"token_type": "reusable"`.
Your connector saves the card with your payment processor and replies with the processor's token:

```json
{
  "token_id": "pm_1234567890",
  "error_code": null,
  "error_message": null
}
```

SignalWire then sends your `action` URL `PayResult=success` and `PaymentToken=pm_1234567890`.
Store the token to charge the card later through your payment processor.

### Custom retry logic:
```xml
<?xml version="1.0" encoding="UTF-8"?>
<Response>
    <Say>Please enter your payment information</Say>
    <Pay 
        chargeAmount="75.00"
        maxAttempts="3"
        timeout="10"
    />
</Response>
```

### International payment:
```xml
<?xml version="1.0" encoding="UTF-8"?>
<Response>
    <Say>Por favor, ingrese su información de pago</Say>
    <Pay 
        chargeAmount="100.00"
        currency="mxn"
        language="es-MX"
        description="Mexican peso transaction"
    />
</Response>
```

### Example with custom parameters and prompts

```xml
<Response>
<Pay chargeAmount="123.45" paymentConnectorUrl="https://example.com/accept-payment" description="renew plan">
  <Parameter name="custom1" value="value1"/>
  <Prompt for="payment-card-number" attempt="1"><Say>Let's collect your payment information. Please enter your credit card number</Say></Prompt>
  <Prompt for="payment-card-number" attempt="2 3"><Say>Please enter your credit card number</Say></Prompt>
  <Prompt for="security-code" cardType="amex"><Say>Please enter your credit card's security code. It's the 4 digits located on the front of your card. </Say></Prompt>
</Pay>
</Response>
```

## Securing your payment connector

Requests to your `paymentConnectorUrl` carry the `X-SignalWire-Signature` and `X-SignalWire-SHA256-Signature` headers, keyed with your project's [Signing Key](/docs/platform/webhooks#verify-webhook-signature). They don't come from a published IP range, so verify the signature and reject any request that doesn't match.
The connector request is signed like a JSON webhook, not like your `action` and `statusCallback` requests: `X-SignalWire-Signature` is the lowercase hex HMAC-SHA1 of the connector URL, with any credentials removed, followed by the raw JSON body. The form-parameter validation you use for other cXML webhooks won't match it.

For a second layer, put credentials in the connector URL.
Credentials such as `https://payuser:<LONG_RANDOM_SECRET>@pay.example.com/connector` are sent as a standard Basic `Authorization` header and aren't part of the signed URL, so your connector can check both.
A long random token in the URL path works the same way.

<Warning title="The connector URL appears in your call logs">
The full `paymentConnectorUrl`, including any credentials or token in it, is visible in your call logs in the Dashboard.
Use a secret that protects only this endpoint, and rotate it periodically.
</Warning>
